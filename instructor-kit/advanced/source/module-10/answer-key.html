11.2 · Recommendation Systems: self-check

Q1
A new recommender scores HR@10 = 0.004 on the leave-last-out test, where a random list scores 0.047. What is the most likely explanation?
A) A strong model on a hard dataset
B) A bug, such as sorting the scores ascending or forgetting to mask owned products
C) Too few factors in the SVD
D) The test item should have been chosen at random
Why: A model that loses to random is almost always a bug, not a bad model. The lesson's ascending argsort scored 0.001: it picked the ten LEAST recommended products. Always compare with the random baseline.
A is wrong: Even a weak model should beat random; far below it means something is inverted.
C is wrong: Two factors still scored 0.220.
D is wrong: The latest purchase is the right test item; it is not the cause.
Q2
What does this print?
import numpy as np
from scipy.sparse import csr_matrix
from sklearn.metrics.pairwise import cosine_similarity
R = csr_matrix(np.array([[1, 0, 1], [1, 1, 0], [0, 1, 1], [1, 0, 0]]))
print(cosine_similarity(R.T)[0].round(2))
[1. 0.41 0.41]
Why: Columns are products. Product 0 was bought by customers 0, 1 and 3; product 1 by 1 and 2; product 2 by 0 and 2. Each pair shares one buyer: 1 / √(3 × 2) = 0.41. A product is identical to itself: 1.
Q3
Why does top_k set the scores of owned products to minus infinity before sorting?
A) Because cosine similarity is undefined for owned products
B) To make the hit rate look better than it is
C) Because SciPy cannot sort sparse matrices
D) Owned products are similar to what the customer bought, so they score high and crowd the list; customers would see items they already have
Why: Without the mask 14% of list slots went to owned products and HR@10 fell from 0.308 to 0.270. Repeat-purchase items (socks, fuel) deserve a separate "buy it again" list.
A is wrong: Cosine similarity is defined for every pair.
B is wrong: The mask is honest: the test item is never owned in training. It raises the hit rate because the list is no longer wasted.
C is wrong: The scores are a dense NumPy array by then.
Q4
The best-seller list shows 31 different products; item-kNN shows 161 and hits more often. What does that number measure?
A) Catalog coverage: how many different products appear on anyone's list
B) How many customers got a hit
C) How many products have at least one buyer
D) How many factors the model learned
Why: Coverage is a second view next to hit rate: a list that only ever shows the head of the long tail serves the shop and its customers less well. Item-kNN reaches about 80% of the catalog.
B is wrong: That is the hit rate (times 3,000).
C is wrong: All 200 products have buyers.
D is wrong: Item-kNN has no factors.
Q5
What does this print?
import numpy as np
from scipy.sparse import csr_matrix
from sklearn.decomposition import TruncatedSVD
svd = TruncatedSVD(n_components=3, random_state=42)
factors = svd.fit_transform(csr_matrix(np.eye(6, 8)))
print(factors.shape, svd.components_.shape)
(6, 3) (3, 8)
Why: fit_transform returns the row factors (one row per customer, k columns); components_ holds the column factors (k rows, one column per product). Their product rebuilds a 6 × 8 score matrix.
Q6
You plot HR@10 against the number of SVD factors on the test item and pick the peak, k = 5. What is wrong with reporting 0.311?
A) Nothing: the test item was never used for training
B) SVD needs more than 5 factors to be valid
C) k was tuned on the test item, so 0.311 is optimistic; choose k on a validation item and score the test item once
D) Hit rate cannot be used to compare SVD models
Why: Choosing a setting by its test score is tuning on the test set. The project holds out each customer's second-to-last purchase for validation (k = 5 scored 0.285 there, item-kNN 0.286), then measures the chosen model once.
A is wrong: Using the test item to choose k is using it, even without training on it.
B is wrong: k = 5 matches the five tastes in this data.
D is wrong: Hit rate is exactly how they are compared.

12.1 · Reproducibility and Experiment Tracking: self-check

Q7
A colleague reruns your churn notebook and gets test AUC 0.8560 instead of 0.8612. The data fingerprint and every library version match. Which ingredient most likely differs?
A) The data file
B) The scikit-learn version
C) The random seed of the forest
D) AUC is computed differently on each run
Why: With the same data, code and environment, the remaining ingredients are randomness and settings. The lesson printed exactly these two numbers for seed 42 and seed 7. A third-decimal difference between seeds is noise.
A is wrong: The fingerprint matches.
B is wrong: The versions match.
D is wrong: roc_auc_score is deterministic.
Q8
What does this print?
import hashlib
h = hashlib.sha256(b"customers_churn.csv contents").hexdigest()
print(len(h), h == hashlib.sha256(b"customers_churn.csv contents").hexdigest())
64 True
Why: SHA-256 always gives 64 hexadecimal characters, and the same bytes always give the same fingerprint. One changed byte gives a completely different one.
Q9
What happens on the last line?
import skops.io as sio
from sklearn.ensemble import HistGradientBoostingClassifier
sio.dump(HistGradientBoostingClassifier().fit([[0], [1], [2], [3]], [0, 1, 0, 1]), "q9.skops")
model = sio.load("q9.skops")
A) UntrustedTypesFoundException: it names the HistGradientBoosting tree type, which you must review and pass in trusted=
B) The model loads, because skops files are always safe
C) pickle.UnpicklingError: skops cannot read its own files
D) The model loads, but prints a warning about the scikit-learn version
Why: skops only rebuilds types on its safe list. Here the file needs TreePredictor; the message even explains its risk. Review it, then load with a trusted= list that names exactly that type.
B is wrong: Safer is not unconditional: unknown types need your decision.
C is wrong: skops does not use pickle.
D is wrong: Same environment; the refusal is about types, not versions.
Q10
Why should a model you share with another team be saved with skops rather than joblib?
A) skops files are smaller
B) joblib cannot save pipelines
C) skops makes the model more accurate
D) Loading a joblib file (a pickle) can run arbitrary code; skops only rebuilds known types or types you trust explicitly
Why: The lesson's harmless pickle called print while LOADING. A malicious one could call anything with your permissions. Treat a model file like a program; skops removes the run-any-function attack.
A is wrong: Often larger: in Lab 12.1 B the skops file was 462 kB and the joblib file 142 kB.
B is wrong: joblib saved the whole pipeline in the lesson.
C is wrong: Same model, same predictions.
Q11
What does this print?
from sklearn.ensemble import RandomForestClassifier
X, y = [[0], [1], [2], [3], [4], [5]], [0, 0, 1, 1, 0, 1]
a = RandomForestClassifier(n_estimators=5, random_state=3).fit(X, y).predict_proba(X)[:, 1]
b = RandomForestClassifier(n_estimators=5, random_state=3).fit(X, y).predict_proba(X)[:, 1]
print((a == b).all(), RandomForestClassifier().get_params()["random_state"])
True None
Why: The same random_state gives the same forest, bit for bit. The default random_state is None: every fit draws new random numbers, so an unseeded forest changes run to run.
Q12
Which call lists the runs of an experiment with the best cross-validated AUC first?
A) mlflow.search_runs(experiment_names=["churn"], order_by=["params.cv_auc DESC"])
B) mlflow.search_runs(experiment_names=["churn"], order_by=["metrics.cv_auc DESC"])
C) mlflow.search_runs(experiment_names=["churn"], order_by=["metrics.cv_auc ASC"])
D) mlflow.search_runs(experiment_names=["churn"], filter_string="max(cv_auc)")
Why: cv_auc was logged as a METRIC (a number), and higher is better, so DESC. Parameters are stored as text; for an error such as MAE you would sort ASC (Lab 12.1 A).
A is wrong: cv_auc is a metric, not a parameter.
C is wrong: ASC puts the worst first.
D is wrong: Not valid filter syntax; filters look like metrics.cv_auc > 0.85.

Why: The bytes 6 and 6.0 differ, so the fingerprints differ, although the numbers are equal. That is the lesson's Exercise 1: a re-saved CSV with the same data can have a new fingerprint.

import numpy as np

Why: The same seed gives the same permutation; another seed almost surely a different one. Seeds make randomness repeatable, not absent.

Exit Ticket

  1. 0.308 vs 0.209: the personal row contains the product a customer really bought next for about 31% of customers against 21% for the best-seller row: about 50% more hits, measured honestly on a held-out purchase.
  2. Five ingredients: code (Git, a script like train_churn.py), data (SHA-256 fingerprint), environment (versions, pip freeze lock file), randomness (random_state, default_rng(42)), settings (one CONFIG, logged with log_params / log_dict).
  3. model.joblib: loading it runs whatever the file says. Load only if you fully trust the sender; better, ask for skops, review get_untrusted_types, load with a hand-written trusted= list.

Common Wrong Answers and What They Reveal

  • Q1 A ("a strong model on a hard dataset"). Has not internalized the random baseline. Ask: "What would ten random picks score?"
  • Q2 written as [1. 0.33 0.33]. Divided shared buyers by the total buyers instead of the geometric mean of the two counts.
  • Q6 A ("nothing wrong"). Thinks only training on the test set is a leak; choosing on it is too.
  • Q7 B ("the version"). Missed that the question says the versions match; seeds are the remaining ingredient.
  • Q10 A ("smaller files"). The opposite in Lab 12.1 B. Safety is the reason.
  • Q12 C ("ASC"). Correct instinct for an error metric (Lab 12.1 A), wrong for AUC.
