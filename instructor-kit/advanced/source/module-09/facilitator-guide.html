Session 9: Transfer Learning and Text Classification

How to teach Session 9 of Advanced Machine Learning: borrow a network trained on a million photos and turn it into a satellite land-cover classifier with 2,000 labels on a CPU, then teach a model to read Pinecrest's product reviews. Learners leave knowing that good features come first: pretrained features beat a from-scratch CNN with a twentieth of the labels (0.913 vs 0.719), and a TF-IDF pipeline beats the baseline by 13 points, as long as nobody throws away the word not.

Questions and answers
W1
What shape does this print?
import torch
from torch import nn
print(nn.Conv2d(1, 8, kernel_size=3)(torch.zeros(4, 1, 28, 28)).shape)
torch.Size([4, 8, 26, 26])
Why: A 3 × 3 kernel with no padding loses one pixel on each side: (28 + 0 - 3) / 1 + 1 = 26. Batch 4, 8 output channels.
W2
How many parameters? (This is ResNet-18's first layer; Lesson 10.3's Before the Next Lesson asked the same.)
from torch import nn
print(sum(p.numel() for p in nn.Conv2d(3, 64, kernel_size=7, bias=False).parameters()))
9408
Why: 64 filters × 3 channels × 7 × 7 = 9,408, and no bias. Today we borrow those 9,408 numbers, and 11 million more, ready-trained.
W3
What does this print?
import torch
from torch import nn
lstm = nn.LSTM(input_size=2, hidden_size=8, batch_first=True)
out, (h, c) = lstm(torch.zeros(5, 14, 2))
print(tuple(out.shape), tuple(h.shape))
(5, 14, 8) (1, 5, 8)
Why: batch_first=True: out is (batch, time steps, hidden) = (5, 14, 8); h is (layers, batch, hidden) = (1, 5, 8), the last step only.
W4
Why must model.eval() come before measuring test accuracy of a model with dropout and batch norm?
So dropout stops zeroing activations and batch norm uses its stored training statistics (not the test batch's).
Why: This comes straight back in 10.5: features extracted in training mode are silently wrong.
W5
A colleague splits overlapping sales windows with train_test_split(..., random_state=42) and beats the seasonal naive forecast by a mile. Your first suspicion?
Leakage: neighboring windows share days, so test days were in training. Split by time.
Why: Same habit as today's text pipeline: anything learned from data (windows, vocabulary, IDF) must come from the training part only.

Transfer Learning

Objectives (from the lesson page)
  • Explain why features learned on ImageNet transfer to a new image task, and when they will not

Mental model to say

"Imagine hiring someone to sort aerial photos into ten land types. A newcomer needs thousands of examples just to learn what a texture or a straight edge is. An experienced photo editor already sees textures, edges and color gradients without thinking; shown a few dozen examples per land type, they learn which combinations mean forest. The pretrained network is that editor. You only teach it the last step."

Draw it: tile → backbone (all the convolutions, ImageNet-trained) → 512 features → head (new, your 10 classes). Then the four strategies from the lesson's table: feature extraction (frozen backbone, train only the head), fine-tuning (head plus the top block, small learning rate), full fine-tuning (everything, needs data and a GPU), from scratch (huge data, or inputs nothing like photos). "Today: the first two, on a CPU, honestly compared with the fourth."

Three mistakes to expect, and how to coach each
  • Normalizing with the wrong statistics, or not at all. No error: the lesson measured 0.840 instead of 0.894 for unnormalized features (Mistake 4). Coach: "Where did your mean and std come from? Print one batch's channel means." The debug_transfer.py handout makes them find it.
  • Freezing in the wrong order, or an optimizer that never got the head. Loud (element 0 of tensors does not require grad) or silent (a loss that never moves). Coach: "Print count_trainable(model) before you train. Is the head in the optimizer?" Lab B builds exactly this audit.
  • Forgetting eval() for features or prediction. Silent: features depend on the batch, stored statistics drift. Coach: "Which mode is your model in right now?" (model.training).

Checks for understanding
  • Why can we compute the features once? Answer: the backbone is frozen and in eval() mode, so each tile's features never change.
  • What does backbone.fc = nn.Identity() do? Answer: removes the ImageNet head, so the network outputs its 512 features.
  • From the label curve, at about how many labels did frozen features pass the from-scratch CNN? Answer: by 100 tiles (0.755 vs 0.719 with 2,000).
  • Why a smaller learning rate for layer4? Answer: its weights are already good; big steps could destroy what we borrowed.

Three mistakes to expect, and how to coach each
  • A DataFrame where a column of text belongs. ValueError: Found input variables with inconsistent numbers of samples: [1, 3095]. Coach: "How many documents does the vectorizer think it got?" (one: the column name). Single brackets.
  • A second vectorizer for the test text, or one fitted before the split. Loud only by luck: ValueError: X has 331 features, but LogisticRegression is expecting 333 features as input.. Coach: "Which vocabulary does column 57 belong to?" Use the pipeline.
  • Trusting accuracy and a default stop-word list. Silent: 0.864 instead of 0.877, and Would not buy again. becomes a coin flip. Coach: "Read the list. Probe with three sentences you understand." Missing text is the fourth one (np.nan is an invalid document): fill or drop.
