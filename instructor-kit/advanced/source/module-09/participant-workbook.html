10.5

Transfer Learning

By the end you can
  • Explain why features learned on ImageNet transfer to a new image task, and when they will not
  • Load a pretrained torchvision model with the weights= API and prepare images the way it expects
  • Use a frozen backbone as a feature extractor and train a small head on its features
  • Fine-tune the last block with a lower learning rate, and compare the result with a CNN trained from scratch
  • Measure how many labeled images a model needs before you pay for labeling more
Key ideas
  • The experienced photo editor. A pretrained backbone already sees edges, textures and colors; you teach only the last step, the head.
  • Backbone and head. ResNet-18's head is fc (512 → 1,000 ImageNet classes). nn.Identity() in its place gives features; nn.Linear(512, 10) gives your classes.
  • Prepare images the model's way. weights.transforms() holds the recipe; normalize with ImageNet's mean and std (not your data's), 3 channels, a sensible size (128 px on a CPU).
  • Frozen features are a table. In eval() mode under torch.inference_mode(), compute them once; then any classifier (a linear head, logistic regression, kNN) learns from them in seconds.
  • The numbers: from scratch 0.719 with 2,000 tiles; frozen + linear head 0.913; 100 labels already beat the from-scratch CNN; fine-tuned layer4 0.928 on test.
  • Freeze first, then attach the head. New layers are trainable by default. Check count_trainable(model) before training.
  • Fine-tune in stages. Head first, then unfreeze the last block with a ten times smaller learning rate (parameter groups); keep it only if validation improves.
  • Silent mistakes: no normalization (0.840 instead of 0.894), features in training mode (batch-dependent features, drifting statistics).
Worked example: find the head, match the channels

Where is the head of a network you have never used? Ask it. MobileNetV3-small, built for phones, keeps its head in classifier, not fc. Building the architecture with weights=None needs no download.

import torch
from torch import nn
from torchvision import models

mobile = models.mobilenet_v3_small(weights=None)      # architecture only: no download needed
print(mobile.classifier)
print(f"parameters: {sum(p.numel() for p in mobile.parameters()):,}")
Sequential(
  (0): Linear(in_features=576, out_features=1024, bias=True)
  (1): Hardswish()
  (2): Dropout(p=0.2, inplace=True)
  (3): Linear(in_features=1024, out_features=1000, bias=True)
)
parameters: 2,542,856

Its head is four layers ending in 1,000 ImageNet classes. Replace the whole classifier and the network outputs its features:

mobile.classifier = nn.Identity()
mobile.eval()
with torch.no_grad():
    print(tuple(mobile(torch.zeros(2, 3, 128, 128)).shape))
(2, 576)

576 features per image (ResNet-18 gives 512). And a grayscale image? Repeat its one channel three times so it fits the RGB stem:

gray = torch.rand(4, 1, 128, 128)                     # four grayscale images
rgb_like = gray.repeat(1, 3, 1, 1)                     # copy the one channel three times
with torch.no_grad():
    print(tuple(rgb_like.shape), "->", tuple(mobile(rgb_like).shape))
(4, 3, 128, 128) -> (4, 576)

Three habits in one example: find the head by printing the model, replace it with nn.Identity() for features, and match the channels the backbone expects. Setting mobile.fc = nn.Identity() instead would raise no error and change nothing: always check the output shape.

11.1

Text Classification

By the end you can
  • Clean and tokenize text with Python's re module, and explain what scikit-learn's vectorizers do to a sentence
  • Build bag-of-words and TF-IDF feature matrices, and read the sparse matrix and vocabulary they produce
  • Train a leak-free sentiment classifier with a Pipeline of TfidfVectorizer and LogisticRegression, and compare it with a baseline
  • Explain the stop-word trap, and use bigrams so that "not waterproof" and "not bad" become features of their own
  • Describe what word embeddings add over TF-IDF, and when the simpler model is the right choice
Key ideas
  • The tally sheet. A bag of words counts which words appear, ignoring order. Text becomes a fixed-length row of numbers; the rest is ordinary scikit-learn.
  • Vectorizers tokenize for you. Lowercase, runs of 2+ word characters: one-letter words disappear. build_analyzer() shows exactly what happens to a sentence.
  • Sparse matrices. Mostly zeros, so only non-zero values are stored (5.3% here). Never .toarray() a real one.
  • TF-IDF weighs a count by rarity: idf = ln((1 + n) / (1 + df)) + 1, then each row is scaled to length 1. A word in every document gets exactly 1.
  • Pipeline = no leak. Vocabulary and IDF are learned in fit, from training text only, also inside every CV fold.
  • The numbers: baseline 0.745; TF-IDF + logistic regression 0.877; stop words removed 0.864.
  • Read the words, probe with sentences. "bad" pulls positive (Not bad at all). The English stop-word list removes not, no, never: never use it unread for sentiment.
  • Bigrams give "not waterproof" and "not bad" their own columns. Choose a threshold from cross-validated probabilities, then grade once on test.
Worked example: bigrams and IDF by hand

Four short notes about a sleeping bag. With ngram_range=(1, 2) and min_df=2, which terms survive?

from sklearn.feature_extraction.text import TfidfVectorizer
notes = ["warm bag", "not warm", "not warm at all", "light and warm"]
vec = TfidfVectorizer(ngram_range=(1, 2), min_df=2).fit(notes)
print(vec.get_feature_names_out())
['not' 'not warm' 'warm']

Only terms in at least two notes are kept: not, not warm and warm. Now the weights:

import pandas as pd
print(pd.Series(vec.idf_, index=vec.get_feature_names_out()).round(3).to_dict())
print(pd.DataFrame(vec.transform(["not warm", "warm bag"]).toarray(),
                   columns=vec.get_feature_names_out()).round(2))
{'not': 1.511, 'not warm': 1.511, 'warm': 1.0}
    not  not warm  warm
0  0.64      0.64  0.42
1  0.00      0.00  1.00

warm is in all four notes, so its IDF is exactly 1; not and not warm are in two: ln(5/3) + 1 = 1.511. In the row for "not warm" the pair not warm carries as much weight as not, so a model can give the phrase its own coefficient. "warm bag" keeps only warm (bag is in one note, below min_df).

Glossary

TermMeaning
transfer learningReusing a model trained on a large dataset and training only what is specific to your task
backboneThe pretrained convolutional layers that turn an image into features
headThe final layer(s) that turn features into class scores (fc in ResNet, classifier in MobileNet)
feature extractionUsing a frozen backbone's outputs as inputs for a new, small model
fine-tuningLetting some pretrained layers keep learning, with a small learning rate
requires_gradPer-tensor switch: False freezes the tensor (no gradient, no update)
parameter groupsOptimizer groups with their own learning rate (layer4 1e-4, head 1e-3)
label curveAccuracy against the number of labeled training examples: is labeling more worth it?
token / tokenizingA unit of text that is counted (usually a word) / cutting text into tokens
bag of wordsA document represented by word counts, ignoring order
sparse matrixStores only non-zero cells and their positions
TF-IDFTerm frequency times inverse document frequency: counts weighted by rarity, rows scaled to length 1
stop wordsVery common words some tools remove; the English list includes not, no, never
n-gram / bigramA run of n consecutive tokens / a pair of words
embeddingA dense vector for a word or text, learned so that similar meanings are close
