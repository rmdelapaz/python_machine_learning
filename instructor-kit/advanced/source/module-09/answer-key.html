10.5 · Transfer Learning: self-check

Q1
With a frozen backbone, the lesson computes the 512 features of every tile ONCE and then trains the head on that table. Why is that allowed?
A) Frozen weights never change, so each tile's features are the same in every epoch
B) Computing features once is required by PyTorch for pretrained models
C) The head needs the features as NumPy arrays, not tensors
D) Features computed once are more accurate than features computed every epoch
Why: A frozen backbone in eval() mode is a fixed function: the same tile always gives the same 512 numbers. Recomputing them every epoch would cost the full forward pass for nothing. Once you fine-tune (unfreeze layer4), the features change every step and caching no longer works.
B is wrong: PyTorch has no such rule; the project trains through the frozen backbone every epoch and that works too, just slowly.
C is wrong: The demo's head is an nn.Linear trained on tensors; NumPy is only needed for scikit-learn.
D is wrong: Same numbers either way; the gain is speed, not accuracy.
Q2
What does this print?
import torch
from torch import nn
from torchvision import models
m = models.mobilenet_v3_small(weights=None)
for p in m.parameters():
    p.requires_grad = False
m.classifier = nn.Linear(576, 3)
print(sum(p.numel() for p in m.parameters() if p.requires_grad))
1731
Why: Everything existing is frozen first; the new head is created afterwards and new layers are trainable by default: 576 × 3 weights + 3 biases = 1,731.
Q3
The label curve: frozen features reach 0.755 with 100 labeled tiles and 0.902 with 2,000; the from-scratch CNN reached 0.719 with 2,000. Pinecrest offers to pay for 5,000 more labels for the frozen-feature model. Your advice?
A) Yes: accuracy always keeps growing with more labels
B) Yes: the from-scratch CNN would then beat transfer learning
C) Probably not: the curve has flattened (1,000 to 2,000 added under a point); fine-tuning is the better next step
D) No: transfer learning cannot use more than 2,000 labels
Why: Read the curve like a budget: above about 500 tiles each extra label buys very little for a frozen backbone. Letting the features adapt (fine-tuning layer4) moved validation accuracy from 0.876 to 0.924 in the project.
A is wrong: The curve shows diminishing returns: +0.007 from 1,000 to 2,000.
B is wrong: Possible in principle with far more data, but nothing on the page suggests it at 7,000 tiles.
D is wrong: Nothing limits the number of labels; the gain per label is the issue.
Q4
A learner extracts features with a freshly created ResNet-18 (never called .eval()) under torch.no_grad(). What goes wrong?
A) Nothing: no_grad already switches the model to evaluation mode
B) Batch normalization uses each batch's statistics, so a tile's features depend on its batch, and the stored ImageNet statistics are overwritten
C) PyTorch raises an error because the model is in training mode
D) The features are computed with dropout, so they are all zero
Why: no_grad stops gradient tracking; eval() changes how layers behave. In training mode batch norm normalizes with the current batch and updates its running averages even without gradients. The demo showed it: same tile, different features in a batch of 8 and a batch of 2.
A is wrong: no_grad and eval() are independent switches.
C is wrong: No error at all: that is why this mistake is dangerous.
D is wrong: ResNet-18 has no dropout; and dropout zeroes some activations, not all.
Q5
What happens when this runs?
import torch
from torchvision import models
net = models.resnet18(weights=None).eval()
net(torch.zeros(1, 1, 64, 64))
A) It returns 1,000 ImageNet scores for the image
B) It returns 512 features because the model is in eval() mode
C) ValueError: the image must be resized to 224 pixels first
D) RuntimeError: the first convolution expects 3 channels and the image has 1
Why: The first layer has 64 filters spanning 3 color channels. Fix: repeat the gray channel (x.repeat(1, 3, 1, 1) or transforms.Grayscale(num_output_channels=3)). The message: RuntimeError: Given groups=1, weight of size [64, 3, 7, 7], expected i...
A is wrong: It never gets past the first convolution.
B is wrong: fc was not replaced, and the channel error comes first anyway.
C is wrong: ResNet accepts any reasonable size thanks to its average pooling; 64 pixels runs once the channels are right.
Q6
What does this print?
from torchvision import models
print(models.resnet18(weights=None).fc)
Linear(in_features=512, out_features=1000, bias=True)
Why: fc is ResNet-18's head: 512 features in, 1,000 ImageNet class scores out. Transfer learning replaces it, with nn.Identity() for features or nn.Linear(512, 10) for EuroSAT.

import torch
from torchvision import transforms

11.1 · Text Classification: self-check

Q7
What does this print?
from sklearn.feature_extraction.text import CountVectorizer
print(CountVectorizer().build_analyzer()("I am a 2-person tent fan!"))
['am', 'person', 'tent', 'fan']
Why: The default token pattern keeps runs of two or more word characters, lowercased: one-letter words (I, a) and the digit 2 disappear, and 2-person becomes person. Punctuation is dropped.
Q8
Why does the lesson put TfidfVectorizer inside the pipeline instead of vectorizing all 3,095 reviews first?
A) Pipelines make TF-IDF faster on sparse matrices
B) A vectorizer outside a pipeline cannot produce bigrams
C) The vocabulary and IDF values are learned from data, so they must come from the training text only (also inside every CV fold)
D) LogisticRegression refuses a sparse matrix that was not produced inside a pipeline
Why: A vectorizer is a fitted transformer like a scaler. Fitted on all reviews, test-only words join the vocabulary and every IDF shifts (334 words instead of 333; idf of leaked 4.17 instead of 4.145): the test score then describes a model that saw the future.
A is wrong: Speed is the same.
B is wrong: ngram_range works anywhere.
D is wrong: Logistic regression accepts any sparse matrix.
Q9
What does this print?
from sklearn.feature_extraction.text import CountVectorizer
print(CountVectorizer(stop_words="english").build_analyzer()("Would not buy it again."))
A) ['buy']
B) ['would', 'not', 'buy', 'again']
C) ['not', 'buy']
D) ['would', 'buy', 'again']
Why: scikit-learn's English stop-word list contains would, not, it and again; it is gone because it is a stop word too. A review that said Would not buy it again reaches the model as the single word buy: the stop-word trap in one line.
B is wrong: That is the default analyzer without a stop-word list (it would also keep it).
C is wrong: not IS on the list: that is the whole problem.
D is wrong: would and again are on the list as well.
Q10
The training matrix is 2,321 × 333 with 5.3% of cells filled. Why does scikit-learn return it as a sparse matrix?
A) Sparse matrices make logistic regression more accurate
B) So that it can be turned into a pandas DataFrame
C) Because TF-IDF values are always between 0 and 1
D) Almost every cell is zero, so storing only the non-zero values saves memory, which matters with real vocabularies
Why: Each review uses a handful of the vocabulary's words. With 50,000 documents and 100,000 words, a dense table would need about 40 GB; the sparse one fits in a few megabytes. Avoid .toarray() on anything bigger than a toy.
A is wrong: Accuracy is the same; only memory and speed differ.
B is wrong: Sparse output cannot become pandas output (SHELL convention: leave text vectorizers sparse).
C is wrong: True but irrelevant: dense matrices can hold values between 0 and 1 too.
Q11
What does this print? (scikit-learn's default IDF is ln((1 + n) / (1 + df)) + 1.)
from sklearn.feature_extraction.text import TfidfVectorizer
v = TfidfVectorizer().fit(["warm tent", "warm bag", "light tent", "light bag"])
print(round(v.idf_[v.vocabulary_["warm"]], 3))
1.511
Why: warm appears in 2 of the 4 documents: ln(5 / 3) + 1 = 1.511. A word in every document would get exactly 1, the smallest possible value.
Q12
In the review-triage project, lowering the flagging threshold for P(negative) from 0.5 to 0.3 does what?
A) Raises both recall and precision for negative reviews
B) Catches more unhappy customers (recall up) at the cost of more false alarms (precision down)
C) Changes the model's coefficients
D) Leaks the test set into training
Why: On the training folds recall rose from 0.570 to 0.851 while precision fell from 0.828 to 0.709. The threshold is a business choice made on cross-validated probabilities, then graded once on the test set (0.858 / 0.698).
A is wrong: They trade against each other.
C is wrong: The threshold is applied after the model; nothing is refitted.
D is wrong: Only if you choose it by looking at the test set; the project uses cross_val_predict on training reviews.

['all' 'at' 'at all' 'not' 'not warm' 'warm' 'warm at']

Predict the output, then run it.

import pandas as pd

  1. C So the network outputs its 512 features instead of 1,000 ImageNet class scores (freezing is requires_grad; Identity has no weights).

  1. B [[0 0 2]]: the vocabulary is light, tent, warm; jacket is unknown and ignored; warm counted twice.
  2. A The list removes negation words such as not, which carry a lot of sentiment.
  3. C 1, the smallest possible value: ln((1 + n)/(1 + n)) + 1.

Exit Ticket

  1. Backbone and head: the backbone is every convolutional block (conv1 to layer4 plus pooling), frozen and in eval() mode; the head is fc, replaced by nn.Identity() (features) or a new nn.Linear(512, 10).
  2. Bag-of-words failure: Would not buy again. (unigrams 0.21, stop words removed 0.51) or Not bad at all. Fix: bigrams (ngram_range=(1, 2)): not bad gets +1.46, Would not buy again. drops to 0.11. Typos → character n-grams; synonyms → embeddings.
  3. Learned from training only: 10.5: the head and anything chosen on validation (stage 1 vs 2); the ImageNet statistics are borrowed, not learned. 11.1: vocabulary and IDF (inside the pipeline), and the threshold (cross-validated probabilities).

Common Wrong Answers and What They Reveal

  • Q1 D ("more accurate"). Confuses caching with improving. Same numbers, less time.
  • Q2 written as 0. Thinks the freeze loop also covers the new head. Order matters: the head came after the loop.
  • Q4 A ("no_grad switches to eval"). The most common confusion in Module 10. no_grad = no gradient tracking; eval() = layer behavior.
  • Q9 C ("['not', 'buy']"). Assumes not is too important to be a stop word. That is exactly the trap.
  • Q11 written as 1.0. Remembered the lesson quiz (word in every document) without counting: warm is in 2 of 4.
  • Exit ticket 3 citing the ImageNet mean and std as learned from training data. They are the pretrained network's, not ours, and not learned at all here.
