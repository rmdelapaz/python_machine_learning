Retrieval on Lessons 8.2 and 8.3. Not graded.

W1
What does this print?
from sklearn.metrics import adjusted_rand_score
a = [0, 0, 1, 1, 2, 2]
b = [2, 2, 0, 0, 1, 1]
print(adjusted_rand_score(a, b))
A) 0.0
B) 0.333
C) 1.0
D) An error: the labels do not match
Why: The adjusted Rand index compares who is grouped with whom and ignores cluster numbers: both labelings put the same pairs together. Lesson 8.2 used it for stability; today it scores clusterings against known groups.
W2
Lesson 8.2 chose k for Pinecrest's customers. Which piece of evidence is NOT a reason to pick k?
A) Where inertia stops dropping steeply (the elbow)
B) A high mean silhouette, checked per cluster
C) Clusters that reappear when you refit on bootstrap samples
D) The k where inertia reaches its minimum
Why: Inertia always falls as k grows (one center per point gives zero), so its minimum means nothing. The elbow, the silhouette, stability and usefulness are the four checks of Lesson 8.2.
W3
What does this print?
from scipy.cluster.hierarchy import linkage
Z = linkage([[0.0], [1.0], [10.0], [11.0]], method="single")
print(Z[:, 2])
A) [ 1. 1. 10.]
B) [1. 1. 9.]
C) [0. 1. 9.]
D) [ 1. 10. 11.]
Why: Single linkage merges 0 with 1 at distance 1, 10 with 11 at distance 1, then the two pairs at their CLOSEST points, 1 and 10: distance 9. A big jump in merge height (1 to 9) is where a dendrogram suggests cutting.
W4
Two groups of customers are joined by a thin trail of in-between customers. Which linkage merges them too early?
A) Single
B) Complete
C) Average
D) Ward
Why: Single linkage measures the closest pair, so a chain of in-between points makes two groups look close: chaining. Density-based methods today treat that trail very differently, as possible noise.
W5
Lesson 8.2 segmented customers on four columns with a log and a scaler. To segment next month's NEW customers, what do you reuse?
A) Only the K-Means centers
B) The whole fitted pipeline (log, scaler, K-Means): call predict on the new rows
C) A new scaler fitted on the new customers, then the old centers
D) Nothing: refit K-Means on the new customers
Why: The centers live in the scaled, logged space of the training customers, so new rows must go through the same fitted steps. Keep one pipeline. Today's density methods cannot do this at all, and Gaussian mixtures can.

8.4 · Density-Based Clustering: self-check

Q1
What does this print?
import numpy as np
from sklearn.cluster import DBSCAN
pts = np.array([[0.0], [1.0], [2.0], [10.0], [11.0], [30.0]])
print(DBSCAN(eps=1.5, min_samples=3).fit_predict(pts))
A) [0 0 0 1 1 2]
B) [ 0 0 0 1 1 -1]
C) [ 0 0 0 -1 -1 -1]
D) [-1 -1 -1 -1 -1 -1]
Why: With min_samples=3 (the point itself counts) only the point at 1.0 has a crowded neighborhood (0, 1 and 2 are all within 1.5), so it is the one core point; 0 and 2 are within reach of it and join cluster 0 as border points. 10 and 11 have only each other: two points are not a crowd, and no core point is near, so both are noise, like the lone 30.
A is wrong: DBSCAN never gives a lone point its own cluster; isolated points are noise (-1).
B is wrong: 10 and 11 are close to each other, but a pair is not three points: neither is core.
D is wrong: The point at 1.0 has three points within 1.5 (itself included), so there is one cluster.
Q2
You compute each point's distance to its 10th nearest neighbor (itself included), sort the distances and plot them. What is the plot for?
A) Choosing the number of clusters
B) Choosing a starting eps for DBSCAN with min_samples=10: just above the knee
C) Choosing min_samples: the height of the knee
D) Checking whether the silhouette is high enough
Why: Each distance is the smallest eps that would make that point a core point with min_samples=10. Crowded points have small distances, isolated ones large: the bend in the sorted curve is a sensible first eps, then a short sweep around it.
A is wrong: DBSCAN has no cluster-count setting; the count comes out of eps and min_samples.
C is wrong: min_samples is chosen first (about twice the features); the plot depends on it.
D is wrong: The k-distance plot uses no cluster labels at all.
Q3
What does this print?
import numpy as np
labels = np.array([0, 0, 1, -1, 1, -1, 2])
print(len(set(labels)), len(set(labels) - {-1}))
4 3
Why: set(labels) holds 0, 1, 2 and -1: four labels. -1 is the noise label, not a cluster, so the real count is three. Report the noise count separately; it is a result.
Q4
You switch from DBSCAN to HDBSCAN on a new data set. Which setting do you choose first, and from what?
A) eps, from the knee of the k-distance plot
B) n_clusters, from the elbow of the inertia curve
C) min_cluster_size, from the smallest group you would act on, then check that nearby values agree
D) xi, from the steepest wall in the reachability plot
Why: HDBSCAN needs no eps: it keeps the clusters that stay stable across all density levels. The setting you can reason about is the smallest group worth naming (HDBSCAN(min_cluster_size=..., copy=True)); Lesson 8.4's Exercise 3 and today's lab both check that neighboring values give the same answer.
A is wrong: That is DBSCAN's setting; HDBSCAN replaces it.
B is wrong: Density methods have no k.
D is wrong: xi belongs to OPTICS's cluster extraction.
Q5
HDBSCAN on card payments returns clusters that each hold payments with exactly 1, 2, 3 or 4 items. What is the best reading?
A) Four genuinely different kinds of shopper, sorted by basket size
B) The items column needs more weight than the others
C) The features were not scaled, so items dominated
D) items only takes whole values, so payments stack on exact values and look dense: profile further and treat the split as an artifact unless the business cares about it
Why: A whole-number column turns each value into a shelf of identical points, the densest thing a density method can see (Lesson 8.4, Common Mistake 5). Today's payment lab shows it, and the real finding there is the noise, not the shelves.
A is wrong: Nothing else about those clusters differs much; the split follows one integer column.
B is wrong: Weighting does not change the fact that values are stacked.
C is wrong: The lab scaled all five features; the problem is that the values are whole numbers.
Q6
What does this print?
from sklearn.cluster import HDBSCAN
print(hasattr(HDBSCAN(), "fit_predict"), hasattr(HDBSCAN(), "predict"))
A) True True
B) True False
C) False True
D) False False
Why: DBSCAN, OPTICS and HDBSCAN describe the data they were fitted on: they have fit_predict but no predict. For new customers, refit, or assign each to the segment of its nearest clustered neighbor and call it noise when it is too far from everyone (Lesson 8.4, Exercise 4).
A is wrong: There is no predict: a new point could even change the clusters.
C is wrong: fit_predict exists on every clustering estimator.
D is wrong: fit_predict exists.

pts = np.array([[1.0], [1.2], [1.4], [3.0], [3.1], [3.2], [9.0]])
print(DBSCAN(eps=0.25, min_samples=3).fit_predict(pts))

Why: 1.0, 1.2 and 1.4: the middle point has three points within 0.25 (itself included), so it is core and the other two join as border points. 3.0, 3.1 and 3.2 likewise. 9.0 has nobody near: noise.

8.5 · Gaussian Mixture Models: self-check

Q7
What does this print?
import numpy as np
from sklearn.mixture import GaussianMixture
x = np.array([[0.0], [0.1], [5.0], [5.1], [5.2]])
gm = GaussianMixture(n_components=2, random_state=42).fit(x)
print(gm.predict_proba([[100.0]]).max().round(2))
A) 0.0
B) 0.5
C) nan
D) 1.0
Why: Each row of predict_proba adds up to 1, however far the point is from everything: 100 is far closer to the component near 5 than to the one near 0, so it gets that component with certainty. How typical a point is comes from score_samples, not from the probabilities.
A is wrong: One of the two probabilities must be large: they add up to 1.
B is wrong: 0.5 would mean equally close to both components; 100 is not.
C is wrong: A far-away point still gets well-defined probabilities.
Q8
BIC for 1 to 6 components is 9,800, 8,100, 7,950, 7,930, 7,920 and 7,915. What is the most sensible choice?
A) About 2 or 3: the big drops stop there; then check whether the third component means something
B) 6, because BIC is lowest there
C) 1, because BIC only rewards simple models
D) None: BIC needs a minimum to be usable
Why: Lower is better, but read the size of each improvement: 1,700, then 150, then 20, 10, 5. After two or three components the extra ones polish shapes of not-quite-Gaussian data. This is the same reading as Lesson 8.5's project.
B is wrong: The last drops are tiny; more components cost parameters and explain little.
C is wrong: BIC penalizes parameters but also rewards fit; the first drops are large.
D is wrong: A curve with no minimum is normal on real data; read where the big gains stop.
Q9
Three groups were made by stretching three identical round blobs with the same matrix. Which covariance_type should BIC prefer?
A) "spherical"
B) "diag"
C) "tied"
D) "full"
Why: tied gives every component the same ellipse shape, which is exactly how the groups were made, with the fewest parameters that fit. In Lesson 8.5 BIC picked tied (3,032.8) over full (3,061.9).
A is wrong: Round components cannot follow stretched groups (ARI 0.568 in the lesson).
B is wrong: Axis-aligned ellipses cannot tilt.
D is wrong: full also fits, but pays for shapes it does not need, so its BIC is a little worse.
Q10
What does this print, and what does it tell you?
from sklearn.metrics import adjusted_rand_score
run_a = [0, 0, 1, 1, 2, 2]
run_b = [1, 1, 2, 2, 0, 0]
print(adjusted_rand_score(run_a, run_b))
1.0: the two runs found the same groups under different numbers
Why: ARI ignores the names of the clusters and compares only who is grouped with whom. Component numbers are arbitrary: name segments by their profile, and match runs with ARI or a crosstab.
Q11
A customer sits far from every component, yet their largest predict_proba value is 0.99. Which output flags them as unusual?
A) score_samples: a very low log-density
B) predict: it returns -1 for outliers
C) weights_: the component's share is small
D) means_: the customer equals no mean
Why: predict_proba compares components with each other, so a far-away point can still be 99% 'nearest component'. score_samples measures how likely the point is under the whole mixture: the lowest values are the atypical customers (the bridge to Lesson 8.6).
B is wrong: A mixture's predict returns a component number, never -1; that convention belongs to outlier detectors (8.6).
C is wrong: weights_ describe components, not individual customers.
D is wrong: No real customer sits exactly on a mean; that says nothing about how typical they are.
Q12
What happens when this runs?
from sklearn.mixture import GaussianMixture
GaussianMixture(n_components=4, random_state=42).fit([[0.0], [1.0], [2.0]])
ValueError: Expected n_samples >= n_components but got n_components = 4, n_samples = 3
Why: Every component needs data to estimate a mean and a covariance, so there can never be more components than rows, and in practice you need many more rows than that. Fewer components, a simpler covariance_type, or more data.

8.5 · Gaussian Mixture Models: predict, then run

P3
Predict the output, then run it.
import numpy as np
from sklearn.mixture import GaussianMixture
x = np.array([[0.0], [0.2], [0.4], [8.0], [8.2]])
gm = GaussianMixture(n_components=2, random_state=42).fit(x)
print(np.sort(gm.weights_).round(1))
[0.4 0.6]
Why: Two well-separated groups: three of five values near 0 (weight 0.6) and two near 8 (0.4). np.sort puts the smaller first.
P4
Predict the output, then run it.
import numpy as np
from sklearn.mixture import GaussianMixture
x = np.array([[0.0], [0.2], [0.4], [8.0], [8.2]])
gm = GaussianMixture(n_components=2, random_state=42).fit(x)
print(gm.predict_proba([[4.1], [100.0]]).sum(axis=1).round(2))
[1. 1.]
Why: Each row of predict_proba adds up to 1, for a point in the middle (4.1) and for a point far from everything (100) alike. Typicality is score_samples' job.

Exit Ticket

  2. Mixture, not HDBSCAN: predicts for new rows; probabilities; a density (score_samples) and synthetic samples. HDBSCAN, not a mixture: clusters of any shape and varying density; an explicit noise label; no number of clusters to choose.

Common Wrong Answers and What They Reveal

  • Q1 B ([ 0 0 0 1 1 -1]). Thinks two close points make a cluster. Recite: min_samples counts the point itself; a pair is not a crowd of three.
  • Q3 written as 4 4 or 3 3. Either counts -1 as a cluster or forgets that it is a label. Ask what set returns.
  • Q5 A (four kinds of shopper). Believes the algorithm. Point to the profile table of the payment lab: the clusters differ in one integer column only.
  • Q7 A (0.0) or B (0.5). Expects probabilities to fall far from the data. The exit ticket's question 3 targets the same misunderstanding.
  • Q8 B (6). Reads the minimum. Same habit as inertia in the warm-up: read the size of the drops.
  • Q11 B (predict returns -1). Mixes the mixture's predict with outlier detectors' convention. Lesson 8.6 introduces that convention; flag it now.
