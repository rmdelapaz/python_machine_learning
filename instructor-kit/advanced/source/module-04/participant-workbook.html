Lessons

8.4

Density-Based Clustering

By the end you can
  • Explain core, border and noise points, and what eps and min_samples control in DBSCAN
  • Choose a starting eps from a k-distance plot and read the effect of changing it
  • Read an OPTICS reachability plot and explain why one eps fails when clusters have different densities
  • Cluster with HDBSCAN, count clusters and noise correctly, and profile the result
  • Judge whether a density-based clustering found real structure or an artifact of the features
Key ideas
  • A city at night. A cluster is a crowded region separated by sparser space; points in sparse space are noise, label -1. The number of clusters comes out of the data.
  • DBSCAN's two settings. eps is a radius; min_samples is how many points (itself included) make a neighborhood crowded. Core, border, noise.
  • Choosing eps. The k-distance plot: each point's distance to its min_samples-th neighbor, sorted. Start just above the knee, then sweep a few values.
  • One radius fails when clusters have different densities: small eps loses loose groups, large eps merges tight ones.
  • OPTICS draws a reachability plot (clusters are valleys); HDBSCAN keeps the clusters stable across densities and needs mainly min_cluster_size (pass copy=True).
  • Count clusters without -1, scale first, and remember these models have no predict.
  • Profile every cluster. Whole-number columns stack points on exact values and create dense "clusters" that are artifacts.
Worked example: roles in a crowd and a trickle

A crowd of 300 points and a trickle of 40 scattered around it. How do the roles change when DBSCAN asks for a bigger crowd?

import numpy as np
import pandas as pd
from sklearn.datasets import make_blobs
from sklearn.cluster import DBSCAN

rng = np.random.default_rng(7)
crowd, _ = make_blobs(n_samples=300, centers=[[0, 0]], cluster_std=0.5, random_state=7)
trickle = rng.uniform(-4, 4, size=(40, 2))          # scattered points around the crowd
X = np.vstack([crowd, trickle])

for min_samples in [5, 15]:
    db = DBSCAN(eps=0.4, min_samples=min_samples).fit(X)
    core = np.zeros(len(X), dtype=bool)
    core[db.core_sample_indices_] = True
    noise = db.labels_ == -1
    print(f"min_samples={min_samples:<3} clusters={len(set(db.labels_) - {-1})}  "
          f"core={core.sum()}  border={(~core & ~noise).sum()}  noise={noise.sum()}")
min_samples=5   clusters=1  core=294  border=5  noise=41
min_samples=15  clusters=1  core=276  border=20  noise=44

With min_samples=5, 294 points are core and only 5 are border points: almost everyone in the crowd is crowded enough. Asking for 15 neighbors makes the fringe of the crowd thinner than the rule: 18 fewer core points, four times as many border points, and a few more noise points. The cluster is the same; the roles moved. A larger min_samples is a stricter definition of "crowded", which is why eps and min_samples must be chosen together.

8.5

Gaussian Mixture Models

By the end you can
  • Explain a Gaussian mixture as a weighted sum of components with means, covariances and weights
  • Fit a mixture with EM and read predict_proba as soft cluster membership
  • Choose the covariance type and the number of components with BIC and AIC
  • Compare a mixture with K-Means on elongated or overlapping clusters
  • Use a fitted mixture to score how typical a point is and to generate new samples
Key ideas
  • Paint from base colors. A mixture is a weighted sum of Gaussian components, each with a mean (means_), a covariance (covariances_) and a weight (weights_).
  • EM alternates soft assignments (E-step) and refitting (M-step). It finds a good answer, not always the best: use n_init and random_state.
  • Soft membership. predict_proba rows add up to 1; keep the top probability as a confidence instead of stopping at predict.
  • Ellipses, not circles. Full or tied covariances follow stretched groups K-Means cuts across. Compare covariance types with BIC (lower is better).
  • How many components? Read where the big BIC drops stop; on real data BIC often keeps creeping down.
  • Numbers are arbitrary. Name components by their profile; match runs with ARI or a crosstab.
  • A density model. score_samples scores how typical a point is (the bridge to anomaly detection); sample generates synthetic data, only as realistic as the Gaussian assumption.
Worked example: borderline is not the same as atypical

Two columns of fractions (discount share and return rate), four components. Which customers does the mixture find least typical, and how sure is it about them?

import numpy as np
import pandas as pd
from sklearn.preprocessing import StandardScaler
from sklearn.mixture import GaussianMixture

customers = pd.read_csv("data/customers_churn.csv")
cols = ["discount_share", "return_rate"]
Z = StandardScaler().fit_transform(customers[cols])
gm = GaussianMixture(n_components=4, n_init=3, random_state=42).fit(Z)

customers["log_density"] = gm.score_samples(Z)
customers["confidence"] = gm.predict_proba(Z).max(axis=1)
print("weights:", np.sort(gm.weights_).round(3))
print(f"confidence below 0.6: {(customers['confidence'] < 0.6).sum()} customers")
weights: [0.14  0.187 0.276 0.397]
confidence below 0.6: 396 customers
print(customers.nsmallest(4, "log_density")[cols + ["log_density", "confidence"]].round(3))
      discount_share  return_rate  log_density  confidence
880            0.576        0.332      -11.365       0.995
2966           0.593        0.261       -9.868       0.839
4834           0.544        0.289       -9.751       0.920
4818           0.490        0.418       -9.551       1.000

The least typical customers combine a high discount share with a high return rate, a mix no component describes well, so their log-density is the lowest. Yet look at the confidence column: the mixture is 0.84 to 1.00 sure which component each belongs to. Confidence answers "which component is nearest?"; log-density answers "is this customer like any of them?". Borderline and atypical are different questions.

Glossary

TermMeaning
epsDBSCAN's neighborhood radius
min_samplesPoints (itself included) that make a neighborhood crowded
core / border / noise pointCrowded itself / next to a core point / neither (label -1)
k-distance plotSorted distances to the min_samples-th neighbor; its knee suggests eps
reachability plotOPTICS's picture: points in visiting order, clusters as valleys
HDBSCANKeeps the clusters that are stable across density levels; main setting min_cluster_size
Gaussian mixtureA weighted sum of bell-shaped components
componentOne Gaussian: a mean, a covariance (an ellipse), a weight
EMExpectation-maximization: alternate soft assignments and refits until the log-likelihood stops improving
covariance_typespherical, diag, tied or full: how flexible each component's shape is
BIC / AICFit minus a penalty per parameter; lower is better; AIC penalizes less
log-densityscore_samples: how likely a point is under the whole model; low = atypical
label switchingThe same clustering with the components numbered differently
