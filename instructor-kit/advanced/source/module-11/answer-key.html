Session 11 12 self-check items Confidential

Warm-up

W1
Lesson 11.2 hid each customer's LATEST purchase for testing, not a random one. Why?
It mimics the real job (predict the next purchase from earlier ones) and keeps future purchases out of the training matrix: the same rule as splitting by time in Lesson 1.2.
W2
Best sellers scored a hit rate at 10 of 0.209 and item-kNN 0.308. Say what 0.308 means in one sentence.
For about 31% of customers, the product they really bought next was in their personal top-10 list (already-owned products excluded): about 50% more often than the best-seller list.
W3
Why did SVD with 40 factors recommend worse than with 5?
With many factors it memorizes each customer's past basket instead of broad tastes, so it generalizes worse (0.19 against 0.311 at k = 5).
W4
A colleague emails you churn_model.joblib. What is the risk of loading it, and what did Lesson 12.1 use instead?
A joblib file is a pickle: loading it can run arbitrary code. Lesson 12.1 saved with skops, which loads only reviewed types passed to trusted=.
W5
Your model card stores a SHA-256 of customers_churn.csv. Today the hash differs. What do you know, and what don't you?
The file is not byte-for-byte the one the model was trained on; the hash cannot say what changed (one row, the order, a column).

12.2 · Serving and Monitoring Models: self-check

Q1
A caller posts a customer with "home_store": "Denver" to the lesson's /predict. What happens?
A) The one-hot encoder ignores the unknown store and the caller gets status 200 with a probability
B) pydantic rejects it before the model runs: status 422, and the body names home_store and the allowed stores
C) uvicorn crashes and the caller gets status 500
D) to_frame raises a KeyError and the caller gets status 500
Why: home_store is a Literal of five stores in schemas.py. FastAPI validates the body with the schema before calling the endpoint, so the model never runs and the 422 lists every problem at once.
A is wrong: That is what would happen if a caller called the PIPELINE directly: the order window exists so it never does.
C is wrong: A 500 means the server failed; an invalid request is the caller's problem, answered with 422.
D is wrong: to_frame is never reached: validation comes first.
Q2
What does this print?
from pydantic import BaseModel, Field
class Visit(BaseModel):
    days: int = Field(ge=0, le=365)
    share: float = Field(ge=0, le=1)
v = Visit(days="30", share=1)
print(v.days * 2, v.share)
60 1.0
Why: pydantic's default (lax) mode converts the text "30" to the integer 30 and the integer 1 to the float 1.0 the schema asks for; both pass their limits. Doubling an int gives 60.
Q3
Why does to_frame in serve.py end with .astype(DTYPES)?
A) It makes predictions faster
B) pydantic cannot produce a DataFrame without it
C) skops refuses to load the model unless the dtypes are stored
D) A one-row table with a None gets the object dtype, the imputer does not see it as missing, and the model scores a slightly different customer with no error
Why: This is training-serving skew (Common Mistake 3): object 0.0719 without the dtypes, str 0.0708 with them. The cure is to store the training dtypes with the model and test that the API matches the notebook on real rows, gaps included.
A is wrong: Speed is not the point; the numbers are.
B is wrong: pydantic hands over plain Python values; pandas builds the frame.
C is wrong: skops checks types inside the model file, not the request's columns.
Q4
This week email_opens_90d has a PSI of 8.4, its missing rate is 100% (9% in the reference), and the mean score barely moved. What is the best reading?
A) A broken data feed: fix it and re-score the week; do not retrain on it
B) Customers changed: retrain on this week's batch
C) Nothing to do: the scores did not move, so the model is fine
D) PSI cannot be trusted above 1, so ignore it
Why: Every value fell into the missing bin: the customers did not change, the pipe did. The imputer quietly filled the median, so the scores looked normal while 500 customers were scored as average email readers (the lesson's week 3).
B is wrong: Retraining on a broken feed teaches the model the bug, and the labels are months away anyway.
C is wrong: That is exactly the trap: only the missing-rate and PSI checks warned.
D is wrong: A huge PSI is honest here: it is the signature of a broken feed.
Q5
What does this print? (A two-bin PSI.)
import numpy as np
ref = np.array([0.5, 0.5])
cur = np.array([0.8, 0.2])
print(round(float(np.sum((cur - ref) * np.log(cur / ref))), 3))
A) 0.0
B) -0.416
C) 0.416
D) 0.3
Why: (0.8 - 0.5) × ln(1.6) + (0.2 - 0.5) × ln(0.4) = 0.141 + 0.275 = 0.416. Both terms are positive: PSI never goes below 0, and it is well past the 0.25 "real shift" line.
A is wrong: That would need identical shares.
B is wrong: Each term is (difference) × ln(ratio), which always has the same sign twice: never negative.
D is wrong: 0.3 is the change in one share, not the index.
Q6
With 30,000 rows, a Kolmogorov-Smirnov test on discount share gives p < 0.0001, while the PSI is 0.021. Should the monitor raise an alert?
A) Yes: p below 0.05 means the inputs drifted
B) No: with enough rows any difference is detectable; PSI says the shift is tiny, and an alert should be about size
C) Yes: PSI is unreliable on large batches
D) No: KS tests only work on categories
Why: Lesson 12.2 Exercise 4: the same 3% nudge gives p = 0.42 on 500 rows and p < 0.0001 on 30,000, while PSI stays near 0.02. A test answers "can I detect any difference?"; PSI answers "how big is it?".
A is wrong: Significance grows with the sample size, not with the size of the change.
C is wrong: PSI is about shares, so it hardly moves with the count.
D is wrong: KS compares numeric distributions.

12.2 · Serving and Monitoring Models: predict, then run

P1
Predict the output, then run it.
from pydantic import BaseModel, Field
class Order(BaseModel):
    units: int = Field(ge=1, le=10)
    note: str | None = None
print(Order(units="7").units + 1, Order(units=7).note)
8 None
Why: Lax mode turns the text "7" into the integer 7 (7 + 1 = 8); note is optional and defaults to None.
P2
Predict the output, then run it.
import numpy as np
ref = np.array([0.25, 0.25, 0.25, 0.25])
for cur in [np.array([0.25, 0.25, 0.25, 0.25]), np.array([0.10, 0.20, 0.30, 0.40])]:
    print(round(float(np.sum((cur - ref) * np.log(cur / ref))), 3))
0.0 0.228
Why: Identical shares give 0.0. Moving 15 points of share from the first bin to the last gives 0.228: in the "watch" band, just under 0.25.

13.1 · Case Study: Predicting Churn: self-check

Q7
Next quarter the retention offer costs $25 and is still worth $60 when it reaches a would-be churner. If the probabilities are calibrated, above which churn probability does an offer pay?
A) 0.25
B) 0.5
C) 0.417
D) 2.4
Why: Offer when p × 60 > 25, so p > 25 / 60 = 0.417. The cost-scenario lab confirms it on out-of-fold predictions: the best threshold on the training data is 0.43.
A is wrong: That was the $15 offer.
B is wrong: 0.5 is predict's default, not a business rule.
D is wrong: That is value / cost, upside down.
Q8
What does this print? ($15 an offer, $60 a churner reached.)
import numpy as np
y = np.array([1, 0, 1, 0, 0, 0])
flagged = np.array([1, 1, 1, 1, 0, 0])
print(60 * ((flagged == 1) & (y == 1)).sum() - 15 * flagged.sum())
60
Why: Four offers, two of them reach churners: 2 × 60 - 4 × 15 = 120 - 60 = 60.
Q9
Cross-validated AUC: random forest 0.868 ± 0.020, gradient boosting (defaults) 0.861 ± 0.013. What may you conclude?
A) The data does not yet say which tree family is better: the gap is inside one fold-to-fold spread
B) The forest is better and should be deployed
C) Boosting is better because its spread is smaller
D) Open the test set to break the tie
Why: A gap of 0.007 with spreads of 0.013 to 0.020 is noise. The case study tunes boosting because its defaults leave the most room; the tuned model's 0.879 then clears both by more than a spread.
B is wrong: 0.007 is well inside the noise.
C is wrong: A smaller spread is not a higher score.
D is wrong: The test set is opened once, after every choice is made: never to choose.
Q10
Which order matches the case study?
A) Tune, split, leak check, threshold, test, explain
B) Split, threshold on the test set, compare, tune, explain
C) Compare on the test set, tune with CV, choose the threshold on the test set, explain
D) Split, leak check, compare with CV, tune with CV, threshold with CV, test once, explain and write up
Why: Everything before "Open the Test Set, Once" uses the 4,500 training customers through cross-validation. The test set gives one honest estimate of the whole plan.
A is wrong: Tuning before the split lets the test rows shape the model.
B is wrong: Choosing the threshold on the test set inflates the reported profit (Mistake 4: $5,280 looks better than the honest $5,220).
C is wrong: Every choice made on the test set makes its score optimistic.
Q11
The manager asks whether the coupon actually keeps customers, or only goes to people who would have stayed anyway. What does the memo suggest?
A) Look at permutation importance: the top feature is the cause
B) Hold back the offer from a random 10% of the list and compare who stays
C) Compare churn of customers who used discounts with those who did not
D) Raise the threshold until precision is 100%
Why: Only an experiment answers a causal question. A random hold-out from the same high-risk list gives two comparable groups; the difference in churn is what the offer really does.
A is wrong: Importance describes what the model relies on, not why customers leave.
C is wrong: Discount users differ from others in many ways: a comparison, not an experiment.
D is wrong: Precision says the list is accurate, not that the coupon works.
Q12
The budget allows 200 offers; 360 test customers are above the break-even probability. Which rule does the case-study project use?
A) The 200 riskiest customers, and never anyone below the break-even probability
B) 200 customers drawn at random from the 360
C) All 360: the budget is a guideline
D) The 200 customers closest to the break-even probability
Why: Rank by probability and spend the budget from the top; an offer below break-even loses money even if the budget allows it. On the test customers that list reaches 131 churners and earns $4,860, against -$540 for 200 random offers.
B is wrong: Random offers from the list waste the ranking.
C is wrong: It breaks the budget.
D is wrong: Those are the least valuable offers above the line.

Capstone Choice: What to Look For

A plan paragraph is ready when it names a decision and its user, the prediction moment, the split the template uses, a metric with its business meaning, the baseline number, and a "do not deploy" bar. The most common gaps: no prediction moment (so no leakage test is possible), a metric without a unit ("accuracy" for fraud), and no bar. Coaching notes per problem are in final-assessment.html.

Exit Ticket

  1. Two silent failures: a frame without the training dtypes (caught by the match test on rows with gaps); a broken feed hidden by the imputer (caught by missing rates and PSI); an impossible value (caught by schema limits).
  2. 0.333 (= 20 / 60). Check it on out-of-fold predictions or with TunedThresholdClassifierCV; the rule assumes calibrated probabilities. The lab's best for $20 was 0.31.
  3. A letter, a decision and a number, for example "D: the ten products on each customer's home page; best-seller hit rate 0.209".

Common Wrong Answers and What They Reveal

  • Q1 A ("the encoder ignores it"). Thinks of the pipeline as the front door. Draw the window again: the schema runs first.
  • Q3 A or C. Has not seen the silent skew. Rerun demo Step 10 for them.
  • Q4 B ("retrain"). Treats drift as a verdict. Ask which labels they would retrain on.
  • Q5 B (a negative PSI). Expects the terms to cancel. Each term is a difference times the log of the same ratio: always ≥ 0.
  • Q9 B. Reads a gap without its spread. Ask for the ± numbers every time.
  • Exit ticket 2: "0.333, done". Right number, missing check: the case study's whole point is theory confirmed by data.
