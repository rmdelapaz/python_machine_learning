Session 7: Neural Networks and PyTorch

How to teach Session 7 of Advanced Machine Learning. Build a neural network by hand in NumPy (forward pass, loss, backpropagation checked numerically, the four-line training loop), let PyTorch's autograd prove it right, then rebuild everything the professional way: tensors, nn.Module, a loss and an optimizer, a DataLoader, early stopping and a saved state_dict. Both projects end with the same honest finding: on Pinecrest's churn table a network beats logistic regression and, at best, ties gradient boosting.

2 lessons 3 hrs session Lessons 10.1–10.2 Session 7 of 13

How to Use This Guide

  • Same rhythm for both lessons: frame (the goal and one mental model) → live demo (you type, they type along) → guided lab (a kit lab, new practice on the lesson's skills) → start the lesson's own project. Exercises, quiz and journal are homework.
  • Type, do not paste. Every code block in the demo scripts was run to produce the output printed under it (Python 3.12, scikit-learn 1.9.1, PyTorch 2.14.1 on 4 CPU threads). Ask for a prediction before every run that prints a number, and read errors from the last line up, out loud.
  • Outputs marked "yours may vary slightly" are PyTorch results. On one machine with a fixed seed and thread count they repeat exactly; another processor or PyTorch build can change the last digits. Say this once at the first such output, then compare trends, not third decimals.
  • The lessons are the reference. Keep deep_learning_basics.html and deep_learning_pytorch.html open for the pictures (the panel diagram, the loss curve and decision boundary, the two-curve chart). Labs live in labs/module-07/: _starter.py files are handouts, _solution.py files are yours.
  • Teal blocks are hands-on, amber blocks are watch-outs. Lesson codes (10.1, 10.2) match the course site.
The #1 risk of Session 7: the math swallows the session

Lesson 10.1 contains a forward pass, a loss, gradient descent, backpropagation, a numeric gradient check and autograd. Each is one demo step of two or three minutes, not a lecture. Derive nothing on the board beyond the shape table and p - y. The learners who want the calculus have it on the lesson page; the ones who do not need to leave knowing the four-line loop, the coin-flip loss 0.693, and that autograd computes the same gradients they could check by nudging. The second risk is the opposite: PyTorch syntax without the honest comparison. Both projects end with the same verdict (a network beats logistic regression on churn and ties gradient boosting at best). Protect the moment the room sees 0.846 against 0.850: it is the course's habit applied to a shiny new tool.

Questions and answers
  1. W1. What does this print? (Lesson 9.2) 
    from sklearn.datasets import make_classification
from sklearn.discriminant_analysis import LinearDiscriminantAnalysis
X, y = make_classification(n_samples=300, n_features=6, n_informative=4, n_classes=3, random_state=42)
print(LinearDiscriminantAnalysis().fit(X, y).transform(X).shape)
    Answer: (300, 2): LDA gives at most (classes - 1) axes, so 3 classes give 2 columns, whatever the number of features.
  2. W2. PCA and LDA both flatten data onto a few directions. What is the one big difference in how they choose them? (9.2) Answer: PCA looks only at X and keeps the directions of largest total spread; LDA uses the labels y and keeps the directions where the class means are far apart relative to the spread inside each class.
  3. W3. A colleague fits LDA on all 200 rows of 500 random features, then cross-validates a classifier on the LDA output and gets 0.99. What happened? (9.2) Answer: Leakage: LDA saw the labels of the rows later used as test folds. With 500 features it can separate any labels. Inside a pipeline, refitted per fold, the score falls to chance.
  4. W4. On a t-SNE map of customers, one island is twice the size of the others and far away from them. What may you conclude from the size and the gap? (9.3) Answer: Very little: t-SNE keeps neighborhoods, not sizes or distances between groups. Check spread and separation in the original data (silhouette, profiles).
  5. W5. Next month 200 new customers arrive and you want to place them on this month's 2-D map. t-SNE or UMAP, and why? (9.3) Answer: UMAP: a fitted UMAP has transform for new rows. t-SNE only has fit_transform; it positions the rows it was given and learns no function.

Mental model to say

Say: "Pinecrest's churn question goes to a panel. Each junior analyst looks at the raw customer numbers and writes down one score of their own; nobody tells them what to look for. A senior analyst reads only the juniors' scores and makes the final call. After every round, each analyst hears how much their score contributed to the final mistake, and adjusts. Then the reason, pointing at a drawn straight line: "Logistic regression draws one straight boundary. Each junior can draw their own line, and the senior combines them, so the panel can bend its boundary around curves and interactions, like the churn threshold near 150 days." Then the four steps on the board, which never change for the rest of Module 10: forward → loss → backward → update.   1. One neuron (2m). "You already know this unit: Lesson 3.1's logistic regression. Weighted sum, plus a bias, through an activation." Do the arithmetic on the board before running it. 
    import numpy as np

x = np.array([0.5, -1.2, 2.0])     # one customer: three scaled features
w = np.array([0.8, 0.1, -0.4])     # one weight per feature
b = 0.2                            # the bias

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

z = x @ w + b
print(f"weighted sum z    = {z:.3f}")
print(f"sigmoid(z)        = {sigmoid(z):.3f}")
print(f"ReLU(z) = max(0,z) = {max(0.0, z):.3f}")
    weighted sum z    = -0.320
sigmoid(z)        = 0.421
ReLU(z) = max(0,z) = 0.000
    With a sigmoid, this neuron IS logistic regression: probability 0.42. ReLU of a negative number is 0. The activation is the only thing that changes between neuron types.

  3. A layer is a matrix multiplication (3m). "Inner dimensions must match; the result takes the outer ones." Write the shape table on the board as you type: (n, 2) @ (2, 16) → (n, 16), then (n, 16) @ (16, 1) → (n, 1). 
    def init_params(n_in, n_hidden, rng):
    return {
        "W1": rng.normal(0, np.sqrt(2 / n_in), size=(n_in, n_hidden)),
        "b1": np.zeros(n_hidden),
        "W2": rng.normal(0, np.sqrt(1 / n_hidden), size=(n_hidden, 1)),
        "b2": np.zeros(1),
    }

def forward(params, X):
    z1 = X @ params["W1"] + params["b1"]       # (n, hidden)
    a1 = np.maximum(0, z1)                     # ReLU
    z2 = a1 @ params["W2"] + params["b2"]      # (n, 1)
    p = sigmoid(z2).ravel()                    # (n,) probabilities
    return p, (X, z1, a1)                      # keep the pieces for the backward pass

params = init_params(2, 16, np.random.default_rng(42))
for name, value in params.items():
    print(f"{name}: shape {value.shape}")

p, cache = forward(params, X_train[:5])
print("first five probabilities:", p.round(3))
    W1: shape (2, 16)
b1: shape (16,)
W2: shape (16, 1)
b2: shape (1,)
first five probabilities: [0.705 0.587 0.59  0.596 0.413]
    Random weights, random opinions. Point at the two deliberate details: random (not zero) starts break the tie between units; the spread sqrt(2 / n_in) is He initialization for ReLU.
  4. How wrong is it? The loss (2m). "Cross-entropy punishes confident mistakes hardest. Remember 0.693: a binary classifier whose loss sits there has learned nothing." 
    def bce_loss(p, y, eps=1e-12):
    p = np.clip(p, eps, 1 - eps)               # avoid log(0)
    return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))

p, cache = forward(params, X_train)
print(f"untrained network loss: {bce_loss(p, y_train):.4f}")
print(f"always guessing 0.5:    {bce_loss(np.full(len(y_train), 0.5), y_train):.4f}")
    untrained network loss: 0.6714
always guessing 0.5:    0.6931
  5. Walking downhill (2m). "One parameter, a valley at 3, and one rule: step against the slope." Ask the room to predict w after step 1 (0.6). 
    w = 0.0
learning_rate = 0.1
for step in range(1, 26):
    grad = 2 * (w - 3)                 # slope of (w - 3)**2 at the current w
    w = w - learning_rate * grad       # step downhill
    if step in (1, 2, 3, 5, 10, 25):
        print(f"step {step:2d}  w = {w:.4f}  loss = {(w - 3) ** 2:.6f}")
    step  1  w = 0.6000  loss = 5.760000
step  2  w = 1.0800  loss = 3.686400
step  3  w = 1.4640  loss = 2.359296
step  5  w = 2.0170  loss = 0.966368
step 10  w = 2.6779  loss = 0.103763
step 25  w = 2.9887  loss = 0.000128
    Big steps where it is steep, small ones near the bottom. Nobody told the loop where the valley is.
  6. Backpropagation: shapes first (3m). "The output error is simply p minus y. Then it is matrix multiplication with the shapes reversed, and ReLU lets the error through only where it was active." Read the comments aloud; do not derive calculus. 
    def backward(params, cache, p, y):
    X, z1, a1 = cache
    n = len(y)
    dz2 = ((p - y) / n).reshape(-1, 1)        # (n, 1): slope of the loss w.r.t. z2
    grads = {"W2": a1.T @ dz2,                 # (16, n) @ (n, 1) -> (16, 1)
             "b2": dz2.sum(axis=0)}
    da1 = dz2 @ params["W2"].T                 # (n, 1) @ (1, 16) -> (n, 16): error sent back
    dz1 = da1 * (z1 > 0)                       # ReLU passes the error only where it was active
    grads["W1"] = X.T @ dz1                    # (2, n) @ (n, 16) -> (2, 16)
    grads["b1"] = dz1.sum(axis=0)
    return grads

grads = backward(params, cache, p, y_train)
for name, g in grads.items():
    print(f"{name}: gradient shape {g.shape}  (parameter shape {params[name].shape})")
    W2: gradient shape (16, 1)  (parameter shape (16, 1))
b2: gradient shape (1,)  (parameter shape (1,))
W1: gradient shape (2, 16)  (parameter shape (2, 16))
b1: gradient shape (16,)  (parameter shape (16,))
    First sanity check for any backward pass: every gradient has its parameter's shape.
  7. Check the calculus with a nudge (2m). "Hand-derived gradients are easy to get subtly wrong, and a wrong gradient does not crash. So nudge one weight and measure." 
    eps = 1e-6
i, j = 0, 3                                     # check one weight: W1[0, 3]
original = params["W1"][i, j]

params["W1"][i, j] = original + eps
loss_plus = bce_loss(forward(params, X_train)[0], y_train)
params["W1"][i, j] = original - eps
loss_minus = bce_loss(forward(params, X_train)[0], y_train)
params["W1"][i, j] = original                   # put it back

numeric = (loss_plus - loss_minus) / (2 * eps)
print(f"backprop gradient: {grads['W1'][i, j]:.8f}")
print(f"numeric gradient:  {numeric:.8f}")
    backprop gradient: -0.02341771
numeric gradient:  -0.02341771
    Ask: "Why not always do this?" (two forward passes per parameter; backprop gets all of them for about one).
  8. Train: forward, loss, backward, update (3m). "These four lines are the engine of every network in Module 10." Point at each numbered comment as it runs (it takes under a second). 
    def train(params, X, y, learning_rate=0.5, epochs=2000, report_every=400):
    history = []
    for epoch in range(1, epochs + 1):
        p, cache = forward(params, X)                  # 1. forward
        history.append(bce_loss(p, y))                 # 2. loss
        grads = backward(params, cache, p, y)          # 3. backward
        for name in params:                            # 4. update every parameter
            params[name] -= learning_rate * grads[name]
        if report_every and epoch % report_every == 0:
            print(f"epoch {epoch:4d}  loss {history[-1]:.4f}")
    return history

params = init_params(2, 16, np.random.default_rng(42))

  9. Autograd in one line (1m). "Now the payoff: PyTorch records the operations and replays them backwards for you." 
    import torch

w = torch.tensor(0.0, requires_grad=True)   # "track every operation on w"
loss = (w - 3) ** 2
loss.backward()                              # chain rule, automatically
print(w.grad)
    tensor(-6.)
    -6 is exactly the slope the walking-downhill loop used at w = 0.
  10. Same network, same gradients (2m). "If my hand-written backward is right, autograd must agree." 
    import torch.nn.functional as F

params = init_params(2, 16, np.random.default_rng(42))           # a fresh copy of the start weights
t_params = {name: torch.tensor(value, requires_grad=True) for name, value in params.items()}
X_train_t = torch.tensor(X_train)                                  # float64, like NumPy
y_train_t = torch.tensor(y_train, dtype=torch.float64)

def forward_torch(tp, X):
    a1 = torch.relu(X @ tp["W1"] + tp["b1"])
    return torch.sigmoid(a1 @ tp["W2"] + tp["b2"]).squeeze(1)

loss_t = F.binary_cross_entropy(forward_torch(t_params, X_train_t), y_train_t)
loss_t.backward()

grads = backward(params, cache, p, y_train)
print(f"loss: NumPy {bce_loss(p, y_train):.6f}   PyTorch {loss_t.item():.6f}")

    gap = np.abs(t_params[name].grad.numpy() - grads[name]).max()

  11. The loop with autograd, and the trap (3m). "Only step 3 changes. Two new lines: the update runs under no_grad, and the gradient is reset." Then run the trap: no reset. 
    t_params = {name: torch.tensor(value, requires_grad=True)
            for name, value in init_params(2, 16, np.random.default_rng(42)).items()}

for epoch in range(1, 2001):
    loss = F.binary_cross_entropy(forward_torch(t_params, X_train_t), y_train_t)   # 1-2. forward, loss
    loss.backward()                                                                # 3. backward

            tensor -= 0.5 * tensor.grad

    if epoch % 400 == 0:

  8. The two functions you will reuse (2m). Type train_one_epoch and evaluate and narrate the four numbered lines, model.train() / model.eval() and torch.no_grad(). Nothing prints. 
    from sklearn.metrics import roc_auc_score

def train_one_epoch(model, loader, loss_fn, optimizer):
    model.train()                                  # training mode (matters for dropout)
    total_loss, n = 0.0, 0
    for xb, yb in loader:
        optimizer.zero_grad()                      # 1. reset gradients
        loss = loss_fn(model(xb), yb)              # 2. forward pass and loss
        loss.backward()                            # 3. backward pass
        optimizer.step()                           # 4. update
        total_loss += loss.item() * len(yb)
        n += len(yb)
    return total_loss / n                          # average loss over the epoch

def evaluate(model, X, y, loss_fn):
    model.eval()                                   # prediction mode
    with torch.no_grad():                          # no gradient bookkeeping needed
        logits = model(X)
        loss = loss_fn(logits, y).item()
        auc = roc_auc_score(y.squeeze(1).numpy(), logits.squeeze(1).numpy())
    return loss, auc

  10. Early stopping (3m). "Keep the best weights; stop after five epochs without improvement; roll back." 
    import copy

def fit(model, train_loader, X_val, y_val, loss_fn, optimizer, max_epochs=50, patience=5):
    best_loss, best_state, best_epoch = float("inf"), None, 0
    for epoch in range(1, max_epochs + 1):
        train_one_epoch(model, train_loader, loss_fn, optimizer)
        val_loss, val_auc = evaluate(model, X_val, y_val, loss_fn)
        if val_loss < best_loss:
            best_loss, best_epoch = val_loss, epoch
            best_state = copy.deepcopy(model.state_dict())
        elif epoch - best_epoch >= patience:
            break
    model.load_state_dict(best_state)              # roll back to the best epoch
    print(f"stopped after epoch {epoch}; best epoch {best_epoch}, validation loss {best_loss:.4f}")
    return model

Closing

Exit ticket (3 questions, no notes, 4 minutes)

Put the three questions on the slide. Learners answer in the workbook's Exit Ticket box or on a sticky note. Sort the notes before Session 8: the pile for question 2 (logits and probabilities) tells you how much of the Session 8 warm-up goes to the loss/last-layer pairing, which 10.3 relies on with ten classes.

  1. Write the four steps of the training loop and the PyTorch line for each. Answer: reset gradients optimizer.zero_grad(); forward and loss loss = loss_fn(model(xb), yb); backward loss.backward(); update optimizer.step().
  2. Your churn model returns logits. How do you get a churn probability for a report, and why is there no sigmoid inside the model? Answer: torch.sigmoid(model(X)) in eval mode under no_grad(); BCEWithLogitsLoss applies the sigmoid itself (in a numerically safe way), and a second sigmoid would squash the outputs and stall training.
  3. On churn the network's test AUC is 0.846 and gradient boosting's 0.850. Which do you recommend, and why? Answer: gradient boosting: the gap is within the wobble of one test set, and boosting needed no scaling, architecture, learning rate, dropout or early stopping.
