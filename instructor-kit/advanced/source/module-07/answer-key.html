Warm-up

Retrieval on Lessons 9.2 and 9.3. Accept answers in the learner's own words.

W1
What does this print? (Lesson 9.2)
from sklearn.datasets import make_classification
from sklearn.discriminant_analysis import LinearDiscriminantAnalysis
X, y = make_classification(n_samples=300, n_features=6, n_informative=4, n_classes=3, random_state=42)
print(LinearDiscriminantAnalysis().fit(X, y).transform(X).shape)
(300, 2): LDA gives at most (classes - 1) axes, so 3 classes give 2 columns, whatever the number of features.
W2
PCA and LDA both flatten data onto a few directions. What is the one big difference in how they choose them? (9.2)
PCA looks only at X and keeps the directions of largest total spread; LDA uses the labels y and keeps the directions where the class means are far apart relative to the spread inside each class.
W3
A colleague fits LDA on all 200 rows of 500 random features, then cross-validates a classifier on the LDA output and gets 0.99. What happened? (9.2)
Leakage: LDA saw the labels of the rows later used as test folds. With 500 features it can separate any labels. Inside a pipeline, refitted per fold, the score falls to chance.
W4
On a t-SNE map of customers, one island is twice the size of the others and far away from them. What may you conclude from the size and the gap? (9.3)
Very little: t-SNE keeps neighborhoods, not sizes or distances between groups. Check spread and separation in the original data (silhouette, profiles).
W5
Next month 200 new customers arrive and you want to place them on this month's 2-D map. t-SNE or UMAP, and why? (9.3)
UMAP: a fitted UMAP has transform for new rows. t-SNE only has fit_transform; it positions the rows it was given and learns no function.

10.1 · Neural Networks from Scratch: self-check

Q1
A hidden layer takes 10 inputs and has 16 units. How many parameters (weights and biases) does it have?
A) 160
B) 176
C) 26
D) 170
Why: One weight per input per unit (10 × 16 = 160) plus one bias per unit (16): 176. The lesson's churn network adds the output layer's 16 weights and 1 bias for 193 in all.
A is wrong: That forgets the 16 biases.
C is wrong: Adding inputs and units counts nothing real.
D is wrong: Ten biases would be one per input; biases belong to units.
Q2
What does this print?
import numpy as np
x = np.array([1.0, 2.0])
w = np.array([0.5, -1.0])
z = x @ w + 1.0
print(z, max(0.0, z), round(1 / (1 + np.exp(-z)), 3))
-0.5 0.0 0.378
Why: z = 1.0 × 0.5 + 2.0 × (-1.0) + 1.0 = -0.5. ReLU of a negative number is 0.0; sigmoid(-0.5) = 0.378. A ReLU unit with a negative z for a row passes no gradient back for that row.
Q3
After 2,000 epochs your network's training loss is still 0.6931 and its test accuracy is 0.500. Which bug is the most likely?
A) The learning rate is far too large
B) The test set is too small
C) Every weight was initialized to zero
D) The network has too many hidden units
Why: 0.6931 is log(2), the coin-flip loss, and it did not move at all. With all-zero weights every ReLU unit outputs 0 and passes no gradient, so only the output bias can learn (the lesson's Mistake 3).
A is wrong: A wild learning rate makes the loss jump around or explode, not sit perfectly still at 0.6931.
B is wrong: The training loss itself is stuck; the test set has nothing to do with it.
D is wrong: Extra units add capacity; they do not freeze learning.
Q4
What does this print?
w = 0.0
for step in range(2):
    w = w - 0.25 * 2 * (w - 1)        # gradient descent on (w - 1) ** 2
print(w)
0.75
Why: The slope of (w - 1)² is 2(w - 1). Step 1: w = 0 - 0.25 × (-2) = 0.5. Step 2: w = 0.5 - 0.25 × (-1) = 0.75. Each step halves the distance to the valley at 1.
Q5
Why is ReLU the default activation for hidden layers rather than the sigmoid?
A) Its slope is 1 wherever it is active, so gradients pass back through many layers undiminished
B) It outputs probabilities between 0 and 1
C) It keeps the network linear, which trains faster
D) It has no weights of its own, unlike the sigmoid
Why: Learning is driven by slopes. The sigmoid's flat ends have slopes near 0, so stacked sigmoid layers pass back ever smaller gradients (the vanishing gradient problem). ReLU's slope is exactly 1 where it is on.
B is wrong: That describes the sigmoid, which is why it sits at the OUTPUT of a yes-or-no classifier.
C is wrong: ReLU is nonlinear (its bend is the point); without a nonlinearity the layers collapse into one.
D is wrong: Neither activation has weights; that is not the difference.
Q6
What happens when this runs?
import torch
w = torch.tensor([1.0, 2.0], requires_grad=True)
out = (w * 3).sum()
out.numpy()
A) It prints 9.0
B) It prints [3. 6.]
C) TypeError: a sum cannot be converted to NumPy
D) RuntimeError: Can't call numpy() on Tensor that requires grad
Why: out was computed from a tensor with requires_grad=True, so it carries its gradient history and NumPy arrays cannot. Use out.detach().numpy(), or compute it inside with torch.no_grad(): (the lesson's Mistake 6).
A is wrong: That would be the value (3 + 6) if the conversion were allowed.
B is wrong: The sum is a single number; and the conversion is refused anyway.
C is wrong: The message is a RuntimeError about gradients, not a TypeError.

10.1 · Neural Networks from Scratch: predict, then run

P1
Predict the output, then run it.
import numpy as np
X = np.ones((5, 3))
W = np.full((3, 2), 2.0)
print((X @ W).shape, (X @ W)[0])
(5, 2) [6. 6.]
Why: Inner dimensions (3 and 3) match and disappear: (5, 2). Each entry is three products of 1 × 2, so 6.0.
P2
Predict the output, then run it.
import torch
w = torch.tensor(1.5, requires_grad=True)
loss = (2 * w) ** 2
loss.backward()
print(w.grad)
tensor(12.)
Why: loss = 4w², whose slope is 8w; at w = 1.5 that is 12. One call of backward, so no accumulation.

10.2 · PyTorch Fundamentals: self-check

Q7
What does this print?
from torch import nn
layer = nn.Linear(4, 3)
print(layer.weight.shape, sum(p.numel() for p in layer.parameters()))
torch.Size([3, 4]) 15
Why: nn.Linear(4, 3) stores its weight as (outputs, inputs) = (3, 4), the transpose of Lesson 10.1's convention, and computes x @ weight.T + bias. Parameters: 12 weights + 3 biases = 15.
Q8
What happens when this runs?
import torch
from torch import nn
logits = torch.zeros(8, 1)
targets = torch.ones(8)
nn.BCEWithLogitsLoss()(logits, targets)
A) ValueError: Target size (torch.Size([8])) must be the same as input size (torch.Size([8, 1]))
B) It returns a loss of about 0.6931
C) RuntimeError: expected integer (Long) targets
D) It returns a loss of 0.0
Why: BCEWithLogitsLoss compares outputs and targets element by element and insists on identical shapes. The fix is targets.unsqueeze(1), as the lesson's to_tensors does. (With matching shapes the loss of logit 0 would be 0.6931.)
B is wrong: That is what it WOULD return with targets of shape (8, 1).
C is wrong: Integer class targets belong to CrossEntropyLoss, not the binary loss.
D is wrong: A logit of 0 is a probability of 0.5, never a perfect answer.
Q9
Which statement about model.eval() and torch.no_grad() is true?
A) They are two names for the same switch
B) torch.no_grad() switches dropout off; model.eval() stops gradient tracking
C) model.eval() changes how layers such as dropout behave; torch.no_grad() stops gradient tracking; prediction code uses both
D) model.eval() is only needed when the model runs on a GPU
Why: They are independent. eval() switches layers that behave differently in training (dropout, batch normalization); no_grad() stops autograd's bookkeeping. The lesson's Mistake 4 shows a dropout model giving three different answers under no_grad() until eval() is called.
A is wrong: One changes layer behavior, the other gradient tracking.
B is wrong: That is exactly backwards.
D is wrong: Devices have nothing to do with it.
Q10
What does this print?
import torch
from torch.utils.data import TensorDataset, DataLoader
data = TensorDataset(torch.zeros(1000, 5), torch.zeros(1000, 1))
loader = DataLoader(data, batch_size=64, shuffle=True)
sizes = [len(xb) for xb, yb in loader]
print(len(loader), sizes[-1])
16 40
Why: 1,000 rows in batches of 64: 15 full batches (960 rows) and one last batch of 40, so 16 batches per epoch. The lesson's 3,600 fitting rows give 57 batches, the last with 16 rows.
Q11
In the lesson's early-stopping function, why does the best state go through copy.deepcopy(model.state_dict())?
A) torch.save cannot save a state_dict that was not copied
B) state_dict() returns references to the live tensors, which later epochs would keep changing
C) deepcopy switches the model to evaluation mode
D) It converts the weights to float64 so nothing is lost
Why: Without the copy, the "best" snapshot would silently follow the model as training continues, and loading it at the end would restore the LAST epoch, not the best one.
A is wrong: torch.save(model.state_dict(), ...) works directly, as the lesson's saving section shows.
C is wrong: Copying changes no mode.
D is wrong: The copy keeps the dtype (float32).
Q12
You predict loyalty_tier (Basic, Silver, Gold) with nn.CrossEntropyLoss. What must the targets be?
A) float32 values 0.0 to 2.0, shape (n, 1)
B) the strings Basic, Silver and Gold
C) float32 values 0.0 or 1.0, shape (n, 1)
D) integer class indices 0, 1, 2 (torch.long), shape (n,)
Why: CrossEntropyLoss takes k logits per row and one integer class index per row; it applies log-softmax itself. The lesson's Exercise 3 maps the tiers to 0, 1, 2 with dtype torch.long.
A is wrong: Float targets of shape (n, 1) are the binary loss's format.
B is wrong: Tensors hold numbers; map the labels to integers first.
C is wrong: That is the binary (churn) target format.

10.2 · PyTorch Fundamentals: predict, then run

P3
Predict the output, then run it.
import torch
print(torch.tensor([1, 2, 3]).dtype, torch.tensor([1.0, 2.0]).dtype)
torch.int64 torch.float32
Why: PyTorch's default for Python integers is int64 and for Python floats float32 (unlike NumPy's float64).
P4
Predict the output, then run it.
from torch import nn
net = nn.Sequential(nn.Linear(3, 5), nn.ReLU(), nn.Linear(5, 2))
print(sum(p.numel() for p in net.parameters()))
32
Why: First layer 3 × 5 + 5 = 20, second 5 × 2 + 2 = 12; ReLU has no parameters: 32.

The Lesson Pages' Own Quick Quizzes

Lesson 10.1 · Neural Networks from Scratch
  1. B (32, 16): the inner dimensions (10 and 10) match and disappear; one row per sample, one column per unit.
  2. A Only a straight line, like logistic regression: matrix products in a row collapse into one.
  3. C tensor(6.): .grad accumulates; three backward calls of slope 2 give 6.
  4. B The learning rate is too large: a loss that jumps and ends in nan overshoots the valley.
  5. A Backpropagation gets all gradients in one backward sweep; the numeric check needs two forward passes per parameter.
Lesson 10.2 · PyTorch Fundamentals
  1. B torch.float64: from_numpy keeps NumPy's dtype (and shares its memory).
  2. C optimizer.zero_grad(), forward and loss, loss.backward(), optimizer.step().
  3. A Apply torch.sigmoid to the model's outputs (in eval mode, under no_grad()).
  4. B The model is still in training mode; call model.eval(): no_grad() does not switch dropout off.
  5. C The test AUC, computed once after training: the validation set chose the epoch.

Exit Ticket

  1. The loop: optimizer.zero_grad() (reset), loss = loss_fn(model(xb), yb) (forward and loss), loss.backward() (gradients), optimizer.step() (update). Accept any wording that keeps the order and names the four calls.
  2. Probabilities: torch.sigmoid(model(X)) with model.eval() and torch.no_grad(). BCEWithLogitsLoss applies the sigmoid internally, in a numerically safe way; a second sigmoid in the model squashes outputs into 0.5 to 0.73 as seen by the loss, which can then never fall below about 0.31 for a sure churner (demo Step 12).
  3. 0.846 vs 0.850: gradient boosting. The gap is within the wobble of one test set (a tie), and boosting needed no scaling, architecture, learning rate, dropout or early stopping. A full answer adds that networks earn their keep on images, sequences and text.

Common Wrong Answers and What They Reveal

  • Q1 A (160). Forgets biases. Count them out loud: one per unit.
  • Q3 A (learning rate too large). Has the loss shapes mixed up. A wild learning rate moves the loss a lot; a frozen 0.6931 means nothing can move.
  • Q5 B ("it outputs probabilities"). Confuses the hidden and output roles. Draw the network: ReLU inside, sigmoid at the end.
  • Q8 B ("0.6931"). Read the code as it would run with matching shapes. Ask them to print both shapes first, always.
  • Q9 A or B. The most common confusion of the session. Replay demo Step 12: three different numbers in train mode under no_grad().
  • Q12 A or C. Carried the binary format over to three classes. The lesson's Exercise 3 is the fix: integers, torch.long, shape (n,).
  • Exit ticket 3: "the network, it is more modern" or "the network, 0.846 is good". The habit this course builds is comparing against a strong baseline and weighing the cost of every choice. Point back to the project's Step 5 text.
