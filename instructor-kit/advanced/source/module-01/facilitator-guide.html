Session 1: Interpreting Models and SHAP

How to teach the first session of Advanced Machine Learning. Welcome a room in which some learners finished Machine Learning Foundations and others bring equivalent experience; recap the conventions this kit builds on; prove that every machine has the full environment, PyTorch and the image data included; then open the churn model up: odds ratios, the impurity trap, permutation importance and partial dependence (7.1), and SHAP values that split one customer's prediction into exact shares (7.2).

How to Use This Guide

  • Same rhythm for both lessons: frame (the goal and one mental model) → live demo (you type, they type along) → guided lab (a kit lab, new practice on the lesson's skills) → start the lesson's own project. The lesson exercises, quiz and journal are homework.
  • Type, do not paste. Ask for a prediction before every run that prints a number, and read errors from the last line up, out loud.
  • The lessons are the reference. Labs live in labs/module-01/: _starter.py files are handouts, _solution.py files are yours.
  • Session 1 of Advanced Machine Learning opens with 30 minutes of welcome, environment check and a Foundations refresher instead of the usual 10-minute warm-up. This kit is sold separately: some learners finished Machine Learning Foundations last week, others learned scikit-learn at work. The opening makes sure everyone shares the same conventions before Module 7 builds on them.
  • Teal blocks are hands-on, amber blocks are watch-outs. Lesson codes (7.1, 7.2) match the course site.
The #1 risk of Session 1: a room with two different backgrounds

Learners who did Foundations know Pinecrest's churn table, the canonical split, Pipeline([("prep", ...), ("model", ...)]) and the $15 / $60 campaign economics by heart. Learners who come "with equivalent experience" may know scikit-learn well and still have never seen this data, these names or these numbers. Module 7 quotes all of them without explanation. Before: send the setup guide and the one-page "What Kit B assumes" table (it is in the workbook's Start Here page) a week ahead, with check_environment.py. In the room: the refresher is six predict-the-output questions, one per convention; the tally tells you who needs a partner. After: diagnostic_starter.py is homework for anyone who missed two or more. The second risk is the image data: Fashion-MNIST, EuroSAT and two pretrained networks (about 175 MB) are needed from Session 5 on. Lesson Plans

7.1

Interpreting Models

60 min
Objectives (from the lesson page)
  • Read the coefficients of a scaled logistic regression as odds ratios, and say when they mislead
  • Compute permutation importance on the test set with permutation_importance and explain why impurity-based importance can fool you
  • Draw partial dependence and ICE plots with PartialDependenceDisplay and read thresholds, curves and interactions from them
  • State what feature importance does and does not mean: it describes the model, not the causes of churn
Timing in the room
10mFrame: three people, three questions (what drives churn, is it using anything it should not, why this person); the recipe, the taste test, the dial
25mLive demo: two models, coefficients and odds ratios, natural units, the noise trap, permutation importance, PDP numbers, an interaction, two errors
15mGuided lab: fraud_drivers_starter.py

Mental model to say

"Before the retention team acts on a churn model, three people ask questions. The marketing manager: what drives churn? The data scientist next to you: is it using anything it should not? An agent looking at one flagged customer: why this person? The first two are about the whole model, global explanations; the third is about one prediction, a local explanation. Today: all three, the first two this hour."

Then the picture, drawn as three boxes on the board: "Think of the model as a dish. Coefficients are reading the recipe: only possible when the recipe is short and written down, as in a linear model. Permutation importance is a taste test: swap one ingredient for a random one and see how much worse the dish gets; it works on any dish, even from a kitchen you cannot see into. Partial dependence is a dial: turn one ingredient up and down, keep everything else, and watch the taste change."

Then the one rule for the whole module, written under the boxes: these tools describe the model, not the world. "The model relies on recency" is a measurement. "Recency causes churn" needs an experiment.

Live demo (you type, they follow)

New notebook, lesson_7_1, in pinecrest-ml. The lesson's charts stay on the lesson page; you type the code that produces the numbers behind them, and ask for a prediction before every run.

  1. Two models to explain (3m). "Before we explain anything, we check it is worth explaining. Same 11 numeric features for both, the canonical split, a baseline." Narrate .astype(float): partial dependence refuses integer columns (Step 9 shows the error). 
    import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.dummy import DummyClassifier
from sklearn.metrics import roc_auc_score

customers = pd.read_csv("data/customers_churn.csv")
features = ["tenure_months", "orders_12m", "spend_12m", "avg_order_value", "days_since_last_order",
            "returns_12m", "return_rate", "support_tickets_12m", "discount_share", "app_user",
            "email_opens_90d"]

X = customers[features].astype(float)
y = customers["churned"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, stratify=y, random_state=42)

baseline = DummyClassifier().fit(X_train, y_train)
logreg = make_pipeline(SimpleImputer(strategy="median"), StandardScaler(), LogisticRegression())
logreg.fit(X_train, y_train)
hgb = HistGradientBoostingClassifier(random_state=42).fit(X_train, y_train)

for name, model in [("baseline", baseline), ("logistic regression", logreg), ("gradient boosting", hgb)]:
    auc = roc_auc_score(y_test, model.predict_proba(X_test)[:, 1])
    print(f"{name:20s} test ROC AUC {auc:.3f}")
    baseline             test ROC AUC 0.500
logistic regression  test ROC AUC 0.828
gradient boosting    test ROC AUC 0.865
    Write 0.500 / 0.828 / 0.865 on the board. Ask: "Where will the 0.04 gap between the two models come from?" Park the answers; Step 6 settles it.

  4. The built-in importance trap (4m). "Forests come with feature_importances_. Free, fast, tempting. Watch what it does with a column of pure noise."

Three mistakes to expect, and how to coach each
  • Reading importance as a lever. "App use is a top-5 driver, so the app campaign will cut churn." Coach with a question: "Would pushing a disengaged customer to install the app make them engaged? What would you need to know that?" The answer is a randomized test. Make them rephrase as "customers who use the app are predicted to churn less".
  • Importance on the training rows, or impurity importance as the answer. No error, bigger and more confident numbers. Coach: "Which rows did you shuffle? Would the noise column survive this?" In the lab, ask them to add a random column if they doubt a ranking.
  • Partial dependence read off the edges. The PDP sets every customer's spend to $2,500, including customers with one $60 order: a customer who cannot exist. Coach: "Check the curve against a groupby of the real rate" (Lab A's TODO 5 does exactly that for the hour).

Checks for understanding

Ask these out loud during the demo and the lab:

  • What does np.exp of a scaled logistic-regression coefficient give you? Answer: an odds ratio per standard deviation of that feature, other features held fixed.
  • Why permutation importance on the TEST set? Answer: on training rows the model's memorized noise looks important; on new rows it does not help, so the test numbers are the honest ones.

Objectives (from the lesson page)

Mental model to say

"A team of three wins a bonus. How much did each person contribute? 'What would the team have earned without Ana?' is unfair when people work together, because the answer depends on who else is in the room. Lloyd Shapley's answer, in 1953: imagine them arriving one at a time, in every possible order; each time someone arrives, credit them with how much the result went up; average each person's credit over all the orders."

Then the translation, on the board: the players are the features; the bonus is how far this customer's prediction is from the model's average prediction (the base value). Under it: base value + all shares = this prediction, exactly. And the warning, boxed: for a boosting classifier, all of it is in log-odds; squash only the end points with expit.

  1. Shapley values by hand (4m). "A toy risk score with an interaction: a long silence is worse without the app. Let the features arrive in every order and credit each with what its arrival adds." Ask for a prediction first: how will the 0.10 interaction bonus be split? 
    import itertools

def toy_risk(days, disc, app):
    risk = 0.10
    if days > 150:
        risk += 0.30
    if disc > 0.35:
        risk += 0.15
    if days > 150 and app == 0:
        risk += 0.10
    return risk

reference = {"days": 40, "disc": 0.15, "app": 1}   # a typical customer
customer = {"days": 240, "disc": 0.45, "app": 0}   # the customer to explain
names = list(customer)

def value(present):
    """Risk when the features in `present` take the customer's values and the rest the reference's."""
    return toy_risk(**{n: customer[n] if n in present else reference[n] for n in names})

shares = dict.fromkeys(names, 0.0)
orders = list(itertools.permutations(names))
for order in orders:
    present = set()
    for name in order:
        before = value(present)
        present.add(name)
        shares[name] += value(present) - before
shares = {n: round(s / len(orders), 3) for n, s in shares.items()}

print("orders tried:", len(orders))
print("reference risk:", value(set()), " customer risk:", value(set(names)))
print("Shapley values:", shares, " sum:", round(sum(shares.values()), 3))
    orders tried: 6
reference risk: 0.1  customer risk: 0.65
Shapley values: {'days': 0.35, 'disc': 0.15, 'app': 0.05}  sum: 0.55
    Days gets 0.30 + 0.05, app gets 0.05: whichever of the two arrives second collects the 0.10, and each arrives second in half the orders. The shares add up to the gap, 0.55, exactly.

Three mistakes to expect, and how to coach each
  • Adding log-odds to a probability. "The base is 16% and discounts add 1.83, so ..." Coach: "What units is the base value in? What does expit(-2.95) give?" Then the rule: add in log-odds, squash at the end. Lab 7.2 A's base value (-5.84 log-odds, 0.0029) is the same trap on fraud.
  • Handing a Pipeline to TreeExplainer, or a forest's 3-D values to a plot. Two errors with clear last lines. Coach: "Print .values.shape before you plot a new model's explanation." A forest gives (rows, features, 2): pick class 1.
  • Reading a top SHAP feature as the cause. An agent offers fewer discounts because discount_share got +1.83. Coach: "flagged because", never "leaving because"; reasons start a conversation, they do not prescribe a treatment.
