7.1 · Interpreting Models: self-check

Q1
In a scaled logistic regression, days_since_last_order has a coefficient of 0.89. Which sentence is right?
A) One more day without an order raises the churn probability by 0.89
B) The model is 89% sure that recency causes churn
C) One more standard deviation of days without an order multiplies the odds of churn by about 2.4, other features held fixed
D) One more standard deviation of days without an order raises the churn probability by 2.4 points
Why: Coefficients of a scaled logistic regression are changes in log-odds per standard deviation; e^0.89 is about 2.43, an odds ratio. Lesson 7.1 then divides by the scaler's standard deviation (87.2 days) to speak per 30 days: x1.36.
A is wrong: Coefficients act on the log-odds, not the probability, and per standard deviation, not per day.
B is wrong: A coefficient measures association inside the model; it is not a probability and not a causal claim.
D is wrong: Odds ratios multiply odds; they do not add percentage points to a probability.
Q2
What does this print?
import numpy as np
import pandas as pd
coefs = pd.Series([0.40, -0.69], index=["support_tickets_12m", "app_user"])
print(np.exp(coefs).round(2).tolist())
[1.49, 0.5]
Why: np.exp turns each coefficient into an odds ratio: e^0.40 is about 1.49 (each standard deviation more tickets multiplies the odds by 1.5), e^-0.69 is about 0.50 (the odds halve). A coefficient of 0 would give 1.0, no change.
Q3
You add a column of pure random noise to the churn data. The forest's feature_importances_ ranks it sixth, above return_rate and app_user; permutation importance on the test set gives it 0.005. What follows?
A) The noise column must hold a little real churn signal
B) Impurity importance cannot be trusted for the ranking: it is measured on training data and rewards columns the trees can memorize with
C) app_user is useless and can be dropped
D) Permutation importance is broken for random forests
Why: Impurity importance (MDI) is computed during training and favors many-valued columns that offer split points to overfit with. Permutation importance on held-out data puts the noise near zero, where it belongs. A noise column is a cheap sanity check for any importance you plan to report.
A is wrong: The noise was drawn independently of everything; it cannot carry churn signal.
C is wrong: app_user matters on test data (0.009 for the forest, 0.019 for boosting); impurity ranks it low because a 0/1 column offers only one split.
D is wrong: It is the method that got it right here.
Q4
In Lab 7.1 A, shuffling hour costs the fraud model 0.074 of average precision but nothing (-0.005) of ROC AUC. What is the best reading?
A) The hour column is broken and should be removed
B) Average precision is a buggy metric for permutation importance
C) The model does not use the hour at all
D) Importance depends on the metric: the hour lifts a few night frauds to the very top of the list, which average precision rewards and the whole-ranking AUC hardly notices
Why: Permutation importance always answers "how much does THIS score depend on the column?". The review team works from the top of the list, so the metric that matches their decision (average precision) is the one to report.
A is wrong: The column carries a real signal: partial dependence shows night payments at 0.017 against 0.007 by day.
B is wrong: Average precision is a standard metric for rare positives (Lesson 1.4).
C is wrong: If the model ignored it, no metric would drop.

What does this print?
import pandas as pd
from sklearn.linear_model import LinearRegression
from sklearn.inspection import partial_dependence
X = pd.DataFrame({"a": [0.0, 1.0, 2.0, 3.0], "b": [0.0, 0.0, 4.0, 4.0]})
model = LinearRegression().fit(X, X["a"] + X["b"])       # learns y = a + b exactly
res = partial_dependence(model, X, ["a"], method="brute", custom_values={"a": [0.0, 10.0]})
print(res["average"][0].round(2))
[ 2. 12.]
Why: Partial dependence sets column a to each grid value for EVERY row, predicts and averages. The model is y = a + b, and the average of b over the four rows is 2, so the averages are 0 + 2 and 10 + 2. Nothing is retrained and no real customer needs to have a = 10.
Q6
Which sentence belongs in the churn-drivers briefing?

B) Long gaps since the last order cause churn, so emailing customers at three months will cut churn

P1
Predict the output, then run it.
import numpy as np
print(round(np.exp(0.69), 2), round(np.exp(-0.69), 2), np.exp(0.0))
1.99 0.5 1.0
Why: np.exp(0.69) is about 2 (the odds double), np.exp(-0.69) about 0.5 (they halve), np.exp(0) exactly 1 (no change). This is the odds-ratio rule of thumb from Lesson 7.1.
P2
Predict the output, then run it.
import numpy as np
from sklearn.tree import DecisionTreeClassifier
from sklearn.inspection import permutation_importance
rng = np.random.default_rng(0)
X = rng.normal(size=(200, 2))
y = (X[:, 0] > 0).astype(int)                 # only column 0 matters
tree = DecisionTreeClassifier(max_depth=1, random_state=0).fit(X, y)
r = permutation_importance(tree, X, y, n_repeats=5, random_state=0)
print(r.importances_mean.round(2))
[0.49 0. ]
Why: The tree splits on column 0 only, so shuffling column 0 destroys about half its accuracy (it falls to a coin toss on a balanced target), and shuffling column 1 changes nothing: exactly 0. Permutation importance measures what the model uses.

7.2 · SHAP Values: self-check

Q7
Lab 7.2 B's fraud rule never looks at gift_card. Explained against a typical payment, what Shapley value does gift_card get, and why?
A) A quarter of the total, because the four features share the gap equally
B) 0, because adding it never changes the score in any arrival order
C) A negative value, to balance the interaction bonus
D) It cannot be computed: Shapley values need every feature to matter
Why: A feature's Shapley value is its average contribution over all arrival orders. If its arrival never changes the score, every contribution is 0, so its share is 0 (the "null player" rule). The lab prints gift_card: 0.0.
A is wrong: Equal splits only happen for features that play identical roles; the interaction bonus is split 0.15 / 0.15 between night and new device for that reason.
C is wrong: Shares are not invented to balance anything; they add up to the gap exactly as computed.
D is wrong: Unused features are allowed and simply get 0.
Q8
What does this print?
import numpy as np
from scipy.special import expit
base = -2.0
shares = np.array([1.5, 0.7, -0.2])
print(round(base + shares.sum(), 2), round(expit(base + shares.sum()), 3))
0.0 0.5
Why: SHAP values for a boosting classifier are log-odds: base -2.0 plus 1.5 + 0.7 - 0.2 gives 0.0 log-odds, and the logistic function expit turns 0 log-odds into a probability of exactly 0.5.
Q9
For the fraud model, device_new tops the mean |SHAP| ranking (0.247) while velocity_24h tops permutation importance. How can both be right?
A) One of the two calculations has a bug
B) SHAP ranks only the riskiest payments
C) Mean |SHAP| measures how much a feature moves predictions; permutation importance measures how much the score depends on it, and the two need not agree
D) Permutation importance is always more correct
Why: A feature can move many predictions a lot (a new device shifts almost every payment's log-odds) and still add less ranking skill than another (velocity separates the frauds at the top). Different questions, both legitimate; report the one that matches the decision.
A is wrong: Both are exact for what they measure; Lesson 7.2 sees the same kind of disagreement on churn (tenure and discounts swap places).
B is wrong: Mean |SHAP| here averages over all 15,000 test payments.
D is wrong: Neither is "more correct": they answer different questions.
Q10
A random forest's explanation has values.shape equal to (200, 11, 2). Which object do you pass to shap.plots.waterfall for the first customer's churn class?
A) forest_sv[0]
B) forest_sv[:, :, 0]
C) forest_sv.values.sum()
D) forest_sv[0, :, 1]
Why: A random forest's SHAP values are in probability units and come once per class, so the last axis is the class. Row 0, every feature, class 1 (churned) is one explanation the waterfall can draw.
A is wrong: That is still an (11, 2) matrix: the waterfall raises "can currently only plot a single explanation".
B is wrong: Every customer, class 0 (stayed): the wrong class and too many rows.

Q11
You explain the logistic-regression pipeline with a PermutationExplainer and swap the background from 100 random customers to 100 Gold-tier customers. What changes?
A) The base value and the shares change; the customer's predicted probability does not
B) Nothing: Shapley values do not depend on the background
C) The predicted probability changes, because the model is refitted on Gold customers
D) The shares stay the same but no longer add up
Why: The background defines "a typical value" when a feature is left out, so it sets the base value and therefore the gap that the shares split. The model is never refitted, so the prediction is the same; additivity still holds. Lab 7.2 B shows the same with a night-time reference: night's share drops to 0 and new device's rises to 0.3.
B is wrong: The background is half of the definition: "compared with whom?"
C is wrong: Explainers never refit the model.
D is wrong: Additivity holds for any background; that is what makes them Shapley values.

P4
Predict the output, then run it.
import itertools
def score(a, b):
    return 0.1 + (0.4 if a and b else 0.0)    # a bonus only when BOTH are present
shares = {"a": 0.0, "b": 0.0}
for order in itertools.permutations(["a", "b"]):
    present = {"a": 0, "b": 0}
    for name in order:
        before = score(**present)
        present[name] = 1
        shares[name] += (score(**present) - before) / 2
print(shares)
{'a': 0.2, 'b': 0.2}
Why: The bonus appears only when the second feature arrives, and each feature is second in one of the two orders, so each gets half of 0.4. The 0.1 starting score is the base value and is not shared out.

Reading it: (1) the base value is -5.84 log-odds, 0.0029 as a probability, below the 0.0088 fraud rate for the same reason as churn's 5% against 16.6%: the squash of the average log-odds is not the average probability; additivity holds to 2e-14; (2) mean |SHAP| puts device_new first, although velocity leads permutation importance: a new device moves many predictions somewhat, velocity separates the frauds at the top (self-check Q9); (3, 4) every one of the 25 riskiest payments is a real fraud, 19 led by card velocity; the reasons are neutral facts about the payment; (5) the hour's share is about 0 by day and +0.33 log-odds at night on a known device, +1.24 on a new device: the same interaction Lab 7.1 A found with partial dependence.

Opening: Reading the Room

There is no retrieval warm-up in Session 1. The opening's two checks have their answers above: the environment check output (what READY looks like) and the refresher D1 to D6. Learners who end the opening NOT READY leave with the numbered fix list in their workbook's Start Here box; learners at READY for Sessions 1 to 4 have the --download line to run at home.

Exit Ticket

  1. Three tools: permutation importance = how much the held-out score depends on a feature; partial dependence = how the average prediction moves as one feature changes; neither = what would happen in the world if Pinecrest changed the feature (that needs an experiment).
  2. Waterfall -2.95 → +0.50: the model says expit(0.50) = 0.62. The bars are in log-odds and start at the base value -2.95 (5% as a probability), so they cannot be added to 16.5%, which is a probability (and not the base value either).
  3. Reason code: "no order in 240 days". The agent must not say "you are leaving because ..." or promise an outcome ("if you order now you will stay"): the reason says why the model flagged the account, not why the customer behaves as they do.

Common Wrong Answers and What They Reveal

  • Q1 A or D ("raises the probability by 0.89 / 2.4 points"). Has not separated probability, odds and log-odds. Write the chain on the board: coef → np.exp → odds ratio; probability only at the end.
  • Q3 A ("the noise holds signal"). Trusts the tool over the setup. Ask how the noise was made.
  • Q4 C ("the model does not use the hour"). Reads one metric's importance as the truth. Show TODO 3's partial dependence: night is 2.4 times day.
  • Q5 written as [0. 10.]. Forgot that the other features keep their real values; the average of b (2) is added to every grid point.
  • Q8 written as 0.0 0.0 or 2.2 .... Added shares to a probability, or forgot the base value. Base + shares = 0.0 log-odds; expit(0) = 0.5.
  • Q11 B ("nothing changes"). Thinks Shapley values are a property of the model alone. Lab 7.2 B's night-owl reference is the counterexample.
  • Exit ticket 2: "0.165 + ...". The most common answer in the room, and the reason the units get a slide of their own in Session 2's warm-up.
