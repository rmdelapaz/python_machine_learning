8.6 · Anomaly Detection: self-check

Q1
What does this print?
import numpy as np
from sklearn.ensemble import IsolationForest
rng = np.random.default_rng(42)
X = np.vstack([rng.normal(0, 1, size=(49, 2)), [[8.0, 8.0]]])
pred = IsolationForest(contamination=0.02, random_state=42).fit(X).predict(X)
print(np.unique(pred, return_counts=True))
A) (array([0, 1]), array([ 1, 49]))
B) (array([-1, 1]), array([ 1, 49]))
C) (array([-1, 1]), array([49, 1]))
D) (array([1]), array([50]))
Why: Outlier detectors label outliers -1 and inliers 1, never 0. contamination=0.02 sets the threshold so that 2% of the 50 training rows, one row, falls below it: the planted point at (8, 8).
A is wrong: 0 is the classifiers' label; detectors use -1.
C is wrong: The counts are the wrong way round: one outlier, 49 inliers.
D is wrong: contamination=0.02 guarantees that about 2% of the training rows are flagged.
Q2
Your detector's ROC AUC on June is 0.12, computed from score_samples. What is the most likely explanation?
A) The detector ranks frauds worse than random: drop it
B) contamination is too low
C) Too few trees in the forest
D) score_samples is a normality score (higher = more normal); negate it and the AUC is 0.88
Why: score_samples is higher for normal points, so the frauds sit at the bottom. An AUC far BELOW 0.5 is a perfect ranking turned upside down: 1 - 0.12 = 0.88. Negate once and call it anomaly_score.
A is wrong: Worse than random by that much means the ranking is good, just reversed.
B is wrong: contamination does not change the scores at all, so it cannot change the AUC.
C is wrong: More trees make scores smoother, not reversed.
Q3
What does this print?
import numpy as np
from sklearn.ensemble import IsolationForest
X = np.random.default_rng(3).normal(size=(200, 2))
for c in [0.01, 0.05]:
    model = IsolationForest(contamination=c, random_state=42).fit(X)
    print(c, (model.predict(X) == -1).sum())
0.01 2 / 0.05 10
Why: contamination sets only the threshold (offset_): 1% and 5% of 200 rows fall below it. The scores, and therefore the ranking, are identical for both models.
Q4
An Isolation Forest with contamination=0.02 fitted on January to March flags 2.16% of March but 1.72% of June. Why, and what does the lesson recommend?
A) The forest was refitted on June; fix the random_state
B) June's payments are distributed differently from the fit months, so a fixed threshold drifts: rank each month and review the top N the team can handle
C) contamination is a random setting; average several runs
D) Rounding: 2% of a smaller month is fewer payments
Why: The threshold is a percentile of the training scores. A new month with a slightly different mix falls on either side of it differently. A top-N queue always fills the budget; watch the score distribution separately to notice drift.
A is wrong: Nothing was refitted; the same model scored every month.
C is wrong: contamination is a fixed number, not random.
D is wrong: A percentage is a share; the size of the month does not change it.
Q5
In today's lab, the Isolation Forest's 60 most unusual customers churn at 0.067, well below the 0.165 average. What is the right conclusion?
A) The detector is broken: anomalies should churn more
B) Unusual customers are loyal; target them with fewer offers
C) An anomaly score finds the unusual, not the bad: these are heavy buyers; whether unusual means a problem is a separate question
D) Use the LOF's top 60 instead, because they churn at 0.333
Why: The forest isolated heavy buyers (about 10 orders, $1,810 spend, many returns). Unusual, and mostly good customers. Lesson 8.6, Common Mistake 5: a score is a reason to look, never a verdict.
A is wrong: Nothing says anomalies must churn; the detector did its job.
B is wrong: Sixty customers chosen for being unusual say nothing about how to treat the rest.
D is wrong: Choosing a detector by the outcome you hoped for is not a method; the LOF list answers a different question.
Q6
You fit Local Outlier Factor on May's payments and want to score June's. Which setup works?
A) LocalOutlierFactor(), then predict(june)
B) LocalOutlierFactor(), then fit_predict(june)
C) LocalOutlierFactor(novelty=True) fitted on May, then -score_samples(june)
D) LocalOutlierFactor(novelty=True) fitted on May, then score_samples(may)
Why: novelty=True learns from one set and scores new rows. Negate for an anomaly score. Scaled features, because LOF uses distances.
A is wrong: The default (novelty=False) has no predict: AttributeError.
B is wrong: That fits a new LOF on June alone; May taught it nothing.
D is wrong: Scoring the training rows in novelty mode is optimistic: each point is its own neighbor.

9.1 · Principal Component Analysis: self-check

Q7
What does this print?
import numpy as np
from sklearn.decomposition import PCA
rng = np.random.default_rng(42)
a, b = rng.normal(size=200), rng.normal(size=200)
X = np.column_stack([a, b, a + b])
print(PCA().fit(X).explained_variance_ratio_.round(3))
A) [0.333 0.333 0.333]
B) [1. 0. 0.]
C) [0.5 0.5 0. ]
D) [0.732 0.268 0. ]
Why: The third column is exactly the sum of the first two, so the data lie in a plane: the last component explains nothing. The first two are not equal because a + b adds spread along one diagonal.
A is wrong: Equal shares would need three unrelated columns.
B is wrong: a and b are independent: two directions carry spread.
C is wrong: The plane is not round: the copy a + b stretches it along one diagonal.
Q8
Unscaled PCA on the nine payment features gives a PC1 that explains 95% of the variance and is almost exactly account_age_days. Why?
A) Account age is the most important fraud signal
B) Account age is measured in days, up to about 7,000, so its variance dwarfs the 0/1 flags and small counts
C) PCA always puts the first column first
D) The other columns are categorical
Why: Variance depends on units. Without scaling, PCA mostly tells you which column has the biggest numbers. Scaled, account age barely appears in PC1 or PC2.
A is wrong: PCA never sees is_fraud.
C is wrong: Column order plays no role.
D is wrong: They are numeric 0/1 flags and counts; their variance is just small.
Q9
What does this print?
import numpy as np
from sklearn.decomposition import PCA
X = np.random.default_rng(1).normal(size=(50, 6))
p = PCA(n_components=3).fit(X)
print(p.transform(X).shape, p.components_.shape)
(50, 3) (3, 6)
Why: transform gives one row per sample and one column per kept component; components_ has one row per component and one column per original feature (each row is a direction in the original space).
Q10
In which situation is PCA before a model most likely to help?
A) Ten business columns that each mean something, with the strongest signal in a low-variance column
B) Four categorical columns, one-hot encoded
C) A target that depends on one column PCA spreads over several components
D) 784 highly correlated pixel columns feeding a slow k-nearest-neighbors model
Why: Many correlated columns of one unit: the first components carry most of the signal, the rest is noise, and a distance-based model gets faster. With ten meaningful business columns PCA usually costs accuracy (Lesson 9.1: two components AUC 0.687 against 0.829).
A is wrong: Exactly the churn case where PCA lost the signal.
B is wrong: The variance of 0/1 indicators is a poor measure of similarity.
C is wrong: That is the weakness PCA has, not a reason to use it.
Q11
On June's payments, PCA reconstruction error reached AUC 0.819 but only 19 frauds in the 165-payment queue; Isolation Forest caught 32. What explains the gap?
A) Much of this fraud is extreme on a few columns rather than breaking the correlations most payments share
B) PCA leaked the labels
C) Four components were too many
D) Reconstruction error cannot be used as a score
Why: Reconstruction error flags rows that break shared patterns. Many frauds here are simply extreme (high velocity, new accounts, many card attempts), which Isolation Forest isolates directly. PCA-based detection shines where normal data has strong correlated structure, like sensors or sales.
B is wrong: PCA never saw is_fraud.
C is wrong: The number of components changes the score a little; it does not explain the pattern.
D is wrong: It worked (AUC 0.819), just with a less pure top of the ranking.
Q12
On the ten scaled churn features, how many components does PCA(n_components=0.90) keep, and is that a useful reduction?
7: hardly a reduction
Why: The cumulative shares reach 0.905 at seven of ten components. The scree is flat: these business columns are only partly redundant, so PCA cannot compress them much.

The Lesson Pages' Own Quick Quizzes

Lesson 8.6 · Anomaly Detection
  1. A Random cuts isolate them in fewer steps, so their average path length is short.
  2. C [-1 1]: outliers -1, inliers 1; a few fringe points of the first 50 are flagged.
  3. B Only the threshold changes: more points labeled -1, in the same order.
  4. A Local Outlier Factor: it compares the point with its own dense neighborhood.
  5. C How many frauds land in the top 165, compared with a baseline.
Lesson 9.1 · Principal Component Analysis
  1. B One column with large units dominates the variance.
  2. C [1. 0.]: b = 2a, so all points lie on one line.
  3. A The directions with the most spread are not the directions that predict churn.
  4. B Nothing important: a component's sign is arbitrary.
  5. C All columns share one unit, and their different spreads are meaningful.

Exit Ticket

  1. anomaly_score = -model.score_samples(X); queue = np.argsort(-anomaly_score)[:165]. Forget predict's labels; count frauds in the queue.
  2. contamination moves only the threshold; scores, ranking and AUC do not change. Decide how many to review from the team's capacity and the costs ($10 per review, $375 per missed fraud in the lesson).
  3. The column with the largest units (spend in dollars) took over PC1. Skip scaling only when all columns share one meaningful unit (monthly sales, pixel brightness).

Common Wrong Answers and What They Reveal

  • Q1 A ([0, 1]). Classifier habit. Write the convention table again.
  • Q2 A (drop the detector). Has not met a flipped sign. Show 1 - 0.12.
  • Q4 A or C. Thinks the model changed. Same model, different month.
  • Q5 A or D. Expects anomaly to mean bad. Reread Common Mistake 5.
  • Q8 A. Thinks PCA knows about fraud. It never sees labels.
  • Q12 written as 2 or 3. Reads 90% as "a few components"; the scree is flat here.
