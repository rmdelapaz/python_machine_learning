Capstone Project

By the end you can
  • Frame a business request as a machine-learning task with a decision, a target, a leakage-safe split, a metric and a baseline, written down before any modeling
  • Build, compare and improve models in leakage-proof pipelines, touching the test set once
  • Analyze errors by subgroup and explain the model honestly, without claiming causes
  • Review your model against a responsible-ML checklist and document it in a model card
  • Deliver a project that reruns from a fresh start and score it yourself against a rubric
Key ideas
  • Test once: refit the final pipeline on all training data, score the test set, write the number next to the baseline. The model is now finished.
  • An interval with every headline number: a paired bootstrap for model vs baseline; resample whole weeks or customers when rows are not independent.
  • An operating point from capacity or costs: the team's 1%, top 10, a threshold from dollars.
  • Averages hide failures: break errors down by a meaningful group, with the baseline's errors beside them, and read the worst cases.
  • Explanations describe the model, never the causes; say who bears the errors and keep a human where an error harms someone.
  • The card leads with a recommendation, and its numbers come from the results, never from memory. "Do not deploy" with evidence is a full answer.
Worked example: an interval for a hit-rate gain

How sure is "better than the baseline"? On the recommendations problem, item-kNN beats the best-seller list on the test purchases. A paired bootstrap resamples the SAME customers for both models.

import numpy as np
import pandas as pd
from scipy.sparse import csr_matrix
from sklearn.metrics.pairwise import cosine_similarity
df = pd.read_csv("data/interactions.csv").sort_values(["customer_id", "last_purchase_date", "product_id"])
test = df.groupby("customer_id").tail(1)
train = df.drop(test.index)
customers, products = np.sort(df["customer_id"].unique()), np.sort(df["product_id"].unique())
row = pd.Series(np.arange(len(customers)), index=customers)
col = pd.Series(np.arange(len(products)), index=products)
R = csr_matrix((np.ones(len(train)), (row[train["customer_id"]], col[train["product_id"]])),
               shape=(len(customers), len(products)))
owned = R.toarray() > 0
hidden = col[test.set_index("customer_id").loc[customers, "product_id"]].to_numpy()
def hits(scores):
    s = np.array(scores, dtype=float)
    s[owned] = -np.inf
    return (np.argsort(-s, axis=1)[:, :10] == hidden[:, None]).any(axis=1).astype(float)
sim = cosine_similarity(R.T)
np.fill_diagonal(sim, 0)
pop_hit = hits(np.tile(np.asarray(R.sum(axis=0)).ravel(), (R.shape[0], 1)))
knn_hit = hits(np.asarray(R @ sim))
print(f"popularity {pop_hit.mean():.3f}   item-kNN {knn_hit.mean():.3f}   difference {knn_hit.mean() - pop_hit.mean():.3f}")
popularity 0.209   item-kNN 0.308   difference 0.099
rng = np.random.default_rng(42)
diffs = []
for _ in range(1000):
    rows = rng.integers(0, len(knn_hit), len(knn_hit))          # the SAME customers for both models
    diffs.append(knn_hit[rows].mean() - pop_hit[rows].mean())
low, high = np.percentile(diffs, [2.5, 97.5])
print(f"item-kNN minus popularity: {knn_hit.mean() - pop_hit.mean():.3f} (95% CI {low:.3f} to {high:.3f})")
n_hist = np.asarray(R.sum(axis=1)).ravel()
group = pd.cut(n_hist, [0, 4, 8, 15, 100], labels=["2-4", "5-8", "9-15", "16+"])
print(pd.DataFrame({"customers": pd.Series(group).value_counts().sort_index(),
                    "popularity": pd.Series(pop_hit).groupby(group, observed=True).mean().round(3),
                    "item_kNN": pd.Series(knn_hit).groupby(group, observed=True).mean().round(3)}))
item-kNN minus popularity: 0.099 (95% CI 0.082 to 0.116)
      customers  popularity  item_kNN
2-4         607       0.199     0.257
5-8         987       0.202     0.280
9-15        950       0.204     0.334
16+         456       0.246     0.382

The gain (0.099) has an interval far from zero, so it is real. The subgroup table says more than the average: customers with long histories gain most, and even customers with only 2 to 4 earlier purchases do better than with best sellers. That is one sentence for the card's Performance by subgroup section.

Glossary

TermMeaning
paired bootstrapResample the same rows for two models and look at the difference
block bootstrapResample whole groups (weeks, customers) that are not independent
operating pointThe threshold or list size used in practice
subgroup analysisThe metric by store, category, account age or segment, with the baseline beside it
model cardOne to two pages: recommendation, use, performance, subgroups, risks, limits, monitoring, how to reproduce
fallbackWhat runs when the model is switched off (usually the baseline)
