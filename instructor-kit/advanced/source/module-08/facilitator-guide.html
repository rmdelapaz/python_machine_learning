Session 8: CNNs and Sequence Models

How to teach Session 8 of Advanced Machine Learning. Convolutions and pooling, built up from a hand-applied filter to a CNN that beats a dense network on Fashion-MNIST with the same loop; then sequences: naive forecasts, windows split by time, an RNN opened up, an LSTM forecaster that beats "same day last week" by a third, and attention built by hand. Includes a CPU-time plan (what to start early, what trains through the break, a checkpoint fallback) for the first session where training takes real time.

The #1 risk of Session 8: waiting for training

Ten epochs of CNN training in the demo, four more in the project, two GRUs in a lab: on a slow laptop the room spends its time watching progress lines. The plan: start every training cell, then TALK over it (each demo step says what to discuss while it runs); load the kit's checkpoint the moment a laptop falls behind; and launch the project's training right before the break so it finishes while people get coffee. The second risk is the opposite of Session 7's: a room that now believes networks always win. Protect the end of 10.4's project (on learners' own time, so make the point in the demo): with the same information, default gradient boosting on a few lag columns ($616) sits between the weekday-only LSTM ($702) and the calendar-aware one ($515). The information fed in mattered more than the architecture.

Questions and answers
  1. W1. What does this print? (Lesson 10.2) 
    import numpy as np
import torch
print(torch.tensor(np.zeros(3)).dtype, torch.tensor(np.zeros(3), dtype=torch.float32).dtype)
    Answer: torch.float64 torch.float32: torch.tensor keeps NumPy's float64; layers want float32, so convert as you create.
  2. W2. Put the four lines of the batch loop in order: loss.backward(), optimizer.step(), optimizer.zero_grad(), loss = loss_fn(model(xb), yb). (10.2) Answer: optimizer.zero_grad(), loss = loss_fn(model(xb), yb), loss.backward(), optimizer.step().
  3. W3. Your binary model ends with nn.Linear(32, 1) and trains with BCEWithLogitsLoss. Where does the sigmoid go? (10.2) Answer: Inside the loss during training; apply torch.sigmoid yourself only to report probabilities. Today's ten-class models follow the same rule with softmax and CrossEntropyLoss.
  4. W4. A model with dropout gives a different score for the same customer on every call, inside with torch.no_grad(). Why? (10.2) Answer: It is still in training mode: no_grad() stops gradient tracking but does not switch dropout off. Call model.eval().
  5. W5. On the churn table the PyTorch network scored test AUC 0.846 and gradient boosting 0.850. What was the verdict, and what kind of data should change it? (10.1, 10.2) Answer: Recommend boosting: a tie within the wobble, with far fewer choices. Images, sequences and text are where networks earn their keep: today's session.

Mental model to say

Say: "Picture a 3 × 3 stencil cut to match one pattern: dark on the left, bright on the right. Slide it across the photo one step at a time and write down how well each patch matches. You get a new image, bright wherever that pattern appears: a feature map. The stencil is a filter, the sliding is a convolution. A layer holds many stencils, and training learns their patterns: edges first, then corners and stripes, then collars and soles."

Then the two ideas on the board: local connectivity (each output looks at a small window) and weight sharing (the same stencil at every position, so a pattern learned once is found anywhere, for 9 weights plus a bias). Contrast: "A dense network flattens the image into 784 unrelated numbers; if a sneaker moves three pixels, every input changes." Today's shift lab tests how far that promise really goes.

def train_one_epoch(model, loader, optimizer, loss_fn):
    model.train()
    total_loss, n = 0.0, 0
    for xb, yb in loader:
        optimizer.zero_grad()
        loss = loss_fn(model(xb), yb)
        loss.backward()
        optimizer.step()
        total_loss += loss.item() * len(yb)
        n += len(yb)
    return total_loss / n

def accuracy(model, loader):
    model.eval()
    correct, n = 0, 0
    with torch.no_grad():
        for xb, yb in loader:
            correct += (model(xb).argmax(dim=1) == yb).sum().item()
            n += len(yb)
    return correct / n

def fit(model, epochs=5, lr=1e-3):
    torch.manual_seed(42)
    train_loader = DataLoader(train_set, batch_size=64, shuffle=True)
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    loss_fn = nn.CrossEntropyLoss()
    for epoch in range(1, epochs + 1):
        loss = train_one_epoch(model, train_loader, optimizer, loss_fn)
        print(f"epoch {epoch}: train loss {loss:.3f}  validation accuracy {accuracy(model, val_loader):.3f}")

Three mistakes to expect, and how to coach each
  • The channel axis. RuntimeError: Given groups=1, weight of size [16, 1, 3, 3], expected input[1, 64, 28, 28] to have 1 channels, but got 64 channels instead Coach: "How many dimensions does a batch of images need, and in what order?" (batch, channels, height, width); .unsqueeze(1).
  • The first Linear sized on paper. RuntimeError: mat1 and mat2 shapes cannot be multiplied (64x1568 and 25088x10) Coach: "Trace a dummy batch through features and read the size." The message always shows the actual size first.
  • Probabilities into CrossEntropyLoss, or predictions in training mode. Both silent (demo Step 13): a softmax layer before the loss keeps even a perfect answer at a loss of 1.461; dropout and batch norm in training mode make predictions noisy and worse. Coach: "What does your last layer output: logits or probabilities? Which mode is the model in right now?"

Mental model to say

Say: "A store manager reads the till report every evening. They do not memorize every number; they keep a short notebook of impressions, update it each evening with the same habits, and guess tomorrow from the notebook alone. That notebook is a recurrent network's hidden state. An LSTM is a manager with a better notebook: it decides what to erase, what to write and what to read out, so a note from four weeks ago can survive. Attention is a different manager: every report goes in a binder, and each evening they flip to the pages that look most relevant to tomorrow."

Then the discipline, which matters more than the architecture: split by time, beat the naive forecasts, report in dollars. "A deep model that cannot beat 'same as last week' is not worth deploying, and in forecasting that happens more often than tutorials admit."

def build_windows(z, calendar, window=WINDOW):
    """Windows of `window` days for every store: (sales, next day's calendar) per step -> next day's sales."""
    X, y, day, store = [], [], [], []

    class SalesRNN(nn.Module):
    def __init__(self, n_features, hidden=32, cell=nn.LSTM):
        super().__init__()
        self.rnn = cell(n_features, hidden, batch_first=True)
        self.head = nn.Linear(hidden, 1)

    def forward(self, x):                      # x: (batch, 28, n_features)
        out, _ = self.rnn(x)                   # out: (batch, 28, hidden)
        return self.head(out[:, -1]).squeeze(-1)   # last step's hidden state -> one number per window

from torch.utils.data import TensorDataset, DataLoader

def train_forecaster(model, X, y, train_mask, epochs=15, lr=3e-3):
    torch.manual_seed(42)                      # same batch order every run
    loader = DataLoader(TensorDataset(X[train_mask], y[train_mask]), batch_size=64, shuffle=True)
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    loss_fn = nn.MSELoss()
    for epoch in range(1, epochs + 1):
        model.train()
        total = 0.0
        for xb, yb in loader:
            optimizer.zero_grad()
            loss = loss_fn(model(xb), yb)
            loss.backward()
            optimizer.step()
            total += loss.item() * len(xb)
        if epoch % 5 == 0:
            print(f"epoch {epoch:2d}  train MSE {total / len(loader.dataset):.3f}")
    return model

def predict_dollars(model, X):
    model.eval()
    with torch.inference_mode():
        return to_dollars(model(X).numpy())

    def attend(query, keys, values, sharpness=5.0):
    scores = sharpness * (keys @ query)
    weights = np.exp(scores - scores.max())
    weights = weights / weights.sum()

  1. A batch (64, 1, 28, 28) goes through nn.Conv2d(1, 16, kernel_size=3, padding=1) and then nn.MaxPool2d(2). Shape after each? Answer: (64, 16, 28, 28), then (64, 16, 14, 14).
  2. Why must a time series be split by time and not at random? Answer: the model must be graded on days after everything it learned from, as in real use; overlapping windows in a random split put each test day's inputs and target into training, so the score is too good to be true.
  3. With the same information, the calendar-aware LSTM forecast daily sales with MAE $515 and default gradient boosting on lag features $616 (and $569 given the event type). What do you tell the store managers? Answer: both are far better than "same day last week" ($1,072) and in the same league; the LSTM leads here, but boosting was simpler, faster and untuned, and the information fed in mattered more than the architecture. Start with the simpler one, keep testing both.
