10.3 · Convolutional Neural Networks: self-check

Q1
What does this print?
import torch
from torch import nn
conv = nn.Conv2d(3, 16, kernel_size=3, stride=2, padding=1)
print(tuple(conv(torch.zeros(8, 3, 32, 32)).shape))
(8, 16, 16, 16)
Why: Per side: (32 + 2 × 1 - 3) / 2 + 1 = 16.5, rounded down to 16. The batch stays 8 and the 16 filters give 16 channels.
Q2
How many parameters does nn.Conv2d(3, 8, kernel_size=3) have?
A) 224
B) 216
C) 72
D) 80
Why: Each of the 8 filters spans all 3 input channels: 8 × (3 × 3 × 3) = 216 weights, plus 8 biases = 224.
B is wrong: That forgets the 8 biases.
C is wrong: That counts one input channel only (8 × 9).
D is wrong: One input channel plus biases: every filter spans ALL incoming channels.
Q3
Why does the lesson use padding=1 with every 3 × 3 kernel?
A) It halves the height and width
B) It adds a border of learnable weights
C) It keeps the height and width unchanged: (n + 2 - 3) / 1 + 1 = n
D) Grayscale images require it
Why: A one-pixel border of zeros lets the 3 × 3 window sit centered on every pixel, so 28 stays 28. Without it, 28 becomes 26. Halving is the pooling layer's job.
A is wrong: That is `MaxPool2d(2)` (or stride 2).
B is wrong: The border is zeros, not weights.
D is wrong: Padding works the same for any number of channels.
Q4
What does this print?
import torch
import torch.nn.functional as F
x = torch.arange(16.0).reshape(1, 1, 4, 4)
print(F.max_pool2d(x, 2).squeeze())
tensor([[ 5., 7.], [13., 15.]])
Why: The 4 × 4 grid holds 0 to 15 row by row. Max pooling keeps the largest value of each 2 × 2 block: 5 (0, 1, 4, 5), 7, 13 and 15. It has no weights.
Q5
In the shift lab, the lesson's CNN loses about 12 points of test accuracy when every image moves 2 pixels to the right. Convolutions share weights across positions, so why does it lose anything?
A) The model has no max pooling
B) The shifted images were scaled differently
C) Each convolution uses different weights at different positions
D) The Flatten + Linear head reads WHERE each feature map lit up, so positions still matter
Why: The convolutions find a pattern anywhere, and pooling forgives a pixel or so. But the flattened maps go into a dense layer with one weight per position, which learned where features usually appear in centered images. Training on shifted copies (augmentation) is the usual remedy.
A is wrong: It has two max-pooling layers; they buy only a pixel or two of tolerance.
B is wrong: Shifting moves pixels; their values are unchanged.
C is wrong: That is exactly what weight sharing rules out.
Q6
This model fails. What should the first argument of its nn.Linear be?
import torch
from torch import nn
model = nn.Sequential(
    nn.Conv2d(1, 64, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.MaxPool2d(2), nn.Flatten(), nn.Linear(64 * 14 * 14, 10),
)
model(torch.zeros(64, 1, 28, 28))
A) 12544 (64 × 14 × 14)
B) 3136 (64 × 7 × 7)
C) 1568 (32 × 7 × 7)
D) 64 (one number per filter)
Why: The message reads RuntimeError: mat1 and mat2 shapes cannot be multiplied (64x3136 and 125...: the rows really have 3,136 numbers. Two poolings take 28 to 14 to 7, with 64 channels: 64 × 7 × 7. Trace a dummy batch instead of computing on paper.
A is wrong: That counts only one pooling.
C is wrong: That is the lesson's SmallCNN with 32 channels.
D is wrong: 64 would need global average pooling first.

10.3 · Convolutional Neural Networks: predict, then run

P1
Predict the output, then run it.
import torch
from torch import nn
print(nn.MaxPool2d(2)(torch.zeros(5, 8, 28, 28)).shape)
torch.Size([5, 8, 14, 14])
Why: Max pooling with a 2 × 2 window halves height and width and keeps batch and channels: (5, 8, 14, 14).
P2
Predict the output, then run it.
from torch import nn
print(sum(p.numel() for p in nn.Conv2d(1, 4, kernel_size=5).parameters()))
104
Why: Four filters of 1 × 5 × 5 = 25 weights, plus 4 biases: 104.

10.4 · Sequence Models: self-check

Q7
What does this print?
import torch
from torch import nn
out, h = nn.GRU(5, 8, batch_first=True)(torch.zeros(4, 10, 5))
print(tuple(out.shape), tuple(h.shape))
(4, 10, 8) (1, 4, 8)
Why: With batch_first=True, out holds the hidden state of size 8 after every one of the 10 steps of each of the 4 sequences; h holds only the last one, with a leading dimension for the number of layers.
Q8
A store has 100 days of sales. How many training examples do windows of 7 days (each predicting the next day) give?
A) 100
B) 94
C) 93
D) 7
Why: The first target that has 7 days before it is day 8 (index 7), so targets run from index 7 to 99: 100 - 7 = 93 windows, exactly as the lesson's make_windows gives 10 - 4 = 6.
A is wrong: The first seven days have no full window before them.
B is wrong: Off by one: count the targets, from index 7 to 99.
D is wrong: That is the window length.
Q9
For Pinecrest's daily store sales, which forecast is the seasonal naive one?
A) Tomorrow = the same weekday last week
B) Tomorrow = today
C) Tomorrow = the average of the training years
D) Tomorrow = the same date last year
Why: The season that dominates daily sales is the week (Saturday sells almost twice what Tuesday does), so the seasonal naive forecast copies the value 7 days earlier: MAE $1,072 in 2025, against $1,350 for yesterday's value.
B is wrong: That is the plain naive forecast.
C is wrong: That ignores the weekly cycle and the trends.
D is wrong: A yearly season exists too, but last year's date falls on a different weekday.
Q10
What does this print?
import numpy as np
keys = np.array([[1, 0], [0, 1], [1, 0]])
values = np.array([10.0, 50.0, 30.0])
query = np.array([1, 0])
w = np.exp(5 * (keys @ query))
w = w / w.sum()
print(w.round(3), round(w @ values, 1))
[0.498 0.003 0.498] 20.1
Why: The query matches keys 1 and 3 (score 5) and not key 2 (score 0), so the softmax gives them almost all the weight, equally: the output is about the average of 10 and 30. That is the lesson's "four Saturdays" lookup in miniature.
Q11
Your LSTM predicts standardized log sales. What must happen before you compute the MAE you report?
A) Round the predictions to whole numbers
B) Nothing: targets and predictions are on the same scale, so the MAE is fair
C) Multiply the predictions by sd
D) Undo the standardization, then the log (expm1), and compare in dollars
Why: The error must be in units a manager understands and comparable with the naive forecasts. The lesson's Mistake 5 shows the same model at 0.222 in scaled log units and $702 in dollars.
A is wrong: Rounding changes nothing about the units.
B is wrong: A scaled error flatters the model and cannot be compared with anything.
C is wrong: Half the undo: add mu, then expm1.
Q12
You create nn.LSTM(8, 32) and forget batch_first=True, while your windows are (batch, 28, 8). What happens?
A) A RuntimeError about the input size
B) It runs and trains on nonsense: PyTorch reads (batch, time) as (time, batch)
C) PyTorch notices and transposes the input
D) The output becomes (28, 64, 32), so the linear head fails
Why: The default layout is (time, batch, features). Your 64 windows become 64 time steps of 28 "sequences"; out[:, -1] still has a usable shape, so nothing complains (the lesson's Mistake 3).
A is wrong: The feature size (8) still matches, so nothing raises.
C is wrong: PyTorch never guesses the layout.
D is wrong: The output keeps the input's (64, 28, ...) layout, which is why the bug is silent.

10.4 · Sequence Models: predict, then run

P3
Predict the output, then run it.
import numpy as np
series = np.arange(6)
X = np.stack([series[i:i + 3] for i in range(len(series) - 3)])
print(X.shape, series[3:])
(3, 3) [3 4 5]
Why: 6 values and windows of 3 give 6 - 3 = 3 windows of 3; the targets are the values after each window: 3, 4, 5.
P4
Predict the output, then run it.
from torch import nn
print(sum(p.numel() for p in nn.LSTM(input_size=2, hidden_size=4).parameters()))
128
Why: Four gates, each with input weights (4 × 2) and hidden weights (4 × 4) and two bias vectors of 4: 4 × (8 + 16 + 8) = 128.

The solution prints (CNN column yours may vary slightly):

(60000, 1, 28, 28) (10000, 1, 28, 28)
edge maps: (4, 2, 28, 28)  filter shape: (2, 1, 3, 3)
hand-made features per image: 48

training images   hand-made filters + logistic regression   SmallCNN, 3 epochs
          1,000                                     0.795               0.676
          5,000                                     0.819               0.782
         20,000                                     0.827               0.863

With little data, two filters chosen by a person win: they encode knowledge the CNN must
learn from examples. With 20,000 images the CNN's sixteen learned filters overtake them,
and more data and epochs widen the gap (the lesson's Scaling Up: about 90 to 92% on all 60,000).

Reading it: 48 = 2 filters × 16 regions + 16 brightness numbers. The hand-made pipeline is strong with little data because the person supplied the knowledge (edges matter, roughly where they are matters); the CNN must learn sixteen filters and a classifier from examples, and at 1,000 images in 3 epochs it cannot. By 20,000 it passes the fixed features. Common sticking point: forgetting .abs(), so positive and negative edge responses cancel when averaged (accuracy drops noticeably).

The Lesson Pages' Own Quick Quizzes

Lesson 10.3 · Convolutional Neural Networks
  1. B torch.Size([4, 8, 24, 24]): 28 - 5 + 1 = 24 without padding; 8 filters give 8 channels.
  2. C 4,640: 32 × (16 × 3 × 3) = 4,608 weights plus 32 biases.
  3. A Small filters reused at every position: patterns learned once and found anywhere.
  4. A So dropout stops zeroing activations and batch norm uses its stored training statistics.
  5. C A plain nn.Linear with 10 outputs (logits): CrossEntropyLoss applies log-softmax itself.
Lesson 10.4 · Sequence Models
  1. B (10, 7, 16): one hidden state of size 16 for each of the 7 steps of the 10 sequences.
  2. A It is a free forecast that already captures the weekly cycle; a model must beat it.
  3. C Gradients vanish over many steps, so plain RNNs struggle to learn from the distant past.
  4. B Their keys matched the query (tomorrow's weekday) and the softmax turned the higher scores into most of the weight.
  5. C Overlapping windows leaked the test days into training: too good to be true.

Exit Ticket

  1. Shapes: (64, 16, 28, 28) after the convolution (16 filters, padding keeps 28), then (64, 16, 14, 14) after pooling.
  2. Time split: a forecast is made on the day before, knowing only the past. A random split of overlapping windows puts the days around each test window, including its target, into training, so the model is graded on data it has effectively seen. Accept "leakage" with any correct reason.
  3. $515 vs $616 / $569: both far better than seasonal naive ($1,072) and in the same league; the LSTM leads here, but boosting was simpler, fast, untuned, and easier to explain; the calendar information mattered more than the architecture. Good answers recommend starting with the simpler model or keeping both under test; weak answers just say "the LSTM, it is lower".

Common Wrong Answers and What They Reveal

  • Q2 B (216). Forgets biases again: a Session 7 echo. Q2 C or D: forgets that every filter spans all input channels.
  • Q5 C. Has not understood weight sharing; replay the stencil sliding over the image.
  • Q6 A (12544). Counted one pooling. The habit to build is tracing, not arithmetic.
  • Q8 B (94). Off by one: count targets, not windows' start positions.
  • Q11 B. Believes a scaled error is fair because both sides are scaled; ask them to compare it with $1,072.
  • Q12 A or D. Expects PyTorch to complain. The lesson's Mistake 3 is the counterexample: always print shapes when building a model.
