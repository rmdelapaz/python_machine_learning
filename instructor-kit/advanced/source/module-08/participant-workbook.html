10.3

Convolutional Neural Networks

By the end you can
  • Explain what a convolution filter and a pooling layer compute, and why sharing one small filter across the whole image suits pictures
  • Predict the output shape and the parameter count of nn.Conv2d and nn.MaxPool2d layers
  • Build a CNN as an nn.Module and train it on Fashion-MNIST with a validation set and a fixed seed
  • Compare it with a dense-network baseline using test accuracy, per-class accuracy and a confusion matrix
  • Save trained weights with state_dict and reload them safely with weights_only=True
Key ideas
  • A convolution slides a small filter over the image; each filter makes one feature map (one output channel). Deep-learning libraries do not flip the kernel; nobody minds.
  • Local connectivity and weight sharing: each output looks at a small window, and the same filter is used everywhere, so a pattern learned once is found anywhere, for very few weights.
  • Shapes: batches are (batch, channels, height, width); per side out = (n + 2p - k) / s + 1, rounded down; padding=1 with a 3 × 3 kernel keeps the size.
  • Parameters: a conv layer has out × (in × k × k) + out; max pooling has none and halves height and width.
  • Trace a dummy batch through the layers to size the first nn.Linear.
  • Logits for CrossEntropyLoss; model.train() / model.eval() switch dropout and batch norm; evaluate under torch.no_grad().
  • A fair comparison: same images, same order, same loop; only the architecture changes. Dense 0.840, CNN 0.864, improved CNN 0.892 on the test set.
  • Report the weakest classes: shirts, T-shirts, pullovers and coats look alike at 28 × 28.
Worked example: a color CNN, layer by layer

Lesson 10.5 will work with 64 × 64 color images. Trace one through a small two-block CNN and count where the parameters live.

import torch
from torch import nn

net = nn.Sequential(
    nn.Conv2d(3, 8, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.Conv2d(8, 16, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
    nn.Flatten(), nn.Linear(16 * 16 * 16, 10),
)
x = torch.zeros(1, 3, 64, 64)                       # one 64 x 64 color image
for layer in net:
    x = layer(x)
    n = sum(p.numel() for p in layer.parameters())
    print(f"{layer.__class__.__name__:10s} {str(tuple(x.shape)):18s} {n:6,d} parameters")
Conv2d     (1, 8, 64, 64)        224 parameters
ReLU       (1, 8, 64, 64)          0 parameters
MaxPool2d  (1, 8, 32, 32)          0 parameters
Conv2d     (1, 16, 32, 32)     1,168 parameters
ReLU       (1, 16, 32, 32)         0 parameters
MaxPool2d  (1, 16, 16, 16)         0 parameters
Flatten    (1, 4096)               0 parameters
Linear     (1, 10)            40,970 parameters

Three channels in, so each first-layer filter has 3 × 3 × 3 weights: 8 × 27 + 8 = 224. Each pooling halves the side: 64 → 32 → 16. The convolutions together use under 1,400 parameters; the single dense layer at the end uses 40,970, because it has one weight per position of every feature map. That is where to save parameters, and why big CNNs end with global pooling.

10.4

Sequence Models

By the end you can
  • Measure naive and seasonal-naive forecasts and a gradient-boosting model on lag features, and use them as the yardsticks any sequence model must beat
  • Turn a time series into sliding windows with a time-based train/test split, and explain why a random split leaks
  • Explain how a recurrent cell carries a hidden state through a sequence, and why LSTMs and GRUs add gates
  • Build, train and evaluate an LSTM forecaster in PyTorch, reporting the error in dollars
  • Describe attention as a soft lookup, compute it by hand, and say when a transformer is (and is not) worth it
Key ideas
  • Order matters: split by time (train 2023 and 2024, test 2025), never at random.
  • Naive forecasts are the yardsticks: yesterday ($1,350 MAE) and the same day last week ($1,072).
  • Windows: a window of recent days predicts the next day; neighbors overlap, which is why random splits leak. Shape (batch, time steps, features) with batch_first=True.
  • A recurrent cell updates a hidden state with the same weights at every step; plain RNNs forget because gradients vanish. LSTMs and GRUs add gates.
  • Scale, then undo: log1p and standardize with the training years; report the error in dollars.
  • The LSTM (28 days + weekday) beat seasonal naive: $702; with tomorrow's promotion and closed flags, $515.
  • Attention is a soft lookup: queries score keys, a softmax makes weights, the output averages the values. Transformers stack learned attention.
  • Honesty: default boosting on lag features with the same information scored $616: the information fed in mattered more than the architecture.
Worked example: a notebook that forgets

A recurrent cell with one input weight, one memory weight and a one-number hidden state. One busy day, then four quiet ones: how long does the notebook remember?

import numpy as np

w_x, w_h, b = 1.0, 0.5, 0.0                         # one input weight, one memory weight
h = 0.0
for t, x in enumerate([2.0, 0.0, 0.0, 0.0, 0.0]):   # one big day, then four quiet ones
    h = np.tanh(w_x * x + w_h * h + b)
    print(f"step {t}: input {x:.1f}  hidden state {h:.3f}")
step 0: input 2.0  hidden state 0.964
step 1: input 0.0  hidden state 0.448
step 2: input 0.0  hidden state 0.220
step 3: input 0.0  hidden state 0.110
step 4: input 0.0  hidden state 0.055

With a memory weight of 0.5 the impression halves every day. Change the memory weight:

for w_h in [0.5, 0.9, 1.5]:
    h = 0.0
    for x in [2.0, 0.0, 0.0, 0.0, 0.0]:
        h = np.tanh(1.0 * x + w_h * h)
    print(f"memory weight {w_h}: hidden state after four quiet days {h:.3f}")
memory weight 0.5: hidden state after four quiet days 0.055
memory weight 0.9: hidden state after four quiet days 0.395
memory weight 1.5: hidden state after four quiet days 0.861

A small memory weight forgets fast; a larger one keeps the busy day in mind for longer. Training chooses such weights. Over 28 steps, the gradient that teaches them is multiplied 28 times by factors like these, which is why plain RNNs struggle with the distant past and LSTMs add a cell state updated by adding and scaling.

Glossary

TermMeaning
convolutionSliding a small filter over an image; each position gives one number of a feature map
filter (kernel)The small grid of learned weights, usually 3 × 3, spanning all input channels
feature map / channelThe output of one filter; a conv layer outputs one channel per filter
padding / strideZeros around the border (keeps the size) / the step between positions (2 halves it)
max poolingKeeps the largest value of each small block; no weights; halves height and width
weight sharingOne filter reused at every position: patterns found anywhere, few weights
batch normalizationRescales activations batch by batch; stores statistics used in eval mode
seasonal naiveForecast = the value one season ago (same weekday last week)
windowA run of recent time steps used as one input; the next step is its target
hidden stateThe vector a recurrent cell carries from step to step: its notebook
LSTM / GRURecurrent cells with gates that decide what to keep, write and reveal
vanishing gradientGradients shrinking over many steps, so the distant past is hard to learn
attentionWeights from matching a query with keys (softmax), used to average values
transformerA model built from stacked learned attention layers plus positional information
