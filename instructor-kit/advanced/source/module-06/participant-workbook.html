9.2

Linear Discriminant Analysis

By the end you can
  • Explain how LDA differs from PCA: it uses the labels to find directions that separate classes
  • Use LDA to reduce dimensions for a plot or as a step before another model
  • Use LDA as a classifier and compare it with logistic regression
  • Know the limit on components (classes minus one) and when shrinkage helps
  • Keep LDA inside the pipeline so cross-validation stays honest
Key ideas
  • The team photo. PCA keeps the widest spread; LDA keeps the class means far apart relative to the spread inside each class.
  • At most classes minus one axes: one for churn, two for three tiers.
  • scalings_ are the axis weights; explained_variance_ratio_ is the share of class separation.
  • As a classifier LDA draws straight boundaries and often matches logistic regression; QDA allows curves but needs far more data.
  • Priors move the threshold, not the ranking. Shrinkage (lsqr or eigen) for many features and few rows.
  • Inside the pipeline. A supervised reducer fitted before cross-validation can separate pure noise.
Worked example: one number as a churn risk score

One number per customer as a churn risk score: the LDA axis against the first principal component, each cut into ten deciles on the test customers.

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
from sklearn.discriminant_analysis import LinearDiscriminantAnalysis

customers = pd.read_csv("data/customers_churn.csv")
features = ["tenure_months", "orders_12m", "spend_12m", "avg_order_value", "days_since_last_order",
            "returns_12m", "return_rate", "support_tickets_12m", "discount_share", "app_user"]
X_train, X_test, y_train, y_test = train_test_split(customers[features], customers["churned"],
                                                    test_size=0.25, stratify=customers["churned"], random_state=42)
ld1 = make_pipeline(StandardScaler(), LinearDiscriminantAnalysis()).fit(X_train, y_train).transform(X_test)[:, 0]
pc1 = make_pipeline(StandardScaler(), PCA(n_components=1)).fit(X_train).transform(X_test)[:, 0]

for name, score in [("LD1", ld1), ("PC1", -pc1)]:          # PC1 negated: low activity = risk
    decile = pd.qcut(pd.Series(score).rank(method="first"), 10, labels=range(1, 11))
    rates = pd.Series(y_test.to_numpy()).groupby(decile, observed=True).mean()
    print(f"{name}: churn in the lowest decile {rates.iloc[0]:.3f}, highest decile {rates.iloc[-1]:.3f}")
LD1: churn in the lowest decile 0.013, highest decile 0.580
PC1: churn in the lowest decile 0.080, highest decile 0.393

The riskiest tenth by LD1 churned at 58%, the safest at 1.3%: a 45-fold spread from ONE number. PC1 (negated so that low activity means risk) spreads churn far less, from 8% to 39%. Both are a single straight direction through the same ten columns; only one was chosen with the labels.

9.3

t-SNE and UMAP

By the end you can
  • Explain what t-SNE and UMAP preserve and what they distort
  • Tune perplexity (t-SNE) and n_neighbors and min_dist (UMAP), and see how the picture changes
  • Read an embedding without over-interpreting cluster sizes or distances
  • Check a map with numbers (neighbors kept, trustworthiness) instead of by eye
  • Choose between PCA, t-SNE and UMAP for a task, and place new rows with UMAP
Key ideas
  • The seating chart. t-SNE and UMAP keep neighbors close and bend everything else.
  • Settings: perplexity (t-SNE), n_neighbors and min_dist (UMAP). Try more than one.
  • Five rules: neighbors meaningful; sizes not; distances between clusters not; axes meaningless; validate clusters in the original space.
  • Low perplexity invents clumps from pure noise.
  • Check with numbers: neighbors kept, trustworthiness. Maps flatter separation.
  • PCA to about 50 first on wide data; scale tabular data.
  • UMAP has transform and can place new rows; t-SNE cannot and never goes in a model pipeline.
Worked example: two perplexities, one set of customers

Two perplexities on 600 customers' four behavior columns. Which neighborhoods does each map keep?

import numpy as np
import pandas as pd
from sklearn.preprocessing import StandardScaler
from sklearn.manifold import TSNE, trustworthiness

customers = pd.read_csv("data/customers_churn.csv").sample(600, random_state=7)
Z = StandardScaler().fit_transform(customers[["orders_12m", "avg_order_value", "discount_share", "return_rate"]])
for perp in [10, 50]:
    emb = TSNE(perplexity=perp, random_state=42).fit_transform(Z)
    print(f"perplexity {perp}: trustworthiness k=10 {trustworthiness(Z, emb, n_neighbors=10):.3f}"
          f"   k=50 {trustworthiness(Z, emb, n_neighbors=50):.3f}   x-span {np.ptp(emb[:, 0]):.0f}")
perplexity 10: trustworthiness k=10 0.991   k=50 0.977   x-span 120
perplexity 50: trustworthiness k=10 0.991   k=50 0.986   x-span 51

Both maps keep the 10 nearest neighbors equally well (0.991). The larger perplexity keeps more of the 50-neighbor structure (0.986 against 0.977), and its map is less than half as wide: the axis numbers have no units. Choose perplexity for the scale of structure you want to see.

Glossary

TermMeaning
LDALinear discriminant analysis: directions that separate labeled classes
Fisher's criterionBetween-class spread divided by within-class spread along a direction
scalings_The weights of LDA's axes
priorsAssumed class shares; they move LDA's decision threshold
shrinkagePulls a noisy covariance estimate toward a stabler shape
QDAQuadratic discriminant analysis: one covariance per class, curved boundaries
t-SNEA nonlinear map that keeps each point's neighbors close
perplexityRoughly how many neighbors each point attends to in t-SNE
UMAPA neighbor-graph map; n_neighbors and min_dist; has transform
trustworthiness0 to 1: penalizes map neighbors that were far apart in the original data
neighbors keptShare of each point's k nearest original neighbors that are also map neighbors
