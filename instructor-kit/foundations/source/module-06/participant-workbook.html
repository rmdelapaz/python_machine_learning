3.1

Linear and Logistic Regression

By the end you can
  • Explain what least squares does and fit LinearRegression, reading coef_ and intercept_ in the units of the data
  • Interpret a coefficient in a multiple regression as an effect "holding the other features constant", and spot when that reading breaks down
  • Use a log target with TransformedTargetRegressor when errors grow with the size of the prediction
  • Describe how logistic regression turns a weighted sum into a probability, and read its coefficients as log-odds and odds ratios
  • Fit a multiclass logistic regression and know which settings are current (C, l1_ratio) and which are gone
Key ideas
  • The ruler on the scatter plot. Least squares picks the line with the smallest sum of squared residuals; for one feature, slope = covariance / variance.
  • Read coefficients in units. -0.76 snow items per °F; an intercept can be meaningless (0 °F never happens).
  • Holding the others constant. A coefficient's meaning depends on what else is in the model: the price effect went from -0.53 to -1.61.
  • Lines extrapolate without limits and give each feature one slope for everyone.
  • A fanning residual plot means percent effects: model log1p(y) with TransformedTargetRegressor; read exp(coef) − 1 as a percentage.
  • Logistic regression: z = b₀ + b·x is the log-odds; p = 1 / (1 + e^−z); exp(coef) is an odds ratio; decision_function > 0 is the same as p > 0.5.
  • Current API: multiclass uses softmax automatically (multi_class is gone); the penalty is C and l1_ratio (penalty is deprecated).
  • Coefficients describe the model, not causes; twin columns split credit arbitrarily.
Worked example: three customers by hand

Two features, no scaler, so each coefficient is "per one unit": being an app user (0 or 1) and one more support ticket. Compute three customers' probabilities by hand.

import numpy as np
import pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split

customers = pd.read_csv("data/customers_churn.csv")
train, test = train_test_split(customers, test_size=0.25, stratify=customers["churned"], random_state=42)
cols = ["app_user", "support_tickets_12m"]
m = LogisticRegression().fit(train[cols], train["churned"])
b0 = m.intercept_[0]
b_app, b_tix = m.coef_[0]
print(f"z = {b0:.3f} {b_app:+.3f} * app_user {b_tix:+.3f} * tickets")
z = -1.630 -0.745 * app_user +0.258 * tickets
for app, tix in [(0, 0), (0, 4), (1, 4)]:
    z = b0 + b_app * app + b_tix * tix
    print(f"app_user={app}, tickets={tix}: z = {z:+.3f}, p = {1 / (1 + np.exp(-z)):.3f}")
real = train[train["support_tickets_12m"] >= 4].groupby("app_user")["churned"].mean()
print("real churn with 4+ tickets, by app_user:", real.round(3).to_dict())
app_user=0, tickets=0: z = -1.630, p = 0.164
app_user=0, tickets=4: z = -0.599, p = 0.354
app_user=1, tickets=4: z = -1.344, p = 0.207
real churn with 4+ tickets, by app_user: {0: 0.464, 1: 0.038}

The by-hand sigmoid gives the model's probabilities. But compare the last line: among customers with 4 or more tickets, 46.4% of non-app users churned and only 3.8% of app users. The model says 35% and 21%: with one slope per feature it cannot say "tickets matter only without the app". The interaction feature from Lesson 2.3 (tickets_no_app) is what lets a linear model say it.

3.2

Regularization and the Bias-Variance Trade-off

By the end you can
  • Explain underfitting and overfitting in terms of bias and variance, and recognize each from training and test errors
  • Add polynomial and interaction features with PolynomialFeatures and predict how many columns they create
  • Fit Ridge, Lasso and ElasticNet in a pipeline with scaling, and describe how their penalties differ
  • Choose the penalty strength alpha by cross-validation on the training data only, with RidgeCV and LassoCV
  • Build a regularized demand forecast with interactions and judge it against baselines on a later year
Key ideas
  • Three students: one rule for everything (bias), every answer memorized (variance), real patterns learned (the goal).
  • The diagnostic: high training and test error = too simple; low training and much higher test error = too flexible.
  • Expected test error = bias² + variance + noise. More flexibility trades bias for variance: the U.
  • PolynomialFeatures adds powers and products; the column count explodes with the degree.
  • Ridge charges for squared weights and shrinks them all; Lasso charges for absolute weights and zeros many; ElasticNet mixes both.
  • Penalties need scaled features, inside the pipeline.
  • Choose alpha by cross-validation on the training rows (RidgeCV, LassoCV), searched on a log scale; test once.
  • More data is also a regularizer. With few rows and many columns the penalty decides everything.
Worked example: a Ridge path

Watch Ridge pull the weights of a Snow demand model toward zero as alpha grows (features scaled, log target).

import numpy as np
import pandas as pd
from sklearn.linear_model import Ridge
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

demand = pd.read_csv("data/weekly_demand.csv")
snow = demand[(demand["year"] == 2024) & (demand["category"] == "Snow")]
cols = ["avg_high_temp_f", "discount_pct", "promo", "holiday_week"]
rows = {}
for alpha in [0.1, 100, 1_000, 10_000, 100_000]:
    m = make_pipeline(StandardScaler(), Ridge(alpha=alpha)).fit(snow[cols], np.log1p(snow["units_sold"]))
    rows[alpha] = m[-1].coef_
print(pd.DataFrame(rows, index=cols).round(3))
                 0.1       100.0     1000.0    10000.0   100000.0
avg_high_temp_f    -1.285    -1.012    -0.358    -0.049    -0.005
discount_pct        0.143     0.058    -0.028    -0.008    -0.001
promo               0.058     0.039    -0.016    -0.006    -0.001
holiday_week        0.151     0.105     0.022     0.002     0.000

Temperature carries the model, so it survives the longest; the small weights for discounts and promotions are pulled to zero quickly (and even change sign on the way). At alpha = 100,000 every weight is close to 0 and the model predicts almost the average week: maximum bias. None is ever exactly 0, which is the difference from Lasso.

Glossary

TermMeaning
least squaresThe rule that picks the line with the smallest sum of squared residuals
residualActual minus predicted, for one row
log targetModeling log1p(y) so effects act in percent; TransformedTargetRegressor converts back
log-oddsz = log(p / (1 − p)), the weighted sum inside logistic regression
odds ratioexp(coef): the factor by which the odds change for a one-unit increase
collinearityColumns that (almost) repeat each other, so their coefficients split credit arbitrarily
bias / varianceHow wrong the average fit is / how much the fit changes from sample to sample
regularizationA penalty on large weights that trades a little bias for less variance
Ridge / Lasso / ElasticNetSquared-weight penalty / absolute-weight penalty (zeros) / a mix
alpha, CPenalty strength in Ridge and Lasso; C in LogisticRegression is its inverse (small C, strong penalty)
