Session 6 12 self-check items Checkpoint 1 rubric Confidential

Warm-up

W1
RFECV's curve is 0.8328 at 6 columns and 0.8333 at 11; the folds disagree by about 0.02. How many columns do you keep, and why?
6: the difference is far smaller than the noise between folds, and the smaller set is cheaper and sturdier (the tolerance rule).
Why: Checkpoint 1 asks for honest comparisons like this one.
W2
Review $10, missed fraud $375. What does this print?
import numpy as np
p = np.array([0.02, 0.04, 0.3, 0.6])
print((p >= 10 / 375).astype(int))
[0 1 1 1]
Why: 10 / 375 ≈ 0.027, so every probability from 0.04 up is flagged. Valid only for calibrated probabilities.
W3
Where must SMOTE sit when you cross-validate, and what happens otherwise?
Inside an imblearn pipeline, after the preprocessing; resampling first put synthetic near-copies into the validation folds and reported AP 0.91 instead of about 0.49.
Why: Same rule as feature selection: a step that learns from y lives inside the folds.
W4
Why must an L1 model be scaled before it selects columns?
The penalty charges for the size of each weight, so without scaling it keeps columns in large units and drops columns in small units, whatever their usefulness.
Why: Lesson 3.2 today: every penalty needs scaled features.
W5
A class-weighted model's probabilities average 0.27 when the real fraud rate is 0.009. What does that change?
Its ranking is about the same, but the probabilities are no longer calibrated: a cost formula applied to them flags almost everything. Tune the threshold with cross-validation instead.
Why: Today's 3.1 shows where those probabilities come from: the sigmoid of the log-odds.

3.1 · Linear and Logistic Regression: self-check

Q1
What does this print?
from sklearn.linear_model import LinearRegression
line = LinearRegression().fit([[0], [1], [2]], [5, 8, 11])
print(line.predict([[10]]))
[35.]
Why: The three points lie exactly on y = 5 + 3x (slope 3, intercept 5), so at x = 10 the line gives 35. A line extrapolates without limits, whether or not x = 10 makes sense.
Q2
A demand model trained on log1p(units_sold) gives promo a coefficient of 0.420. What does that say?
A) A promo week sells 0.42 more units
B) A promo week sells about 52% more, for every product, whatever its size
C) A promo week sells 42% more
D) Promotions explain 42% of the variation in sales
Why: On a log target, effects multiply: exp(0.420) - 1 ≈ 0.52, so +52%. That is why the log model fits a fan-shaped residual plot better than "14 extra units of anything".
A is wrong: That would be a coefficient on units, not on log units.
C is wrong: Close for small coefficients only; at 0.42 the exact change is exp(0.42) - 1 = 52%.
D is wrong: That describes R², not a coefficient.
Q3
An unscaled logistic regression gives the 0/1 flag device_new a coefficient of 0.69. Which sentence is right?
A) A new device adds 0.69 to the probability of fraud
B) A new device makes fraud 69% more likely
C) A new device causes fraud
D) A new device multiplies the odds of fraud by about 2, holding the other features constant
Why: Logistic coefficients are changes in log-odds; exp(0.69) ≈ 2.0 is the odds ratio for a one-unit change, here from 0 to 1.
A is wrong: Coefficients act on the log-odds, not on the probability.
B is wrong: Odds double; how much the probability rises depends on where it started.
C is wrong: A model describes associations in the data, never causes.
Q4
The lesson project's naive price elasticity was -0.53; adding product_id made it -1.50. Why did it change so much?
A) The naive slope compared different products (cheap socks sell more units than tents), so price stood in for product type
B) Adding a column always makes coefficients larger
C) The log of the price was taken twice
D) The second model was fitted on fewer rows
Why: A coefficient means "holding the other features constant". With the product in the model, the price coefficient uses only each product's own price changes, its discounts. Season (product × month) then moves it to -1.61.
B is wrong: Coefficients can shrink, grow or flip sign when columns are added; here it is about what is held constant.
C is wrong: Both models use the same log price.
D is wrong: Both models use all rows.
Q5
A logistic regression's decision_function returns -1.0986 for one customer. What does this print?
import numpy as np
z = -1.0986
print(round(1 / (1 + np.exp(-z)), 2))
0.25
Why: The sigmoid of the log-odds: 1 / (1 + e^1.0986) = 1 / (1 + 3) = 0.25. Log-odds of -1.0986 = ln(1/3) means odds of 1 to 3. Negative z, so predict says 0.
Q6
Someone fits LogisticRegression() with the whole-number target units_sold. What happens?
A) ValueError: Unknown label type: continuous
B) It fits a regression line through the counts
C) No error: every distinct count becomes its own class, which is wrong and slow
D) It predicts probabilities of selling more than the mean
Why: Logistic regression is a classifier. Integers look like labels, so scikit-learn silently treats each count as a class; only a continuous target such as units_sold / 10 raises the error. Check model.classes_ if in doubt; use a regressor for numbers.
A is wrong: That error appears for continuous values, such as units divided by 10.
B is wrong: Logistic regression never fits a line to the target; it models class probabilities.
D is wrong: It knows nothing about the mean; each count is just a label.

3.1 · Linear and Logistic Regression: predict, then run

P1
Predict the output, then run it.
from sklearn.linear_model import LinearRegression
line = LinearRegression().fit([[0], [1], [2]], [1, 1, 4])
print(line.coef_.round(2), round(line.intercept_, 2), line.predict([[4]]).round(2))
[1.5] 0.5 [6.5]
Why: Least squares through (0, 1), (1, 1), (2, 4): slope 1.5, intercept 0.5 (the line passes through the averages, x̄ = 1, ȳ = 2). At x = 4: 0.5 + 1.5 × 4 = 6.5.
P2
Predict the output, then run it.
import numpy as np
z = np.log(3)            # log-odds: odds of 3 to 1
print(round(1 / (1 + np.exp(-z)), 2))
0.75
Why: Odds of 3 to 1 means p / (1 − p) = 3, so p = 0.75. The sigmoid of the log-odds turns odds back into a probability.

3.2 · Regularization and the Bias-Variance Trade-off: self-check

Q7
An interaction model trained on a 400-row pilot has training MAE 3.4 and test MAE 42.2. Which change is most likely to help?
A) Remove the penalty so the model can fit better
B) Add degree-3 terms to capture more patterns
C) Increase the Ridge penalty (alpha), chosen by cross-validation
D) Judge it on the training rows, where it does well
Why: A tiny training error with a huge test error is high variance. A penalty (or more data, or fewer columns) shrinks the weights that chase noise; in the lesson alpha = 10 cut the test MAE to 10.0.
A is wrong: Less penalty means more variance: the opposite of what is needed.
B is wrong: More columns add flexibility, and this model already has too much.
D is wrong: Training error alone says nothing about new weeks.
Q8
How many columns does this report?
import numpy as np
from sklearn.preprocessing import PolynomialFeatures
print(PolynomialFeatures(degree=2, include_bias=False).fit(np.zeros((1, 4))).n_output_features_)
14
Why: 4 originals, 4 squares and 6 products of pairs (4 × 3 / 2): 14. include_bias=False leaves out the column of ones; with interaction_only=True the squares go too (10).
Q9
Snow sales get the temperature twice, in °F and in °C. Ridge gives weights [-0.607, -0.607]; Lasso gives [-1.164, 0]. What follows?
A) Ridge shares the effect between the twins; Lasso keeps one twin and zeros the other, somewhat arbitrarily
B) Lasso is wrong and Ridge is right
C) The Celsius column does not matter, so temperature in °C has no effect on sales
D) The penalties need more scaling
Why: With perfectly correlated columns, Lasso's choice of which twin to keep depends on details such as column order. A zero means "redundant here", not "no effect". Elastic Net shares the weight again.
B is wrong: Both fit equally well; they divide the same effect differently.
C is wrong: The two columns hold the same information; Lasso simply needed only one of them.
D is wrong: The pipeline scaled both; the twins are the reason.
Q10
Without a scaler, Ridge(alpha=100) fits Snow sales with the price in dollars (R² 0.770) and with the price in thousands of dollars (R² 0.752). Why do the fits differ?
A) Prices in thousands are rounded
B) Ridge cannot use prices below 1
C) R² changes whenever the units change
D) In thousands the price needs a weight 1,000 times larger, and the penalty shrinks it hard
Why: The penalty adds up squared weights, so a column's units decide how much its effect costs. Results that change with units are a red flag: scale inside the pipeline.
A is wrong: Dividing by 1,000 loses no information.
B is wrong: Ridge accepts any numbers.
C is wrong: Plain least squares gives the same R² in any units; the penalty is what is unit-sensitive.
Q11
What does this print?
from sklearn.linear_model import Ridge
m = Ridge(alpha=1e6).fit([[0], [1], [2], [3]], [10, 12, 14, 16])
print(m.coef_.round(3), round(m.intercept_, 1))
[0.] 13.0
Why: A huge alpha pulls the slope to (almost) zero. The intercept is not penalized, so the model predicts the mean of y, 13.0, for every x: maximum bias.
Q12
RidgeCV chose alpha = 3.16 on the 400-row pilot but alpha = 1.0 on the full 5,088 rows of 2024. Why less penalty with more data?
A) Cross-validation is unreliable on small data, so the first number is wrong
B) More rows reduce variance on their own, so less penalty is needed to control it
C) Ridge always prefers alpha = 1
D) The full year has fewer columns
Why: More data is also a regularizer: with 5,088 rows the 489 columns are far less dangerous. That is why you choose alpha by cross-validation each time instead of reusing a number.
A is wrong: Both choices are sensible for their data; they differ because the data differ.
C is wrong: The default happens to be 1.0; RidgeCV searches the list it is given.
D is wrong: The design has 489 columns in both cases.

3.2 · Regularization and the Bias-Variance Trade-off: predict, then run

P3
Predict the output, then run it.
import numpy as np
from sklearn.preprocessing import PolynomialFeatures
pf = PolynomialFeatures(degree=2, interaction_only=True, include_bias=False).fit(np.zeros((1, 4)))
print(pf.n_output_features_)
10
Why: 4 originals plus 6 products of pairs (4 × 3 / 2); interaction_only=True leaves out the squares and include_bias=False the column of ones.
P4
Predict the output, then run it.
from sklearn.linear_model import LinearRegression, Ridge
X, y = [[0], [1], [2], [3]], [10, 12, 14, 16]
print(LinearRegression().fit(X, y).coef_, Ridge(alpha=10).fit(X, y).coef_.round(2))
[2.] [0.67]
Why: The points lie exactly on y = 10 + 2x, so least squares finds slope 2. Ridge with alpha = 10 pays for the weight and settles for 0.67: bias bought on purpose (here there is no variance to save).

Checkpoint 1: Rubric, Model Answer and Weak Answers

The question

Pinecrest's marketing team will email a win-back voucher to the customers a churn model flags. An email with a voucher costs $5; a churner nobody reaches costs about $50 of margin. A colleague's notebook (Part A of labs/module-06/checkpoint-1/checkpoint1_starter.py) reports about 95% accuracy. Plan what you will check; audit the colleague's code (one line per problem); rebuild an honest model in a pipeline, cross-validated against a baseline with a metric suited to a rare class, and choose who gets the email from the prices, on the training rows only; look at the test set once; report three sentences for the marketing lead.

Rubric. Five rows, four levels, 20 points. "Proficient" in every row (15 points) is a successful checkpoint. Circle one cell per row and write one sentence of advice.

The colleague's notebook prints colleague's accuracy: 0.947. Problems a full audit lists: (1) cancellation_reason is filled only for churners (625 of 625): a leak; (2) gaps filled with medians of all rows, get_dummies and the scaler fitted on all 6,000 rows before the split; (3) accuracy with no baseline (0.835 for doing nothing); (4) one unstratified split, no cross-validation; (5) predict at 0.5 ignores the $5 and $50 prices ($9,630 against $4,970).

Common weak answers and what they reveal
  • "Accuracy 0.85 after removing the leak, so the model works." Doing nothing scores 0.835. Ask for the baseline and a ranking metric.
  • The leak removed, but preprocessing still runs on all 6,000 rows (pd.get_dummies, StandardScaler). The test rows shaped the preprocessing. The number moves only a little, but it is the habit the checkpoint tests.
  • A threshold read off the test-set cost curve. That threshold is fitted to the test set. Ask which rows chose it.
  • The confusion-matrix order wrong (tn, fp, fn, tp). Costs come out absurd (tens of thousands). Ask them to price "email nobody" first: it must be 248 × $50 = $12,400.
  • SMOTE or class weights added "because churn is imbalanced", then the formula on those probabilities. The cut-off moves to almost everyone. Lesson 2.5's Mistake 3.
  • A report that lists steps ("I imputed, I scaled, I cross-validated"). Ask for the first sentence the marketing lead will read.

The Lesson Pages' Own Quick Quizzes

Lesson 3.1 · Linear and Logistic Regression
  1. B 2.0 1.0: the points lie exactly on y = 1 + 2x.
  2. A One SD more days multiplies the odds of churning by about exp(0.88) ≈ 2.4, others held constant.
  3. C Model log1p(units_sold) with TransformedTargetRegressor: the exponential is never negative.
  4. C A probability of 0.5: exactly on the boundary.
  5. A Predictions stay the same; the store and floor-area coefficients become arbitrary.
Lesson 3.2 · Regularization and the Bias-Variance Trade-off
  1. B High variance: it fits the training rows but does not generalize.
  2. C 9: three originals, three squares, three products.
  3. A All weights shrink toward zero; predictions approach a constant.
  4. B Nothing about floor area: Lasso kept its twin sqft.
  5. C RidgeCV with cross-validation on the training set, then score the test set once.

Exit Ticket

  1. 0.67 for discount_share: one standard deviation more discount reliance multiplies the odds of churning by about 1.96, other features held constant. It does not say discounts cause churn, nor that the probability rises by 0.67.
  2. Tiny training error, large test error: high variance (overfitting). Fixes: a stronger penalty chosen by CV, fewer or simpler features, more data.
  3. Scaling: the penalty charges for the size of each weight; without scaling, a feature's units decide how much it is penalized.

Common Wrong Answers and What They Reveal

  • Q2 A ("0.42 more units"). Forgets the log target. Ask what scale the model trained on.
  • Q3 A or B. Probability and odds mixed up. Compute one example: from p = 0.10 (odds 0.11) doubling the odds gives p ≈ 0.18, not 0.20 or 0.79.
  • Q6 A. Has seen the error in the lesson and assumes it always appears. Integers are silently treated as classes.
  • Q7 A or B. Thinks more flexibility fixes a bad test score. Draw the U.
  • Q9 A. "Lasso dropped it, so it does not matter": the same error as "dropped means irrelevant" in Lesson 2.4.
  • Exit ticket 1: "discounts cause churn". Ask whether anyone changed a customer's discounts and watched.
