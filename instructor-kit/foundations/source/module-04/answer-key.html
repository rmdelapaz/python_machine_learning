Warm-up

Retrieval from Session 3 (Lessons 1.4 and 2.1). Answers and what each checks:

W1
Pinecrest's care team calls 150 customers and 103 of them really were about to churn. Which metric is 103 / 150, and what does it answer? (Lesson 1.4)
Precision (at 150): of the customers we contacted, how many were real churners? Recall would divide by all real churners instead.
W2
What does this print? (Lesson 1.4)
from sklearn.metrics import precision_score, recall_score
y_true = [1, 1, 1, 0, 0, 0, 0, 0]
y_pred = [1, 1, 0, 1, 0, 0, 0, 0]
print(round(precision_score(y_true, y_pred), 3), round(recall_score(y_true, y_pred), 3))
0.667 0.667: two of the three flagged are churners (precision 2/3) and two of the three churners were flagged (recall 2/3).
W3
Lesson 1.4's project chose a threshold of 0.26. Why from out-of-fold probabilities on the training rows, and never from the test set? (Lesson 1.4)
The threshold is a setting learned from data. Choosing it on the test set lets the test set help build the model, so its score is no longer an honest preview. Out-of-fold probabilities give every training customer a score from a model that did not see them.
W4
What does this print? (Lesson 2.1)
from sklearn.preprocessing import OneHotEncoder
enc = OneHotEncoder(sparse_output=False, handle_unknown="ignore").fit([["Bend"], ["Boise"], ["Online"]])
print(enc.transform([["Reno"], ["Boise"]]))
Reno is unknown, so with handle_unknown="ignore" it becomes a row of zeros; Boise is the second learned category. The category list was learned in fit.
W5
Lesson 2.1 asked: to cross-validate its churn model, which objects must be refitted inside every fold, and in which order? (Lesson 2.1)
The whole ColumnTransformer (imputer, scalers, ordinal and one-hot encoders), then the model, on the training folds only; then transform-and-predict on the validation fold. Doing that by hand is error-prone: a Pipeline does exactly this, which is today's first lesson.

2.2 · Pipelines: self-check

Q1
A fitted pipeline make_pipeline(StandardScaler(), LogisticRegression()) is asked to predict_proba(X_new). What does the scaler step do with X_new?
A) fit_transform: the new rows are centered on their own mean
B) transform only, with the means and standard deviations it learned during fit
C) Nothing: scaling only happens during fit
D) It refits on the training rows and the new rows together
Why: During prediction every step except the last calls transform with what it learned in fit; nothing is refitted on the data being predicted. That is the whole reason a pipeline cannot leak.
A is wrong: Then a batch of ten new customers would be scaled against each other, and the same customer would get a different score in a different batch.
C is wrong: Without scaling, the model would receive raw numbers it was never trained on.
D is wrong: The pipeline does not keep the training rows; it keeps only what each step learned.
Q2
Which name sets the imputer's strategy in this pipeline?
pipe = Pipeline([
    ("prep", ColumnTransformer([
        ("num", make_pipeline(SimpleImputer(), StandardScaler()), ["email_opens_90d"]),
    ])),
    ("model", LogisticRegression()),
])
A) prep__simpleimputer__strategy
B) num__simpleimputer__strategy
C) prep_num_simpleimputer_strategy
D) prep__num__simpleimputer__strategy
Why: Read it as a path from the top: the step named prep, its branch named num, that branch's step simpleimputer (make_pipeline's automatic name), then the setting. Each level is joined by two underscores.
A is wrong: Skips the branch name num.
B is wrong: Starts below the top level: the pipeline itself has no step called num.
C is wrong: Single underscores are part of ordinary names; the separator is a double underscore.
Q3
What happens when this runs?
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
pipe = make_pipeline(StandardScaler(), LogisticRegression())
pipe.set_params(model__C=0.1)
A) ValueError: Invalid parameter 'model': make_pipeline named the step logisticregression
B) It sets C on the logistic regression
C) TypeError: C can only be set when the model is created
D) Nothing: the unknown setting is silently ignored
Why: make_pipeline names steps after their classes in lowercase, so the model step is logisticregression and the setting is logisticregression__C. The step is called model only when you name it yourself with Pipeline([...]). The message: ValueError: Invalid parameter 'model' for estimator Pipeline(s...
B is wrong: It would, with the right step name.
C is wrong: set_params can change any setting after creation.
D is wrong: scikit-learn refuses unknown settings loudly, and lists the valid ones.
Q4
Which of these steps could be applied to all training rows BEFORE cross-validation without changing the cross-validated score at all?
A) SimpleImputer(strategy="median")
B) TargetEncoder() on a high-cardinality column
C) FunctionTransformer(np.log1p)
D) SelectKBest(k=10) (keeps the columns most related to y)
Why: A fixed function learns nothing from the data (it is stateless), so applying it early or inside the folds gives the identical result. Lab 2.2 B measures it: a difference of +0.00000.
A is wrong: Learns a median from the rows it sees, so the validation rows would shape it (a tiny leak, but a leak).
B is wrong: Learns from the target: the biggest leaks of all (0.913 vs 0.583 in the lab).
D is wrong: Selection looks at y, so choosing columns on all rows lets the validation rows vote (Lesson 2.4).
Q5
What does this print?
import numpy as np
from sklearn.preprocessing import FunctionTransformer
log = FunctionTransformer(np.log1p).fit([[0.0], [9.0]])
print(log.transform([[99.0]]).round(3))
[[4.605]]
Why: FunctionTransformer with a fixed function is stateless: fit learns nothing from 0 and 9, and transform applies log(1 + 99) = log(100) = 4.605 to whatever arrives.
Q6
The IT team reloads churn_pipeline.joblib and sends next month's records, but their export leaves out the email_opens_90d column. What happens?
A) The imputer fills the whole column with the training median
B) The pipeline uses the other 15 columns and ignores the missing one
C) It predicts the baseline churn rate for every customer
D) ValueError: columns are missing: {'email_opens_90d'}: send the column, empty (NaN) where unknown
Why: The ColumnTransformer selects columns by name and refuses a record that lacks one it was fitted with (reloaded.feature_names_in_ lists them). A column that is present but empty is fine: the imputer handles NaN.
A is wrong: The imputer fills gaps INSIDE a column; it cannot invent a missing column.
B is wrong: The model's weights assume every column; nothing silently drops one.
C is wrong: Nothing falls back to a baseline; it raises an error.

2.2 · Pipelines: predict, then run

P1
Predict the output, then run it.
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
pipe = make_pipeline(SimpleImputer(), StandardScaler(), LogisticRegression())
print(list(pipe.named_steps))
print(len(pipe[:-1]))
['simpleimputer', 'standardscaler', 'logisticregression'] 2
Why: make_pipeline names each step after its class in lowercase. pipe[:-1] is a pipeline of every step before the model: two steps.
P2
Predict the output, then run it.
from sklearn.impute import SimpleImputer
imp = SimpleImputer(strategy="median").fit([[1.0], [2.0], [9.0]])
print(imp.transform([[None], [100.0]]).ravel())
[ 2. 100.]
Why: The median of 1, 2 and 9 is 2. The gap gets the training median; 100 is not a gap, so it passes through unchanged. Nothing is learned from the new rows.

2.3 · Creating Features: self-check

Q7
What does this print?
import pandas as pd
df = pd.DataFrame({"store": ["A", "A", "B", "B", "A"], "units": [5, 7, 9, 4, 6]})
print(df.groupby("store")["units"].shift(1).tolist())
[nan, 5.0, nan, 9.0, 7.0]
Why: shift(1) within each store: each row gets the previous value of ITS OWN store. Rows 0 and 2 are the first of stores A and B (no history: NaN); row 3 gets B's 9; row 4 gets A's previous value, 7 (row 1), not B's 4. That is why lags are always built per series.
Q8
Churn is 32% for customers under 6 months, about 8 to 11% in the middle years and 21.5% above 72 months, yet a logistic regression on the raw columns gives tenure only a small weight. Why?
A) Tenure does not really matter for churn
B) Tenure was not scaled
C) A straight line through a U-shape is nearly flat; flags such as new_customer and veteran let the model express it
D) Tenure is redundant with signup_date
Why: A linear model gives each column one slope. High at both ends and low in the middle averages out to almost no slope. With two flags, each arm of the U gets its own weight (0.92 and 0.49 in the lesson).
A is wrong: The tenure table shows a big effect, just not a straight-line one.
B is wrong: The lesson's pipelines all scale; scaling changes units, not shape.
D is wrong: It is (the workbook example shows a correlation of 1.0), but that does not explain the weight, and signup_date is not in the model.
Q9
What does tickets_no_app = support_tickets_12m * (1 - app_user) let a linear model do?
A) Give support tickets their own weight for customers without the app
B) Remove app users from the training data
C) Count every app user's tickets twice
D) Replace app_user, which can then be dropped
Why: The product equals the ticket count for non-app customers and 0 for app users, so its weight describes tickets where they matter (churn 14% to 46% without the app, flat with it). That is an interaction term.
B is wrong: Every row stays; app users just get 0 in the new column.
C is wrong: App users get 0, not double.
D is wrong: The interaction is added next to app_user, which still carries its own effect.
Q10
What does this print?
import numpy as np
months = np.array([3, 6, 12])
print(np.cos(2 * np.pi * months / 12).round(2))
[ 0. -1. 1.]
Why: cos(2π·3/12) = cos(π/2) = 0, cos(π) = -1, cos(2π) = 1. December (12) lands on the same point of the circle as "month 0", one step from January: the encoding wraps around. Cosine alone is not enough, though: April and August both have a cosine of -0.5. The sine column tells them apart.
Q11
An average of units sold per product, store and month computed from BOTH years forecasts 2025 with MAE 9.87; computed from 2024 only, 11.36. Why is 9.87 not a real improvement?
A) Averages over more rows always overfit
B) The 2025 weeks being predicted helped compute their own feature
C) MAE rewards forecasts that are too low
D) 2025 has fewer weeks than 2024
Why: Half of every average now comes from the test answers. On the day a 2025 forecast is made, those weeks have not happened. Compute target aggregates from the training rows only (or per fold, with TargetEncoder).
A is wrong: More honest rows would help; the problem is WHICH rows.
C is wrong: MAE treats over- and under-forecasts alike.
D is wrong: The row counts (5,088 and 4,896) do not explain an error that drops by 13%.
Q12
What does this print?
import pandas as pd
df = pd.DataFrame({"returns": [1, 0, 2], "tickets": [2, 0, 0]})
print((df["returns"] / df["tickets"]).tolist())
A) [0.5, 0.0, 0.0]
B) A ZeroDivisionError
C) [0.5, nan, inf]
D) [0.5, nan, nan]
Why: pandas does not raise on division by zero: 0 / 0 is NaN and 2 / 0 is infinity. The error appears only later, inside the model (Input X contains infinity). Divide by something that cannot be 0, such as tickets + 1.
A is wrong: pandas does not replace the result with 0.
B is wrong: Plain Python integers raise; pandas Series do not.
D is wrong: Only 0 / 0 is undefined; a positive number over 0 is infinity.

2.3 · Creating Features: predict, then run

P3
Predict the output, then run it.
import pandas as pd
df = pd.DataFrame({"tickets": [0, 2, 3, 1], "app_user": [1, 1, 0, 0]})
df["tickets_no_app"] = df["tickets"] * (1 - df["app_user"])
print(df["tickets_no_app"].tolist())
[0, 0, 3, 1]
Why: Rows 0 and 1 are app users (1 - 1 = 0), so 0 whatever their tickets; rows 2 and 3 keep their ticket counts 3 and 1.

Predict the output, then run it.
import pandas as pd
days = pd.to_datetime(pd.Series(["2025-06-28", "2025-06-30", "2025-07-04"]))
print(days.dt.dayofweek.tolist(), days.dt.month.tolist())
[5, 0, 4] [6, 6, 7]
Why: Monday is 0, so Saturday June 28 is 5, Monday June 30 is 0 and Friday July 4 is 4; the months are 6, 6 and 7.

Lab 2.2-B: labs/module-04/l2_2-pipelines/leak_size_starter.py → leak_size_solution.py

The solution prints:

1016 distinct dollar amounts in train; 434 of them occur 5 times or fewer
target rate  before CV 0.913   inside pipeline 0.583   test 0.568
scaler       before CV 0.8613  inside pipeline 0.8613  difference -0.00001
log1p        before CV 0.8617  inside pipeline 0.8617  difference +0.00000

learns from y, few rows per value : huge lie  (put it in the pipeline, or drop the idea)

learns nothing (stateless)        : no lie    (safe anywhere; the pipeline costs nothing)

Reading it: the per-amount fraud rate is the lesson's signup-date leak on new data. Most amounts occur only a handful of times, so "the fraud rate of this amount" is mostly the row's own label: 0.913. Inside the pipeline the encoder never sees a validation row's label: 0.583, and the test agrees (0.568). The amount does carry a little real signal (gift cards come in $25 steps). The scaler leak exists but is invisible at this size (-0.00001); the log step cannot leak at all. The habit, not the judgment: put every learning step in the pipeline.

The Lesson Pages' Own Quick Quizzes

Lesson 2.2 · Pipelines
  1. C It calls fit_transform on X_train and passes the result to the model: every step but the last fits and transforms during fit.
  2. A quiz_pipe.set_params(logisticregression__C=0.1): make_pipeline names the step after its class, and the separator is two underscores.
  3. B The rates were computed before the folds were split, so each validation row's own label went into its feature.
  4. A It fills the gap with the median it learned from the training rows: prediction only transforms.
  5. B No: a pipeline keeps rows apart, but it cannot know that a column comes from the future.
Lesson 2.3 · Creating Features
  1. B [nan, nan, 6.0, 8.0]: shift moves 5, 7, 9 down one place, then each window of two averages (5, 7) and (7, 9).
  2. C Categories have opposite seasons, so one shared effect per month averages them away.
  3. A The training rows only: choosing a threshold is learning from data.
  4. C The window includes the week being predicted, so the feature contains the answer.
  5. A Sine alone gives two different months the same value (for example April and August); cosine tells them apart.

Exit Ticket

  1. Pipeline: it fits each step on the training rows and only transforms at prediction time (no remembering the order); cross-validation and grid search refit every step inside each fold; one object saves to one file. It cannot stop a leaky COLUMN (such as cancellation_reason) that you put in the feature list.
  2. 0.930 vs 0.571: the rates were computed with every training label, so each validation row's feature contained its own answer (most signup dates have one or two customers). TargetEncoder inside a pipeline, refitted per fold: honest CV 0.586, which matches the test.
  3. A feature and its proof: e.g. lapsed_150 (a jump), new_customer/veteran (a U-shape), tickets_no_app or night_new_device (an interaction), category × month (a season per category). Proof = cross-validation against the plain model (0.829 → 0.883 for churn; 11.23 → 9.39 MAE for demand), then one test check.

Common Wrong Answers and What They Reveal

  • Q1 A (fit_transform on new rows). The learner still pictures preprocessing as something that happens to whatever data arrives. Use the batch argument: the same customer would get a different score in a different batch.
  • Q2 A or B. Skips a level of nesting. Have them print list(pipe.get_params()) and find the key; the path always starts at the top-level step.
  • Q3 B ("it sets C"). Assumes the step is called model everywhere. Only Pipeline([...]) with your own names gives model.
  • Q4 A (the imputer). Thinks "it does not look at y" means "it cannot leak". It still learns a median from the validation rows: a tiny leak, but not zero. Only a step that learns nothing is exactly safe.
  • Q8 A ("tenure does not matter"). Reads a small weight as no effect. Show the tenure table next to the weight: a shape the model cannot draw.
  • Q11 A ("averages overfit"). Misses the timing. Ask: "Were the 2025 weeks known when the forecast was made?"
  • Exit ticket 1: "a pipeline prevents all leaks". The most important misconception of the day; point back to the selector that grabbed cancellation_reason (0.937).
