Warm-up: Session 2 in Five Questions

Retrieval, not graded. The fifth question checks the 1.3 "Before the Next Lesson" task.

W1
Why does every churn split in this course pass stratify=y?
It keeps the churn share (16.5%) the same in the training and test parts. Without it the class balance wobbles from split to split, and with it the baseline and every score wobble too.
From: Lesson 1.2.
W2
In the honest-evaluation project, a depth-2 tree on the single column has_reason scored 0.942 on validation against a baseline of 0.835. What do you do, and what do you check first?
Treat it as a leak suspect: far too good for one column. Check when and how it is recorded (it is filled only when an account is closed, after the outcome), then drop it. A high score alone is not proof; the recording process is.
From: Lesson 1.2.
W3
Why cross-validate make_pipeline(StandardScaler(), LogisticRegression()) instead of scaling X_train once and cross-validating the model on the scaled table?
The pipeline refits the scaler on the training folds of every round. Scaling first lets each validation fold shape the mean and standard deviation: a small, hidden leak, and a big one when the preprocessing learns more (today's imputers and encoders).
From: Lesson 1.3.
W4
What does cross_val_predict(model, X_train, y_train, cv=cv, method="predict_proba")[:, 1] give you, and why is it honest?
One churn probability per training customer, each from the fold model that did NOT train on that customer. Today's project chooses its decision threshold from exactly these out-of-fold probabilities, so the test set stays sealed.
From: Lesson 1.3.
W5
You reran the bake-off with scoring=["accuracy", "roc_auc", "f1"]. What did the baseline score on accuracy and on F1, and why so different?
Accuracy 0.835, ROC AUC 0.5, F1 0.0. The baseline never predicts churn, so it has no true positives: recall is 0 and precision is 0/0 (scikit-learn reports 0 with a warning), so F1 is 0. Accuracy rewards the 83.5% it gets right by saying "stays". That gap is today's first topic.
From: Homework check (1.3, Before the Next Lesson).

1.4 · Metrics for Classification and Regression: self-check

Q1
A churn model's confusion matrix on a test set: TN 880, FP 60, FN 20, TP 40. What are its precision and recall?
A) precision 0.667, recall 0.400
B) precision 0.400, recall 0.667
C) precision 0.978, recall 0.936
D) precision 0.920, recall 0.400
Why: Precision = TP / (TP + FP) = 40 / 100 = 0.400: of the customers flagged, four in ten were really leaving. Recall = TP / (TP + FN) = 40 / 60 = 0.667: two thirds of the real churners were found.
A is wrong: Precision and recall swapped: exactly what swapping the arguments of a metric function does, silently.
C is wrong: Those treat "stays" as the positive class: 880 / 900 = 0.978 and 880 / 940 = 0.936.
D is wrong: 0.920 is the accuracy (920 of 1,000), which counts the 880 easy true negatives.
Q2
What does this print?
from sklearn.metrics import precision_score, recall_score
y_true = [1, 0, 1, 1, 0, 0, 0, 1]
y_pred = [1, 1, 0, 1, 0, 0, 0, 0]
print(round(precision_score(y_true, y_pred), 3), recall_score(y_true, y_pred))
0.667 0.5
Why: Truth first, prediction second. Three customers are flagged (positions 0, 1, 3); two of them really churned, so precision is 2 / 3 = 0.667. Four customers really churned (0, 2, 3, 7) and two of them were flagged, so recall is 2 / 4 = 0.5. scikit-learn 1.9 returns plain floats, so round() works and .round() would not.
Q3
You want the decision threshold that maximizes the retention campaign's profit. Where should the probabilities you search over come from?
A) The test set: it is the most realistic data you have
B) The training rows, from the fitted model's own predict_proba(X_train)
C) The training rows, out of fold: cross_val_predict(..., method="predict_proba") or TunedThresholdClassifierCV
D) Nowhere: always use 0.5, because the model was trained for it
Why: Each training customer gets a probability from a model that never saw them, so the profit curve is honest, and the test set stays untouched for one final check. TunedThresholdClassifierCV does exactly this internally.
A is wrong: Choosing the threshold on the test set is tuning on the test set: the final profit is then flattered.
B is wrong: A model scored on the rows it learned from is over-confident (a forest especially), so the curve and its peak are wrong.
D is wrong: 0.5 is a default, not a decision. The lesson's tuned threshold (0.245) earns $3,555 against $2,280 at 0.5 with the same model.
Q4
What does this print?
from sklearn.metrics import roc_auc_score
y = [0, 0, 1, 1]
print(roc_auc_score(y, [0, 1, 1, 1]), roc_auc_score(y, [0.2, 0.6, 0.7, 0.9]))
A) 0.75 1.0
B) 1.0 1.0
C) 0.5 1.0
D) ValueError: ROC AUC needs probabilities
Why: ROC AUC is the share of (positive, negative) pairs in which the positive scores higher, ties counting one half. With hard labels the second negative ties with both positives: (1 + 1 + 0.5 + 0.5) / 4 = 0.75. With probabilities every positive beats every negative: 1.0. Labels throw ranking information away, without any error.
B is wrong: The labels cannot separate the negative scored 1 from the two positives.
C is wrong: 0.5 would be a coin flip; the labels still separate one negative correctly.
D is wrong: Nothing checks that the scores are probabilities, which is why this mistake is silent.
Q5
A retention offer costs $20 and reaching a real churner is worth $80. If the model's probabilities were perfectly calibrated, whom should Pinecrest contact?
A) Everyone predicted to churn at the default threshold of 0.5
B) Nobody: each offer costs money
C) The customers with a churn probability of at least 0.80
D) The customers with a churn probability of at least 0.25
Why: An offer to a customer with probability p is worth 80 × p on average and costs 20, so it pays when p ≥ 20 / 80 = 0.25, the break-even probability. Real probabilities are only roughly calibrated, which is why the lesson measures profit on out-of-fold probabilities instead of trusting the formula.
A is wrong: 0.5 ignores the costs: everyone between 0.25 and 0.5 is a profitable call left unmade.
B is wrong: Contacting nobody earns 0; contacting the right customers earns more.
C is wrong: 0.80 is the value, not the break-even; it would skip most profitable calls.
Q6
What does this print?
from sklearn.metrics import mean_absolute_error, root_mean_squared_error
y_true = [10, 20, 30, 40]
y_pred = [12, 18, 30, 50]
print(mean_absolute_error(y_true, y_pred), round(root_mean_squared_error(y_true, y_pred), 2))
3.5 5.2
Why: The errors are 2, 2, 0 and 10. MAE = 14 / 4 = 3.5 units. RMSE = √((4 + 4 + 0 + 100) / 4) = √27 ≈ 5.2: the one big miss counts far more once squared, so RMSE is above MAE.

1.4 · Metrics for Classification and Regression: predict, then run

P1
Predict the output, then run it.
import numpy as np
proba = np.array([0.9, 0.7, 0.4, 0.3, 0.2, 0.1])
truth = np.array([1, 0, 1, 1, 0, 0])
for t in [0.5, 0.25]:
    flagged = (proba >= t).astype(int)
    print(t, flagged.sum(), (flagged & truth).sum())
0.5 2 1 0.25 4 3
Why: At 0.5 two customers are flagged (0.9 and 0.7) and one of them really churned. At 0.25 four are flagged and three of them churned. Recall rises from 1/3 to 3/3, and here precision rises too (1/2 to 3/4), because the two extra flags happen to be churners: "lower threshold, lower precision" is the usual direction, not a law, and six customers are a tiny sample.
P2
Predict the output, then run it.
from sklearn.metrics import mean_absolute_error, r2_score
y = [2, 4, 6, 8]
print(r2_score(y, [5, 5, 5, 5]), mean_absolute_error(y, [5, 5, 5, 5]))
0.0 2.0
Why: Predicting the mean (5) explains none of the variation: R² is exactly 0.0. The misses are 3, 1, 1 and 3, so the MAE is 2.0.

2.1 · Impute, Scale and Encode: self-check

Q7
What does this print?
import pandas as pd
from sklearn.preprocessing import OneHotEncoder
enc = OneHotEncoder(sparse_output=False, handle_unknown="ignore")
enc.fit(pd.DataFrame({"store": ["Bend", "Boise", "Bend"]}))
print(enc.transform(pd.DataFrame({"store": ["Boise", "Reno"]})))
A) [[0. 1. 0.] [0. 0. 1.]] (a new Reno column)
B) ValueError: Found unknown categories ['Reno']
C) [[0. 1.] [0. 0.]]
D) [[1. 0.] [0. 0.]]
Why: The encoder learned two categories, Bend and Boise, in sorted order. Boise gets a 1 in the second column. Reno was never seen, and with handle_unknown="ignore" it becomes all zeros: "none of the stores I know".
A is wrong: An encoder never adds columns after fit; the output always has the training columns.
B is wrong: That is the default, handle_unknown="error".
D is wrong: Columns follow the sorted categories: Bend first, Boise second.
Q8
What does this print?
import numpy as np
from sklearn.impute import SimpleImputer
imp = SimpleImputer(strategy="mean", add_indicator=True).fit([[2.0], [np.nan], [4.0], [9.0]])
print(imp.transform([[np.nan], [1.0]]))
[[5. 1.] [1. 0.]]
Why: The imputer learns the mean of the three known values, (2 + 4 + 9) / 3 = 5, and adds an indicator column because the training column had a gap. The first new row was missing: filled with 5 and flagged 1. The second was present: kept (1.0) and flagged 0.
Q9
After StandardScaler, days_since_last_order still has a skew of 1.71, the same as the raw column. Why?
A) Scaling changes the units, not the shape; a log transform such as np.log1p changes the shape
B) The scaler was fitted on the test rows instead of the training rows
C) StandardScaler only removes skew when there are no outliers
D) Skew cannot be measured on scaled data
Why: (x − mean) / sd moves and stretches every value by the same amounts, so the histogram keeps its shape and only the numbers on the axis change. np.log1p squeezes the long tail: skew −0.19.
B is wrong: Fitting on other rows would change the center, not the shape.
C is wrong: No scaler removes skew; RobustScaler only limits the pull of outliers on the center and spread.
D is wrong: Skew is unit-free, which is exactly why it comes out identical.
Q10
What does this print?
from sklearn.preprocessing import OrdinalEncoder
enc = OrdinalEncoder().fit([["Small"], ["Medium"], ["Large"]])
print(enc.transform([["Small"], ["Large"]]).ravel())
A) [0. 2.]
B) [2. 1.]
C) [1. 0.]
D) [2. 0.]
Why: Without categories=, OrdinalEncoder sorts alphabetically: Large 0, Medium 1, Small 2. So Small is 2 and Large is 0, the reverse of the size order, and nothing warns you. Spell the order out: OrdinalEncoder(categories=[["Small", "Medium", "Large"]]).
A is wrong: That is the order you meant (Small 0, Large 2), which the encoder does not know.
B is wrong: Medium is 1, but it is not asked for.
C is wrong: Neither code matches the alphabetical order.
Q11
In a ColumnTransformer, the email_opens_90d column needs its gaps filled AND then scaling. How do you do it?
A) Two branches on the same column: one with the imputer, one with the scaler
B) One branch whose transformer is make_pipeline(SimpleImputer(...), StandardScaler())
C) Put the scaler in the branch and fill the gaps in pandas on the whole table before splitting
D) Set remainder="passthrough" so the scaler runs after the imputer
Why: Branches run side by side, each on the raw columns it is given. Steps that must run one after another go into a small pipeline inside one branch: fit fits the imputer, passes its output to the scaler, and fits that too.
A is wrong: Two branches would produce two separate copies of the column (one filled but unscaled, one scaled but still with gaps, which fails).
C is wrong: Filling before the split lets the test rows shape the fill value: a leak, and no answer for next month's customers.
D is wrong: remainder only decides what happens to unlisted columns.
Q12
What does this print?
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
df = pd.DataFrame({"spend": [10.0, 20.0, 30.0], "store": ["Bend", "Boise", "Bend"],
                   "customer_id": ["C1", "C2", "C3"]})
ct = ColumnTransformer([("num", StandardScaler(), ["spend"]),
                        ("cat", OneHotEncoder(sparse_output=False), ["store"])])
print(ct.fit_transform(df).shape, ct.get_feature_names_out().tolist())
(3, 3) ['num__spend', 'cat__store_Bend', 'cat__store_Boise']
Why: Each branch fits on its own columns and the outputs sit side by side: one scaled number plus one column per store (Bend, Boise), named branch__column. customer_id is in no branch, so the default remainder="drop" leaves it out: a safety feature, since an unlisted column (an ID, or a leak) cannot sneak into the model.

Common Wrong Answers and What They Reveal

  • Q1 A (precision 0.667, recall 0.400). Precision and recall swapped in their head, the same thing a swapped (y_pred, y_true) does in code. Use the questions: "of those we called" (precision), "of those who left" (recall).
  • Q3 A or B (test set, or in-sample training probabilities). Has the idea of tuning a threshold but not of where it may be tuned. In-sample is the subtle one: a forest scored on its own training rows is far too confident.
  • Q4 C (0.5 1.0). Thinks labels give a coin flip. Count the pairs with the learner, ties as halves.
  • Q5 A or C. Either ignores the costs (0.5) or confuses value with break-even (0.80). Write the expected value of one call: 80 × p − 20.
  • Q7 A (a new Reno column). Expects the encoder to grow. The output always has the training columns, which is the whole point of a fitted encoder.
  • Q10 A ([0. 2.]). Assumes the encoder knows the intended order. It never does: spell it out.
  • Q11 A (two branches). Thinks branches run in sequence. Draw the ColumnTransformer diagram: branches side by side, each on the raw columns.
  • Exit ticket 2: "because the test set is smaller". Misses the point about unseen data. Return to the dress-rehearsal rule from Lesson 1.2.
