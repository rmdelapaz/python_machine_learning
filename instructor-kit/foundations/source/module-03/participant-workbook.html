1.4

Metrics for Classification and Regression

By the end you can
  • Read a confusion matrix and compute precision, recall and F1, saying what each means for Pinecrest's retention team
  • Move a classifier's decision threshold and explain the precision-recall trade-off it controls
  • Use ROC AUC and average precision to judge how well a model ranks, and know when the precision-recall view is the honest one
  • Choose a threshold from business costs with out-of-fold probabilities or TunedThresholdClassifierCV, without peeking at the test set
  • Report MAE, RMSE and R² for a regression against a baseline, and avoid the MAPE trap on zero sales
Key ideas
  • The smoke alarm. Recall: when there is a fire, does it go off? Precision: when it goes off, is there a fire? The threshold: how sensitive to set it, which depends on what each mistake costs.
  • The confusion matrix counts TN, FP, FN and TP (rows: the truth; columns: the prediction). confusion_matrix(y_test, y_pred).ravel() gives them in that order.
  • Precision = TP / (TP + FP), "of those we called, how many were leaving?"; recall = TP / (TP + FN), "of those leaving, how many did we call?"; F1 is their harmonic mean.
  • The threshold is a decision, not a property of the model. Lower it: recall up, precision down. FixedThresholdClassifier saves a threshold with the model. Never choose it on the test set.
  • ROC AUC = the chance a random churner outranks a random stayer (0.5 random, 1.0 perfect). Average precision summarizes the precision-recall curve; its random baseline is the positive rate (0.165 churn, about 0.009 fraud). For rare positives it is the more honest number.
  • Thresholds from costs. Profit = value × TP − cost × (TP + FP); break-even probability = cost / value. Choose on out-of-fold probabilities, or with TunedThresholdClassifierCV(model, scoring=make_scorer(profit), cv=cv), then test once.
  • Regression: MAE (average miss, in units), RMSE (punishes big misses, always at least the MAE), R² (against predicting the mean). Always next to a naive baseline. MAPE explodes when true values can be 0.
  • Metric functions take (y_true, y_pred), AUC needs scores not labels, and in scikit-learn 1.9 they return plain floats (round(x, 3)).
Worked example: one threshold, two business answers

A small tree on three columns, so you can follow every number. The question: what does moving the threshold from 0.5 to 0.3 do to the retention team's calls, and to its profit at $15 per offer and $60 per churner reached?

import pandas as pd
from sklearn.metrics import confusion_matrix, precision_score, recall_score
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
customers = pd.read_csv("data/customers_churn.csv")
X = customers[["days_since_last_order", "discount_share", "tenure_months"]]
y = customers["churned"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, stratify=y, random_state=42)
tree = DecisionTreeClassifier(max_depth=4, random_state=42).fit(X_train, y_train)
proba = tree.predict_proba(X_test)[:, 1]
for t in [0.5, 0.3]:
    flagged = (proba >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_test, flagged).ravel()
    print(f"threshold {t}: flagged {flagged.sum()}  TP {tp}  FP {fp}  FN {fn}  "
          f"precision {precision_score(y_test, flagged):.3f}  recall {recall_score(y_test, flagged):.3f}")
threshold 0.5: flagged 126  TP 87  FP 39  FN 161  precision 0.690  recall 0.351
threshold 0.3: flagged 274  TP 152  FP 122  FN 96  precision 0.555  recall 0.613

Read the first line as the care team would: 126 calls, 87 reach real churners, 39 are wasted, and 161 churners are missed. Lowering the threshold to 0.3 more than doubles the calls (274) and finds 152 churners: recall rises from 0.351 to 0.613 while precision falls from 0.690 to 0.555. Now put money on it.

for t in [0.5, 0.3]:
    flagged = (proba >= t).astype(int)
    tp = ((flagged == 1) & (y_test == 1)).sum()
    print(f"threshold {t}: profit {60 * tp - 15 * flagged.sum():,} dollars")
threshold 0.5: profit 3,330 dollars
threshold 0.3: profit 5,010 dollars

The lower threshold earns more, because $60 for a churner reached is worth four wasted $15 offers. One caution: this example compares thresholds on the TEST set only to show the trade-off. To CHOOSE a threshold, use out-of-fold training probabilities, as the lesson project does.

2.1

Impute, Scale and Encode

By the end you can
  • Fill missing values with SimpleImputer, and keep the fact that a value was missing with add_indicator=True
  • Choose between StandardScaler, MinMaxScaler, RobustScaler and a log transform, and explain what each one changes
  • Encode categories with OneHotEncoder (including categories never seen in training) and ordered categories with OrdinalEncoder
  • Build a ColumnTransformer that sends each group of columns to the right transformer, fitted on the training data only
  • Train a model on all 16 usable churn columns, not just the 10 clean numeric ones
Key ideas
  • Mise en place. Each kind of column gets its own treatment: gaps → imputer, units → scaler, words → encoder. The recipe is learned from the training rows, then applied unchanged to the test rows and every new customer.
  • Ask what a gap means before filling it. Customers with no email count churned at 25.3% against 15.6%: the gap is a clue.
  • SimpleImputer fills with a learned value (statistics_): median for skewed numbers, most_frequent or a constant such as "unknown" for text. add_indicator=True keeps a 0/1 "was missing" column.
  • Scalers change units, not shape. StandardScaler (mean 0, sd 1), MinMaxScaler (0 to 1), RobustScaler (median 0, interquartile range 1; resists outliers). A log (np.log1p) changes the shape. Trees need neither.
  • OneHotEncoder(sparse_output=False, handle_unknown="ignore"): one 0/1 column per category; an unseen category becomes all zeros; a gap becomes its own column. Never pd.get_dummies on new data.
  • OrdinalEncoder only for ordered categories, always with the order spelled out: categories=[["Basic", "Silver", "Gold"]]. The default is alphabetical.
  • ColumnTransformer: a list of (name, transformer, columns); branches run side by side, unlisted columns are dropped. Steps that must run one after another go in a make_pipeline inside one branch.
  • fit_transform on train, transform on everything else. Check it: scaled training columns have a mean of exactly 0; test columns only close to 0.
Worked example: the product catalog, ready for a model

A different Pinecrest table, the product catalog, prepared with the same tools. No model today: the goal is a numeric table and a check that a brand-new product still gets a row.

import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import MinMaxScaler, OneHotEncoder
products = pd.read_csv("data/products_ml.csv")
print(products.shape)
print(products[["brand", "price", "launch_year", "primary_activity"]].head(3))
(200, 8)
            brand   price  launch_year primary_activity
0  Larkspur Ridge  220.95         2020           hiking
1  Larkspur Ridge  164.95         2025          running
2  Larkspur Ridge  165.95         2023         climbing

Two numbers on very different scales, and two text columns with no order. MinMaxScaler puts both numbers on 0 to 1; OneHotEncoder makes one column per brand and per activity.

prep = ColumnTransformer([
    ("nums", MinMaxScaler(), ["price", "launch_year"]),
    ("cats", OneHotEncoder(sparse_output=False, handle_unknown="ignore"), ["brand", "primary_activity"]),
]).set_output(transform="pandas")
table = prep.fit_transform(products)
print(table.shape)
print(table.columns[:5].tolist())
(200, 16)
['nums__price', 'nums__launch_year', 'cats__brand_Cedar Notch', 'cats__brand_Granite Fork', 'cats__brand_Juniper Vane']

Eight columns became 16: two scaled numbers, 8 brands and 6 activities. The name and the category were not listed, so they were dropped. Now a product launched next year by a brand the catalog has never seen:

new = pd.DataFrame({"price": [99.95], "launch_year": [2026], "brand": ["Brand-New Co"],
                    "primary_activity": ["hiking"]})
row = prep.transform(new)
print(row[["nums__price", "nums__launch_year"]].round(3).to_dict("records"))
print("brand columns set:", int(row.filter(like="cats__brand").sum(axis=1).iloc[0]),
      "| activity columns set:", int(row.filter(like="cats__primary_activity").sum(axis=1).iloc[0]))
[{'nums__price': 0.127, 'nums__launch_year': 1.167}]
brand columns set: 0 | activity columns set: 1

Two things to notice. The launch year scales to 1.167, above 1: MinMaxScaler learned 2019 to 2025 from the training table and does not clip new values. And the unknown brand sets no brand column at all (all zeros, thanks to handle_unknown="ignore"), while the known activity, hiking, sets exactly one.

Glossary

TermMeaning
confusion matrixThe four counts TN, FP, FN, TP: rows are the truth, columns the prediction
positive classThe class you are looking for (churned, fraud), coded 1 or named with pos_label
precisionTP / (TP + FP): of those flagged, the share that really are positive
recallTP / (TP + FN): of the real positives, the share flagged (also sensitivity, true positive rate)
F1 / F-betaHarmonic mean of precision and recall; beta above 1 weighs recall more
decision thresholdThe probability above which a case is flagged; 0.5 by default, a business decision
ROC AUCChance a random positive outranks a random negative; 0.5 random, 1.0 perfect
average precisionSummary of the precision-recall curve; its random baseline is the positive rate
break-even probabilitycost / value: the probability at which contacting someone pays for itself
out-of-fold predictionA prediction for a training row from a fold model that did not see that row (cross_val_predict)
MAE / RMSE / R²Average miss in units / root of the mean squared miss / share of variation explained compared with the mean
imputationFilling a gap with a value learned from the training data (SimpleImputer)
missing indicatorA 0/1 column that remembers which values were filled (add_indicator=True)
one-hot encodingOne 0/1 column per category (OneHotEncoder)
ordinal encodingOne column of ordered codes 0, 1, 2 (OrdinalEncoder, order spelled out)
ColumnTransformerSends each list of columns to its own transformer and puts the results side by side
