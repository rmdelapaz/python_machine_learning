Session 11 12 self-check items Confidential

Warm-up

  1. Five 70%-accurate classifiers always make exactly the same predictions. How accurate is their majority vote? Answer: 70%: identical voters are one voter repeated.
  2. Where must a stacking meta-model's training features come from? Answer: Out-of-fold predictions on the training rows (cross_val_predict, or StackingClassifier's cv).
  3. Why pass one splitter object with a fixed random_state to every candidate? Answer: So all are scored on the same folds and can be compared fold by fold (paired differences).
  4. A learning curve's training and validation scores meet at 0.83 and stay flat. Next step? Answer: Better features or a more flexible model (high bias); more rows of the same data will not help.
  5. Boosting's learning curve: training 1.0, validation still rising to 0.861. What would close the gap? Answer: Regularization (smaller trees, larger leaves, a smaller learning rate) or more data. Today's lesson tests it: max_leaf_nodes 7 lifts CV AUC to 0.8795.

Self-check: project skills

Q1
Which of these is a well-framed final-project question?
A) Build the most accurate churn model possible
B) Use gradient boosting on the transactions table
C) Which customers should get the $15 retention offer next quarter, judged by profit on held-out customers, against offering to everyone (-$7,620)?
D) Find out what causes churn
Why: A framed question names the decision, who acts on it, the deciding measure and the comparison. The other three name a technique, a target without a decision, or a causal question a predictive model cannot answer.
A is wrong: Accuracy is not the business measure, and "most accurate possible" has no comparison or decision.
B is wrong: A technique is not a question; the model should be chosen by evidence.
D is wrong: A predictive model describes associations, not causes (Module 7 keeps these apart).
Q2
Your weekly-demand model (train 2024, test 2025) has an MAE of 9.1 units. Which number must it beat to be worth anything?
A) The per-product 2024 mean: MAE 13.42
B) Zero, the perfect forecast
C) The training MAE of the same model
D) A shuffled 75/25 split's MAE of 7.36
Why: A buyer can forecast each product's average without any model; that is the bar. The model at 9.1 beats it by about a third; Poisson boosting reaches 8.05.
B is wrong: No forecaster reaches zero; a baseline is what doing nothing clever scores.
C is wrong: Training error is optimistic and measures nothing about 2025.
D is wrong: A shuffled split mixes 2025 weeks into training: a leak, not a bar.
Q3
A learner adds "units sold last week" as a feature to the demand forecaster, which is meant to plan all of 2025 at the start of the year. What is wrong?
A) Nothing: lag features always help
B) Lag features need scaling first
C) The feature makes the model slower
D) On the planning date, last week's sales are unknown for almost every 2025 week: it is a framing leak
Why: A feature is legitimate only if it is known when the prediction is made. A forecast for week 30 made in January cannot use week 29's sales. (Here it does not even help: MAE 8.17 against 8.05.) It would be fine for a one-week-ahead forecaster, which is a different project.
A is wrong: Whether a lag is allowed depends on the forecast horizon, not on the feature.
B is wrong: Trees do not need scaling; the problem is timing.
C is wrong: Speed is irrelevant; validity is the issue.
Q4
How many fits does a GridSearchCV with cv=5 run on this grid, not counting the refit?
from sklearn.model_selection import ParameterGrid
grid = {"model__learning_rate": [0.03, 0.1, 0.3],
        "model__max_leaf_nodes": [7, 15, 31, 63]}
print(len(ParameterGrid(grid)) * 5)          # cv=5
60
Why: 3 × 4 = 12 settings, each cross-validated on 5 folds: 60 fits, plus one refit of the winner. A grid's cost is the product of its list lengths.
Q5
Your search reports best_score_ 0.636 (CV average precision). The tuned model scores 0.614 on the test set, opened once. Which number goes in your report as the model's expected performance?
A) 0.636, because it is the cross-validated score
B) 0.614, the one-time test score (or a nested CV estimate), with best_score_ described only as what chose the settings
C) Their average, 0.625
D) Whichever is higher, since both are honest
Why: best_score_ is the best of many noisy scores (the winner's curse): it chose the model and is biased upward. A score from data that played no part in the choice, the one-time test or a nested estimate, is the one to promise.
A is wrong: Cross-validated, yes, but maximized over 15 settings.
C is wrong: Averaging an optimistic number with an honest one is still optimistic.
D is wrong: Picking the higher one is choosing by the result.
Q6
Two hyperparameters, only the first matters, budget 9 trials. Why does random search usually beat a 3 × 3 grid?
A) Random search uses more folds
B) Random search learns from earlier trials
C) It tries 9 different values of the important hyperparameter instead of 3
D) A grid cannot use log scales
Why: The grid repeats the same three values of the important knob; every random trial draws a fresh value of every knob (Bergstra and Bengio).
A is wrong: Both use whatever cv you pass.
B is wrong: That is Optuna's TPE sampler, not random search.
D is wrong: A grid can list log-spaced values, such as 0.001, 0.01, 0.1.
Q7
For the fraud project, which split is the leak-safe one?
A) Train January to May, test June, never shuffling months together
B) A stratified 70/30 split of all six months, random_state=42
C) Train on June, test on January to May
D) Five-fold cross-validation on all six months, with no test set
Why: The model will be used on future payments, and the fraud rate drifts (1.00% in January, 0.77% in June). Training on the past and testing on a later month is the only split that matches use; cross-validation for choices happens inside January to May.
B is wrong: It lets the model learn from June while being tested on earlier months, and hides the drift.
C is wrong: Backwards in time: the future would teach the past.
D is wrong: Without an untouched test month there is no honest final number.
Q8
What does this print?
import numpy as np
print(np.logspace(-3, 1, 5))
[1.e-03 1.e-02 1.e-01 1.e+00 1.e+01]
Why: Five values evenly spaced in powers of ten from 10^-3 to 10^1: each ten times the last. That is the right spacing for learning rates and regularization strengths.
Q9
A churn offer costs $15 and is worth $60 when it reaches a real churner. If the probabilities are well calibrated, above which churn probability does an offer pay for itself?
A) 0.50, the default of predict
B) 0.75
C) 0.15
D) 0.25
Why: An offer to a customer with churn probability p is worth 60p on average and costs 15: it pays when 60p > 15, so p > 0.25. Tuned on the training customers, TunedThresholdClassifierCV picks a threshold close to that (0.240 in this session's worked example).
A is wrong: 0.5 is a convention, not a business number.
B is wrong: That would be the break-even for a $45 offer.
C is wrong: 15 is the cost in dollars, not a probability; divide by the value.
Q10
Which sentence is an honest report of a tuning result?
A) Tuning made the model 2% better
B) Tuned boosting: test ROC AUC 0.874 against 0.860 for the default, on the same 1,500 test customers, after a search on the training rows only; the nested CV estimate of the procedure is 0.868
C) Our best CV score was 0.8795, so the model will score 0.88 on new customers
D) Tuning proved that small trees cause better predictions
Why: It states the comparison, on which data, how the choice was made, and an estimate that accounts for the search. It promises no more than the evidence shows.
A is wrong: Better on what, measured how, compared with what?
C is wrong: best_score_ is the winner's curse number; the nested estimate is about 0.868.
D is wrong: Tuning finds settings that predict well; it says nothing about causes.
Q11
You choose the churn offer threshold by trying thresholds on the TEST customers and keeping the most profitable (0.26: $5,475). The threshold chosen by TunedThresholdClassifierCV on the training customers (0.240) earns $5,265 on the same test set. Which number goes in the report?
A) $5,475: it is the best result you found
B) The average of the two
C) $5,265: the threshold was chosen without the test set, so its test profit is an honest estimate
D) Neither: profits cannot be reported
Why: Choosing the threshold on the test set makes the test set part of training: $5,475 is the best of many tries on the very data that grades it. The honest number is the one from a threshold chosen on training data, scored once.
A is wrong: Best-of-many on the grading data is optimistic by construction.
B is wrong: Mixing an optimistic number in does not make it honest.
D is wrong: Profit is the business number the decision needs; report it honestly.
Q12
Fraud review cost ($10 per review, $375 per missed fraud). What does this print?
from sklearn.metrics import confusion_matrix
y_true = [0, 0, 0, 1, 1, 0, 1, 0]
flag   = [1, 0, 0, 1, 0, 1, 1, 0]
tn, fp, fn, tp = confusion_matrix(y_true, flag).ravel()
print(10 * (tp + fp) + 375 * fn)
415
Why: Four payments flagged (tp 2, fp 2): 4 × $10 = $40. One fraud missed: $375. Total $415. The same formula the fraud project uses: review nothing costs $24,000 in June.

Predict, then run

P1
Predict the output, then run it.
from sklearn.model_selection import ParameterGrid
grid = {"model__learning_rate": [0.05, 0.1], "model__max_leaf_nodes": [7, 15, 31],
        "model__l2_regularization": [0.0]}
print(len(ParameterGrid(grid)), len(ParameterGrid(grid)) * 5)
6 30
Why: 2 × 3 × 1 = 6 settings; with 5 folds, 30 fits (plus one refit). A single-value list still counts as one setting.
P2
Predict the output, then run it.
import pandas as pd
demand = pd.read_csv("data/weekly_demand.csv")
print((demand["year"] == 2024).sum(), (demand["year"] == 2025).sum())
5088 4896
Why: 2024 has 53 Mondays in the data (2024-12-30 counts as 2024): 53 × 96 = 5,088 rows; 2025 has 51 × 96 = 4,896. A split by year is exactly these sizes.
P3
Predict the output, then run it.
print(round(15 / 60, 2), round(10 / 375, 3))
0.25 0.027
Why: Break-even probabilities: churn offer $15 / $60 = 0.25; fraud review $10 / $375 = 0.027. Act when the probability is above them.

Lab 6.2-B: labs/module-11/l6_2-hyperparameter-tuning/winners_curse_starter.py → winners_curse_solution.py

The solution prints:

shuffled labels keep the churn rate (0.165) but break every link to the features
  1 settings tried: best_score_ 0.504
 10 settings tried: best_score_ 0.514
 40 settings tried: best_score_ 0.537

shuffled labels: best_score_ 0.537 | nested 0.501 | test 0.524
real labels:     best_score_ 0.848 | nested 0.840 | test 0.859

The number to promise is the nested estimate or the one-time test score, never best_score_.

Reading it: with shuffled labels the true AUC of any model is 0.5, yet best_score_ rises with the number of settings tried (0.504, 0.514, 0.537): the best of more noisy scores is higher by chance. The nested estimate (0.501) sees through it. The test score on noise (0.524) is a single noisy draw of 1,500 rows. With the real labels the gap between best_score_ (0.848) and nested (0.840) is small because there is real signal and the search space is modest.

Studio and Showcase: What Good Looks Like

  • Milestone 2: the baseline row is in the leaderboard; one splitter object; the deciding metric is the one in the plan; mean and std side by side; the top two compared fold by fold.
  • Milestone 3: the space is written before the search; rates and strengths on log scales; the search and any threshold tuning run on the training rows only; the report will quote a nested estimate or the test score.
  • Showcase talk: leads with the decision and the bar to beat, gives a spread with every score, names one trap. A talk that quotes only accuracy, or only best_score_, gets the private follow-up question.
  • Reference numbers for every problem, the traps and what an honest result looks like: final-assessment.html.

Exit Ticket

  1. best_score_: the maximum of many noisy CV scores, biased upward (winner's curse); promise a nested estimate or the one-time test score.
  2. Three numbers: for example churn: random-order AP 0.165 → tuned CV AP 0.636 ± 0.04 → test AP 0.614 (once); demand: per-product mean 13.42 → CV 8.49 → test 8.05; fraud: review nothing $24,000 → CV AP about 0.52 → June cost about $9,900 at a threshold tuned on January to May.
  3. What is left: no right answer; use it to plan follow-ups.

Common Wrong Answers and What They Reveal

  • Q2 D ("the shuffled split's 7.36"). Thinks a lower error is a higher bar. Ask what the shuffled split let the model see.
  • Q3 A ("lag features always help"). Has not yet separated features from the moment of prediction. Ask: on 2 January, what is week 29's sales?
  • Q5 A / Q10 C. Treats best_score_ as a forecast. Show the winners-curse lab: 0.537 on pure noise.
  • Q11 A. Believes the best number found is the result. The test set graded a choice it made.
