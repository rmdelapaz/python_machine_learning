Warm-up

0:00

Warm-up: Ensembles and Model Selection

10 min
Five retrieval questions (answers after each)
  1. Five 70%-accurate classifiers always make exactly the same predictions. How accurate is their majority vote? Answer: 70%: identical voters are one voter repeated.
  2. Where must a stacking meta-model's training features come from? Answer: Out-of-fold predictions on the training rows (cross_val_predict, or StackingClassifier's cv).
  3. Why pass one splitter object with a fixed random_state to every candidate? Answer: So all are scored on the same folds and can be compared fold by fold (paired differences).
  4. A learning curve's training and validation scores meet at 0.83 and stay flat. Next step? Answer: Better features or a more flexible model (high bias); more rows of the same data will not help.
  5. Boosting's learning curve: training 1.0, validation still rising to 0.861. What would close the gap? Answer: Regularization (smaller trees, larger leaves, a smaller learning rate) or more data. Today's lesson tests it: max_leaf_nodes 7 lifts CV AUC to 0.8795.
Milestone-1 check (3 minutes)
  • Hands up per problem: churn, demand, fraud. Then: "Who has a split, the bar to beat and a first cross-validated score?" Note the learners without it: they start the studio with final_project_starter.py.
  • Quick sanity numbers to listen for: churn 4,500 / 1,500 and random-order AP 0.165; demand 5,088 / 4,896 and per-product mean MAE 13.42; fraud 41,738 / 8,262 with 374 / 64 frauds and review-nothing $24,000. A different split size means a different split: fix it first.

Hyperparameter Tuning

Objectives (from the lesson page)

Mental model to say

"A camp stove has two knobs: fuel flow and air. You cannot calculate the best setting from the manual; you try a setting, boil a pot, time it, and adjust. Every trial costs fuel, so a smart camper tries a few spread-out settings, notices which knob matters, and spends the remaining fuel near the best results."

Map it on the board: a trial = one full cross-validation run; the fuel = computing time; the strategy = which settings get tried. Grid tries every combination; random samples; halving runs a tournament on growing data; Optuna learns from past trials. Then the honesty rule: "The best-looking setting looks better than it is: the best of many noisy scores. Report a nested estimate or the test score, once."

Live demo (you type, they follow)

Notebook lesson_6_2, same split and make_preprocess as 6.1 (learners can copy them from their 6.1 project notebook).

  1. The number to beat (3m). "Lesson 6.1 left a puzzle: default boosting lost narrowly to a forest and its learning curve showed a perfect training score. Its settings control exactly that. First: what does the default score, and what are its settings called?" Short step names, prep and model, keep the names short. 
    import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_val_score
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline, make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.ensemble import HistGradientBoostingClassifier

customers = pd.read_csv("data/customers_churn.csv")
numeric = ["tenure_months", "orders_12m", "spend_12m", "avg_order_value", "days_since_last_order",
           "returns_12m", "return_rate", "support_tickets_12m", "discount_share", "app_user",
           "email_opens_90d"]
categorical = ["home_store", "region", "age_group", "loyalty_tier", "preferred_category"]
X_train, X_test, y_train, y_test = train_test_split(
    customers[numeric + categorical], customers["churned"],
    test_size=0.25, stratify=customers["churned"], random_state=42)

def make_preprocess():
    return ColumnTransformer([
        ("num", make_pipeline(SimpleImputer(strategy="median"), StandardScaler()), numeric),
        ("cat", make_pipeline(SimpleImputer(strategy="most_frequent"),
                              OneHotEncoder(handle_unknown="ignore")), categorical),
    ])

hgb = Pipeline([("prep", make_preprocess()),
                ("model", HistGradientBoostingClassifier(random_state=42))])
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

default_auc = cross_val_score(hgb, X_train, y_train, cv=cv, scoring="roc_auc")
print(f"default boosting, 5-fold AUC: {default_auc.mean():.4f} +/- {default_auc.std():.4f}")
print([name for name in hgb.get_params() if name.startswith("model__")][:8])

logit_search.fit(X_train, y_train)

  4. Random search (4m). "Same budget idea, sampled from distributions: loguniform for rates, randint for sizes. And two more knobs a grid could not afford." 
    from scipy.stats import loguniform, randint
from sklearn.model_selection import RandomizedSearchCV

space = {"model__learning_rate": loguniform(0.01, 0.3),
         "model__max_leaf_nodes": randint(4, 64),

         "model__l2_regularization": loguniform(1e-3, 10)}

  6. Optuna learns where to look (5m). "Grid and random search never learn from their own results. Optuna's TPE does." On a slow machine, run it before the session and show the saved output; it is 100 fits. 
    import optuna

optuna.logging.set_verbosity(optuna.logging.WARNING)   # hide one log line per trial

def objective(trial):
    params = {
        "model__learning_rate": trial.suggest_float("learning_rate", 0.01, 0.3, log=True),
        "model__max_leaf_nodes": trial.suggest_int("max_leaf_nodes", 4, 64),
        "model__min_samples_leaf": trial.suggest_int("min_samples_leaf", 10, 200),
        "model__l2_regularization": trial.suggest_float("l2_regularization", 1e-3, 10, log=True),
    }
    model = hgb.set_params(**params)
    return cross_val_score(model, X_train, y_train, cv=cv, scoring="roc_auc", n_jobs=-1).mean()

study = optuna.create_study(direction="maximize", sampler=optuna.samplers.TPESampler(seed=42))
study.optimize(objective, n_trials=20)

print(f"best CV AUC: {study.best_value:.4f} (trial number {study.best_trial.number}, counting from 0)")
print({k: round(v, 4) for k, v in study.best_params.items()})
    best CV AUC: 0.8793 (trial number 12, counting from 0)
{'learning_rate': 0.0609, 'max_leaf_nodes': 5, 'min_samples_leaf': 183, 'l2_regularization': 0.0094}
    Level with the grid. The differences between searches are a few thousandths, far smaller than the fold spread; what they agree on matters more: every search beats the default.
  7. Nested cross-validation (3m). "best_score_ is the best of many noisy numbers. To estimate the whole procedure honestly, cross-validate the search itself." 
    inner = RandomizedSearchCV(hgb, space, n_iter=6, scoring="roc_auc", random_state=42, n_jobs=-1,
                           cv=StratifiedKFold(n_splits=3, shuffle=True, random_state=0))
outer_cv = StratifiedKFold(n_splits=3, shuffle=True, random_state=1)
nested = cross_val_score(inner, X_train, y_train, cv=outer_cv, scoring="roc_auc")
print("outer-fold AUCs:", nested.round(4))
print(f"nested estimate of the whole tuning procedure: {nested.mean():.4f}")
    outer-fold AUCs: [0.8609 0.8528 0.8907]
nested estimate of the whole tuning procedure: 0.8681
    0.868: about 0.01 below the best scores, still above the default's 0.8615. The gain is real, a little smaller than best_score_ claims.

Three mistakes to expect, and how to coach each
  • Tuning on the test set. A loop that scores settings on X_test, or early stopping on it. Coach: "Which rows chose this setting? Then which rows are left to grade it?" Every search runs on the training rows only.
  • Linear grids for log-scale knobs. [1, 2, 3, 4, 5] for C: the scores agree to three decimals and nothing was explored. Coach: "From the model's point of view, are 1 and 5 far apart?" Use np.logspace or loguniform.
  • Promising best_score_. "The model scores 0.8795." Coach with the three numbers on the slide: best_score_ 0.8795, nested 0.868, test 0.874. "Which one did the search choose with?"

Checks for understanding

Ask these out loud:

  • A grid of 4 × 5 × 3 values with cv=5: how many fits? Answer: 300, plus one refit.
  • Why loguniform for the learning rate? Answer: it matters across orders of magnitude; loguniform samples as many values between 0.01 and 0.03 as between 0.1 and 0.3.
  • What does nested cross-validation estimate? Answer: how well the whole procedure (search, then refit the winner) does on unseen data.
  • Tuning did not beat the default on your project. Is that a failure? Answer: no: an honest negative result. The workbook's demand example: the best of 8 settings is worse than the default (CV 8.73 vs 8.49; test 8.20 vs 8.05). Report the default.

Showcase: Lightning Talks

35 min
Running the showcase
  • Format: two minutes each, from the notebook or one slide, then 30 seconds for one question. The card on the board: the decision · the bar to beat · the best CV score with its spread · one trap avoided · what is left. Keep strict time: a phone timer on the projector.
  • Groups larger than 12: split into two rooms or tables with a peer timekeeper, or run a gallery walk (each learner leaves the notebook open on the card's five lines; others rotate and leave feedback cards).
  • Peer cards: each listener writes one strength and one question for two talks; the speaker keeps them for the report's Caveats and Next questions.
  • Your role: one sentence of praise per talk, aimed at a habit ("you showed the spread", "you named the leak"). Write down one strength per learner for the written feedback. The showcase is practice and is not scored.
  • Listen for: a test score already opened (ask whether anything was changed after it: if yes, the report must say so); "accuracy 99%" for fraud; a demand forecaster scored on shuffled folds. Raise these privately after the session, not in front of the room.

Closing

Exit ticket (3 questions, 4 minutes)
  1. Why is a search's best_score_ not the number to promise? Answer: it is the best of many noisy scores (the winner's curse), so it is biased upward; promise a nested estimate or the test score from one look.
  2. Write the three numbers your report will lead with. Answer (example): churn: random-order AP 0.165 → CV AP 0.636 ± 0.04 → test AP once; plus the profit at a threshold chosen on training rows.
  3. What is the one thing left before you submit? Answer: any honest answer; sort the notes to plan the follow-up emails (learners with "test set" or "report" left are on track; "leaderboard" or "split" left need a check-in this week).

If You Run Long or Short

Running long
  • Protect: the studio start at 1:20 and at least 20 minutes of showcase.
  • Cut first: demo Step 5 (halving), then Step 6 (show Optuna's saved output), then the lab's TODO 3 to 5 (they go home with the expected output).
  • Showcase under time pressure: one-minute talks with the five-line card, or a gallery walk.
Running short
  • Run winners_curse_starter.py for everyone: the most memorable picture of why best_score_ is optimistic.
  • Extend the studio: Milestone 4 rehearsal (write the report's first three sentences: answer, evidence, caveat).
