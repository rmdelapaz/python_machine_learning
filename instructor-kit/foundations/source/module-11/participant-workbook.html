6.2

Hyperparameter Tuning

By the end you can
  • Tune a whole pipeline with GridSearchCV and RandomizedSearchCV, naming its hyperparameters as step__param, and read cv_results_
  • Choose sensible search ranges (log scales, distributions from scipy.stats) and explain why random search usually beats a grid of the same size
  • Speed up a search with successive halving (HalvingRandomSearchCV)
  • Run a seeded Optuna study that learns where to search next
  • Explain why best_score_ is optimistic, estimate a tuned model honestly with nested cross-validation, and use the test set once
Key ideas
  • Parameters are learned by fit; hyperparameters are chosen by you, before fit, and found by search with cross-validation on the training rows.
  • Every search has a space (knobs and ranges), a budget (trials) and an objective (the CV metric decided first). Keys are step__param.
  • Grid search tries every combination: its cost is the product of the list lengths. Random search samples distributions (loguniform, randint) and usually beats a grid of the same size.
  • Successive halving screens many candidates on growing data; slow starters can be knocked out. Optuna (TPE) learns from past trials; seed it and run trials one at a time.
  • best_score_ is optimistic (the winner's curse). Report a nested cross-validation estimate or the test score, once. On churn: best 0.8795, nested 0.868, test 0.874.
  • Tuning moves a model toward its own ceiling; it does not change which family has the higher one. When gains flatten, look at features and framing.
Worked example: a business threshold, tuned honestly

Tuning a model is one decision; turning probabilities into actions is another, and it must be tuned honestly too. Take the tuned churn booster from Lesson 6.2's project and let TunedThresholdClassifierCV choose the offer threshold on the training customers for Lesson 1.4's economics ($15 per offer, $60 per churner reached).

import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.impute import SimpleImputer
from sklearn.metrics import make_scorer
from sklearn.model_selection import StratifiedKFold, TunedThresholdClassifierCV, train_test_split
from sklearn.pipeline import Pipeline, make_pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

customers = pd.read_csv("data/customers_churn.csv")
numeric = ["tenure_months", "orders_12m", "spend_12m", "avg_order_value", "days_since_last_order",
           "returns_12m", "return_rate", "support_tickets_12m", "discount_share", "app_user", "email_opens_90d"]
categorical = ["home_store", "region", "age_group", "loyalty_tier", "preferred_category"]
train, test = train_test_split(customers, test_size=0.25, stratify=customers["churned"], random_state=42)
X_train, y_train = train[numeric + categorical], train["churned"]
X_test, y_test = test[numeric + categorical], test["churned"]
prep = ColumnTransformer([
    ("num", make_pipeline(SimpleImputer(strategy="median"), StandardScaler()), numeric),
    ("cat", make_pipeline(SimpleImputer(strategy="most_frequent"), OneHotEncoder(handle_unknown="ignore")), categorical)])
best = {"l2_regularization": 0.0292, "learning_rate": 0.0472, "max_leaf_nodes": 50, "min_samples_leaf": 199}
tuned = Pipeline([("prep", prep), ("model", HistGradientBoostingClassifier(random_state=42, **best))])

def campaign_profit(y_true, flagged):               # Lesson 1.4: $60 per churner reached, $15 per offer
    y_true, flagged = np.asarray(y_true), np.asarray(flagged)
    return 60 * int(((flagged == 1) & (y_true == 1)).sum()) - 15 * int(flagged.sum())

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
plan = TunedThresholdClassifierCV(tuned, scoring=make_scorer(campaign_profit), cv=cv).fit(X_train, y_train)
offers = plan.predict(X_test)
print(f"threshold chosen on the training customers: {plan.best_threshold_:.3f}  (break-even 0.25)")
print(f"test: {offers.sum()} offers, {int(y_test[offers == 1].sum())} reach a churner, profit ${campaign_profit(y_test, offers):,}")
threshold chosen on the training customers: 0.240  (break-even 0.25)
test: 377 offers, 182 reach a churner, profit $5,265

Now the tempting shortcut: try thresholds on the test customers and keep the best.

p = plan.predict_proba(X_test)[:, 1]
peek = {t: campaign_profit(y_test, (p >= t).astype(int)) for t in np.round(np.arange(0.05, 0.6, 0.01), 2)}
t_peek = max(peek, key=peek.get)
print(f"threshold picked by peeking at the test set: {t_peek:.2f}, 'profit' ${peek[t_peek]:,}")
print(f"default 0.5: ${campaign_profit(y_test, (p >= 0.5).astype(int)):,}")
print(f"contact everyone: {campaign_profit(y_test, np.ones(len(p), int)):,} dollars")
threshold picked by peeking at the test set: 0.26, 'profit' $5,475
default 0.5: $3,690
contact everyone: -7,620 dollars

The chosen threshold (0.240) sits next to the break-even 0.25, a sign the probabilities are reasonably calibrated, and earns $5,265 on customers it never saw. Peeking finds $5,475, but that number was chosen by the data that grades it, so it is not a result: it is the winner's curse again. The default 0.5 earns far less, and offering to everyone loses money.

Worked example: when tuning does not help

Tuning does not always help, and saying so is a result. The demand forecaster from Lesson 5.3, tuned with 8 random settings on blocks of 2024 weeks:

import pandas as pd
from scipy.stats import loguniform, randint
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error
from sklearn.model_selection import KFold, RandomizedSearchCV, cross_val_score

demand = pd.read_csv("data/weekly_demand.csv")
features = ["store", "product_id", "category", "week_of_year", "list_price",
            "discount_pct", "price", "promo", "holiday_week", "avg_high_temp_f"]
cats = ["store", "product_id", "category"]
X = demand[features].copy()
X[cats] = X[cats].astype("category")
is_train = demand["year"] == 2024
X_train, X_test = X[is_train], X[~is_train]
y_train, y_test = demand.loc[is_train, "units_sold"], demand.loc[~is_train, "units_sold"]

blocks = KFold(5)                                      # blocks of weeks: no shuffling of time
base = HistGradientBoostingRegressor(loss="poisson", random_state=42)
default_cv = -cross_val_score(base, X_train, y_train, cv=blocks, scoring="neg_mean_absolute_error").mean()
space = {"learning_rate": loguniform(0.01, 0.3), "max_leaf_nodes": randint(4, 64),
         "min_samples_leaf": randint(10, 200), "l2_regularization": loguniform(1e-3, 10)}
search = RandomizedSearchCV(base, space, n_iter=8, cv=blocks, scoring="neg_mean_absolute_error",
                            random_state=42, n_jobs=-1).fit(X_train, y_train)
print(f"default CV MAE {default_cv:.2f}   best of 8 settings {-search.best_score_:.2f}")
print(f"2025 test MAE: default {mean_absolute_error(y_test, base.fit(X_train, y_train).predict(X_test)):.2f}"
      f"   tuned {mean_absolute_error(y_test, search.predict(X_test)):.2f}")
default CV MAE 8.49   best of 8 settings 8.73
2025 test MAE: default 8.05   tuned 8.20

The best of 8 settings is worse than the library default in cross-validation (8.73 against 8.49), and the test agrees (8.20 against 8.05). The honest report: "A random search did not improve on the default settings; we kept the default." Then spend the effort where it pays: features, the forecast horizon, or more history.

Glossary

TermMeaning
hyperparameterA setting chosen before fit (learning_rate, max_leaf_nodes, C)
search spaceThe knobs and ranges a search may try
grid / random searchEvery combination of listed values / samples from distributions
loguniformA distribution even across orders of magnitude, for rates and strengths
successive halvingA tournament: many candidates on little data, the best go on with more
Optuna, TPEA tuning library whose sampler learns from earlier trials
best_score_The best mean CV score of a search: chooses, but is optimistic
winner's curseThe best of many noisy scores looks better than it really is
nested cross-validationCross-validating the whole search-and-refit procedure
decision thresholdThe probability above which you act; tuned for costs on training data
milestoneA checkpoint of the final project: split, leaderboard, tuning, test once, report
