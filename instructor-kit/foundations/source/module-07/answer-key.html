Session 7 12 self-check items Confidential

Warm-up

W1
A log-target demand model gives holiday_week a coefficient of 0.405. In words?
A holiday week sells about exp(0.405) − 1 ≈ 50% more, for every product.
Why: Percent effects come back today as likelihood ratios that multiply.
W2
A logistic regression flag has coefficient 0.69. What does this print, and what does it mean?
import numpy as np
print(round(np.exp(0.69), 2))
1.99
Why: The odds ratio: the flag about doubles the odds. Naive Bayes today also multiplies odds, one clue at a time.
W3
Degree 15 has training MSE 0.016 and test MSE 0.187 (noise floor 0.09). Which problem, and which dial helps?
High variance (overfitting); a penalty such as Ridge's alpha, fewer features or more data.
Why: Today's dial is k: k = 1 is the degree-15 model of nearest neighbors.
W4
Temperature in °F and °C: Ridge gives [-0.607, -0.607], Lasso [-1.164, 0]. What does Lasso's zero mean?
Only that the column was redundant given its twin, not that it has no effect.
Why: Naive Bayes has the opposite problem with twins: it counts both.
W5
Why must features be scaled before Ridge or Lasso?
The penalty charges for weight size, and a feature's units decide how big its weight must be.
Why: For kNN scaling is even more basic: it defines what "similar" means.

4.1 · k-Nearest Neighbors: self-check

Q1
What does this print?
from sklearn.neighbors import KNeighborsClassifier
knn = KNeighborsClassifier(n_neighbors=3).fit([[0], [1], [2], [6], [7]], [1, 1, 0, 0, 0])
print(knn.predict_proba([[1.2]]).round(3))
[[0.333 0.667]]
Why: The three training points nearest 1.2 are 1 (0.2 away), 2 (0.8) and 0 (1.2), with labels 1, 0 and 1. The probabilities are the vote shares in the order of classes_: class 0 1/3, class 1 2/3.
Q2
As n_neighbors grows from 1 to 501 on the churn data, what happens?
A) Variance falls and bias rises: predictions drift toward the overall churn rate
B) Variance rises: more neighbors means more noise in each vote
C) Nothing changes once the features are scaled
D) The model trains more slowly, because it learns more weights
Why: k = 1 copies one neighbor (training AUC 1.000, test 0.645: variance); a huge k averages so many customers that every prediction approaches 16.5% (bias). The test AUC peaks on a plateau around 50 to 150.
B is wrong: Averaging more neighbors smooths the vote; noise shrinks.
C is wrong: Scaling decides who the neighbors are; k decides how many vote. Both matter.
D is wrong: kNN learns no weights; fit only stores the rows, whatever k is.
Q3
Unscaled kNN on fraud scored AP 0.056 (scaled: 0.397). The first two training payments' squared distance was 99.7% account age. What went wrong?
A) kNN cannot handle rare classes
B) 51 neighbors is too many for fraud
C) Account age runs up to 7,030 days, so it alone decided who the neighbors were; the flags that signal fraud had no say
D) Average precision does not work for kNN
Why: A distance adds up raw differences. Without scaling, the column with the biggest numbers defines similarity. Scaling gives every column an equal say to begin with.
A is wrong: Scaled kNN on the same rare class reached AP 0.397.
B is wrong: k was the same in both runs; only scaling changed.
D is wrong: AP needs only a ranking; kNN's vote shares provide one.
Q4
Fifty columns of random noise lower kNN's churn AUC from 0.842 to 0.755 but logistic regression's only from 0.823 to 0.816. Why?
A) kNN needs more training iterations when there are more columns
B) kNN gives every scaled column an equal say in the distance; logistic regression learns near-zero weights for useless columns
C) Logistic regression scales its own inputs
D) The noise columns were not scaled for kNN
Why: kNN has no weights to switch a column off, so every irrelevant column blurs who the true neighbors are (the curse of dimensionality). For kNN, feature selection is part of the model.
A is wrong: kNN does not iterate: fit only stores the data.
C is wrong: Both models had the same StandardScaler in front.
D is wrong: Both pipelines scaled every column.
Q5
What does this print?
from sklearn.metrics import pairwise_distances
print(pairwise_distances([[1, 2, 3]], [[4, 0, 3]], metric="manhattan"))
[[5.]]
Why: Manhattan distance adds the absolute differences: |1 − 4| + |2 − 0| + |3 − 3| = 3 + 2 + 0 = 5. (Euclidean would be √13 ≈ 3.61.)
Q6
Pinecrest wants to put the lookalike churn model into a nightly scoring job. What must ship with the fitted kNN model?
A) Only the scaler's means and standard deviations
B) One weight per feature, like logistic regression
C) Nothing: kNN predicts from the new customer alone
D) The scaler and every training customer, because each prediction searches them
Why: kNN is a lazy learner: fit stores the training table, and predict searches it. Prediction time grows with the training set, and the explanation by lookalikes is other customers' data, which is also a privacy question.
A is wrong: The scaler is needed, but so are the rows it scales.
B is wrong: kNN has no weights.
C is wrong: A prediction is a vote of stored neighbors.

4.1 · k-Nearest Neighbors: predict, then run

P1
Predict the output, then run it.
from sklearn.neighbors import KNeighborsRegressor
reg = KNeighborsRegressor(n_neighbors=2).fit([[1], [2], [4], [8]], [10, 20, 40, 80])
print(reg.predict([[3]]))
[30.]
Why: 2 and 4 are both 1 away from 3; their targets 20 and 40 average to 30. kNN regression averages the neighbors' targets; it cannot predict outside their range.
P2
Predict the output, then run it.
from sklearn.metrics import pairwise_distances
pts = [[0, 0], [3, 4]]
print(pairwise_distances(pts)[0, 1], pairwise_distances(pts, metric="manhattan")[0, 1])
5.0 7.0
Why: Euclidean: √(3² + 4²) = 5. Manhattan: 3 + 4 = 7, walking the grid. Manhattan is never shorter.

4.2 · Naive Bayes: self-check

Q7
20% of reviews are negative. The word "flimsy" appears in 10% of negative reviews and 1% of positive ones. What is P(negative | "flimsy")?
A) 0.10
B) 0.20, the prior does not change
C) 0.50
D) About 0.71
Why: Prior odds 0.2 / 0.8 = 0.25; the likelihood ratio 10% / 1% = 10 multiplies them to 2.5; 2.5 / 3.5 ≈ 0.71.
A is wrong: That is P(word | negative), the likelihood, not the posterior.
B is wrong: The word appears ten times as often in negative reviews; the belief must move.
C is wrong: That would need a likelihood ratio of 4.
Q8
What does this print?
from sklearn.feature_extraction.text import CountVectorizer
v = CountVectorizer()
print(v.fit_transform(["not bad not", "bad"]).toarray())
[[1 2] [1 0]]
Why: The vocabulary is sorted alphabetically: bad, not. The first text has bad once and not twice; the second only bad. Counts, not presence (that would need binary=True).
Q9
With MultinomialNB(alpha=1e-10) an angry review that says "leaked", "fell apart" and "returned" but also "love" comes out 100% positive. Why?
A) "love" never appeared in a negative training review, so with almost no smoothing its probability in that class is about 0, and one zero factor vetoes everything else
B) "love" is the strongest word in the vocabulary
C) The model ignores negative words
D) Small alpha makes the model prefer the majority class
Why: Naive Bayes multiplies one factor per word. Smoothing (alpha = 1) adds a pretend count to every word in every class, so no word can veto the rest: the same review comes out 97% negative.
B is wrong: Its log ratio is large, but with smoothing the other words outweigh it.
C is wrong: The negative words are counted; they are cancelled by a zero factor.
D is wrong: Alpha smooths word counts, not the class prior.
Q10
make_pipeline(StandardScaler(), MultinomialNB()) on the churn columns raises ValueError: Negative values in data passed to MultinomialNB (input X). What should you use?
A) A MinMaxScaler, so the values are between 0 and 1
B) ComplementNB, which accepts negative counts
C) GaussianNB, unscaled: it models continuous measurements with a bell curve per class
D) Take absolute values before MultinomialNB
Why: Multinomial, Complement and Bernoulli NB expect counts or 0/1 flags. Continuous measurements belong in GaussianNB, which needs no scaling because each feature is compared with its own per-class mean and spread.
A is wrong: It would run, but churn columns are not word counts; the model's assumptions would still be wrong.
B is wrong: ComplementNB also expects non-negative counts.
D is wrong: Absolute values would merge customers above and below average: nonsense.
Q11
GaussianNB on 10 churn columns scores AUC 0.778; on 6 (without spend, average order value and the two returns columns) 0.813. Why does dropping columns help?
A) Six columns train faster
B) The dropped columns repeat information already present, and Naive Bayes counts each one as a new, independent clue
C) The dropped columns had missing values
D) GaussianNB can only use six columns
Why: Spend is orders × average order value; returns_12m overlaps return_rate. The naive assumption counts the same evidence two or three times, which distorts the scores. Removing duplicates stops the double counting.
A is wrong: Speed does not change AUC.
C is wrong: None of those four columns has gaps.
D is wrong: It takes any number of columns.
Q12
What does this print?
from sklearn.feature_extraction.text import ENGLISH_STOP_WORDS
print("not" in ENGLISH_STOP_WORDS, "boots" in ENGLISH_STOP_WORDS)
True False
Why: scikit-learn's built-in English stop-word list contains "not" (and "no", "never"), the words that carry negative sentiment. Removing stop words cost accuracy in the lesson (0.849 against 0.857).

4.2 · Naive Bayes: predict, then run

P3
Predict the output, then run it.
from sklearn.feature_extraction.text import CountVectorizer
v = CountVectorizer(binary=True)
print(v.fit_transform(["warm warm boots", "boots"]).toarray())
[[1 1] [1 0]]
Why: Vocabulary boots, warm. With binary=True "warm warm" counts once: presence, the input BernoulliNB expects.
P4
Predict the output, then run it.
prior, ratio = 0.25, 3            # P(negative) and P(word | neg) / P(word | pos)
odds = prior / (1 - prior) * ratio
print(round(odds / (1 + odds), 2))
0.5
Why: Prior odds 0.25 / 0.75 = 1/3; times 3 = 1; odds of 1 mean a probability of 0.5.

The Lesson Pages' Own Quick Quizzes

Lesson 4.1 · k-Nearest Neighbors
  1. B [[0.667 0.333]]: the three nearest points to 1.4 are 1, 2 and 0 with labels 0, 1, 0.
  2. A Overfitting: each training customer is its own nearest neighbor.
  3. C Spend, simply because its numbers are bigger (90,000 against 14,400 in the squared distance).
  4. B kNN gives every column an equal say; logistic regression learns to ignore useless columns.
  5. C kNN trains almost instantly but must keep and search all the training rows at prediction time.
Lesson 4.2 · Naive Bayes
  1. B It rises from 0.25 to about 0.8 (likelihood ratio 12).
  2. C The model treats the new column as independent evidence and counts the same information twice.
  3. A [[0 2 1] [1 0 1]]: vocabulary boots, dry, warm.
  4. C It pushes toward positive, but other words can still make the review negative.
  5. B Rank customers with it, but recalibrate before quoting its probabilities.

Exit Ticket

  1. Scaling: kNN's distance adds raw differences, so without scaling the units decide similarity; MultinomialNB models counts, and scaling creates negative values it refuses.
  2. k = 1: high variance: every training customer is its own nearest neighbor, so training AUC is meaningless. Choose a larger k (around 50 here) by cross-validation.
  3. Posterior: prior odds 0.25 / 0.75 = 1/3; likelihood ratio 8 / 2 = 4; posterior odds 4/3; probability 4/7 ≈ 0.57.

Common Wrong Answers and What They Reveal

  • Q1 written with the two numbers swapped ([[0.667 0.333]]). Reads the columns in the wrong order: they follow classes_, 0 then 1.
  • Q2 B. Thinks more neighbors means more noise; draw 1 neighbor against 50.
  • Q4 C or D. Assumes logistic regression is protected by scaling; both were scaled. The difference is weights.
  • Q7 A. Gives the likelihood, not the posterior. Write prior × likelihood ratio in odds.
  • Q10 A. "Make it positive and it runs": running is not the same as modeling the right thing.
  • Exit ticket 3 written as 0.08 or 0.8. Same confusion as Q7.
