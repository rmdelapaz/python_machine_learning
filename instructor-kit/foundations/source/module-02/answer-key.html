1.2 · Splits, Baselines and Leakage: self-check

Q1
Pinecrest wants to predict how a product it has never sold will sell, from weekly_demand.csv. Which evaluation matches how the model will be used?
A) A random 75/25 split of the rows with stratify=demand["units_sold"]
B) A time split: 2024 for training, 2025 for testing
C) A group split, GroupShuffleSplit(..., groups=demand["product_id"]), so that no test product appears in training
D) Cross-validate on all the rows, then confirm on the same rows
Why: The dress rehearsal must hold products the model has never seen, so every row of a product goes to one side. In the lesson the forest's error jumps from 10.23 units (random rows) to 17.84 (new products): the honest number for a launch.
A is wrong: Stratifying on a number crashes (Common Mistake 2), and a random split puts weeks of every product on both sides.
B is wrong: That answers a different question: next year's sales of the products Pinecrest already sells.
D is wrong: Grading on rows the model trained on is no evaluation at all.
Q2
What does this print?
from sklearn.model_selection import train_test_split
rows = list(range(1000))
rest, test = train_test_split(rows, test_size=0.20, random_state=42)
train, val = train_test_split(rest, test_size=0.25, random_state=42)
print(len(train), len(val), len(test))
600 200 200
Why: The first call keeps 20% (200 rows) as the test set. The second takes 25% of the remaining 800 as validation (200) and leaves 600 for training: a 60/20/20 split from two calls, exactly the lesson's recipe.
Q3
You forecast tomorrow's sales for each store. Which candidate feature leaks the future?
A) Yesterday's sales, shift(1) within each store
B) A 7-day average built with rolling(7, center=True)
C) Sales on the same day last week, shift(7)
D) The day of the week
Why: A centered window averages the three days AFTER each date too. On opening night those days do not exist. In Common Mistake 5 it makes an honest time split look like a $504 forecast instead of $854.
A is wrong: Yesterday is known the evening before: a legitimate lag (and a cheap baseline).
C is wrong: Last week is known: the seasonal-naive baseline is built from exactly this column.
D is wrong: The calendar is known in advance.
Q4
What happens when this runs?
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
customers = pd.read_csv("data/customers_churn.csv")
X, y = customers[["tenure_months", "orders_12m"]], customers["churned"]
X_train, y_train, X_test, y_test = train_test_split(X, y, test_size=0.25, random_state=42)
LogisticRegression().fit(X_train, y_train)
A) It fits a model on 4,500 customers
B) KeyError: 'churned'
C) NotFittedError: the model was never fitted
D) ValueError: y should be one-dimensional; the second result is the 1,500 test rows of X
Why: train_test_split returns the X parts first, then the y parts: X_train, X_test, y_train, y_test. Unpacked in the wrong order, y_train holds a 1,500 × 2 table. The message: ValueError: y should be a 1d array, got an array of shape (1500, 2) instead.
A is wrong: It never gets that far.
B is wrong: The column exists; the order of the results is the problem.
C is wrong: The error comes from inside fit, before any predict.
Q5
Depths 3 and 4 tie on validation (0.864). You refit depth 3 on training plus validation rows and it scores 0.858 on the test set. What now?
A) Report 0.858 and keep depth 3: the test set has spoken once
B) Report 0.864: it is the best number you measured
C) Try depth 4 on the test set too and report the better of the two
D) Report the average of 0.864 and 0.858
Why: The validation winner is partly the one that got lucky on those 1,200 rows, so a slightly lower test score is normal. The test score is the unbiased number, and only if nothing was chosen with it.
B is wrong: The best of several validation scores is optimistic: you picked the maximum of noisy numbers.
C is wrong: Choosing with the test set turns it into a second validation set; its score stops being unbiased.
D is wrong: Averaging an optimistic number with an honest one gives a number that is neither.
Q6
What does this print? (The "yesterday" forecast's mean absolute error.)
import pandas as pd
sales = pd.Series([100, 120, 90, 130])
yesterday = sales.shift(1)
print((sales - yesterday).abs().mean())
30.0
Why: shift(1) moves every value down a row, so the first day has no forecast (NaN) and is skipped by mean. The misses are 20, 30 and 40: their mean is 30.0. The naive baseline is that cheap.

1.2 · Splits, Baselines and Leakage: predict, then run

P1
Predict the output, then run it.
from sklearn.model_selection import train_test_split
a, b = train_test_split(list(range(20)), test_size=5, random_state=0)
print(len(a), len(b))
15 5
Why: An integer test_size is a COUNT, not a share: 5 rows test, 15 train (1.2 Common Mistake 3).
P2
Predict the output, then run it.
from sklearn.model_selection import train_test_split
y = [0] * 16 + [1] * 4
y_tr, y_te = train_test_split(y, test_size=0.25, stratify=y, random_state=0)
print(len(y_te), sum(y_te))
5 1
Why: A quarter of 20 is 5 test rows; stratifying keeps the 20% share of ones, so exactly 1 of the 5 is a one.

1.3 · Cross-Validation: self-check

Q7
What does this print?
from sklearn.model_selection import RepeatedStratifiedKFold
rcv = RepeatedStratifiedKFold(n_splits=4, n_repeats=2, random_state=42)
print(rcv.get_n_splits())
8
Why: Four folds, repeated twice with different shuffles: eight rounds, so eight fits of every model you cross-validate with it (the lesson's 5 × 3 gives 15).
Q8
What happens when this runs?
from sklearn.model_selection import KFold
cv = KFold(n_splits=5, random_state=42)
A) It makes five shuffled folds with seed 42
B) ValueError: setting a random_state has no effect since shuffle is False
C) It makes five unshuffled folds and silently ignores the seed
D) TypeError: KFold has no random_state argument
Why: An unshuffled splitter is not random, so scikit-learn refuses a seed rather than let you believe the folds are shuffled. Add shuffle=True (and for classification, use StratifiedKFold).
Q9
A colleague fills the gaps in email_opens_90d with the median of all 4,500 training rows, then runs cross_val_score on the filled table. What is wrong?
A) Nothing: the test set was never used
B) cross_val_score cannot handle a column that once had gaps
C) The median should come from all 6,000 rows to be more accurate
D) Each validation fold helped compute the median that filled it: put the filling step inside a pipeline so it is refitted on the training folds of every round
Why: Same leak as pre-scaling: a step that learns from data saw the validation rows. With a median it is tiny; with steps that learn more (feature selection, encoding by churn rate) it can turn noise into 0.825 accuracy, as in Common Mistake 1.
A is wrong: The validation folds play the test set's role inside cross-validation; they were seen.
B is wrong: After filling, the column has no gaps; scikit-learn runs happily, which is the danger.
C is wrong: That would let the real test set leak in as well.
Q10
interactions.csv has many rows per customer. You want to know how well a model will predict ratings for customers it has never seen. Which splitter?
A) StratifiedKFold(5, shuffle=True, random_state=42) on the rating
B) TimeSeriesSplit(n_splits=5) on the rows in file order
C) GroupKFold(n_splits=5) with groups=customer_id
D) KFold(5) without shuffling
Why: Ask what will be new to the model: a customer. Group folds keep all of a customer's rows on one side, so every validation customer is a stranger. With row folds, nearly every validation customer also has rows in training (the workbook's worked example: 2,641 of 2,649).
A is wrong: Shuffled row folds put each customer on both sides: an easier exam than reality.
B is wrong: Time order is a different question (next month), and the file is sorted by customer, not by time.
D is wrong: Unshuffled blocks of a file sorted by customer happen to keep most customers together, but by accident; and they mix it with whatever order the file has.
Q11
What does this print?
from sklearn.dummy import DummyRegressor
from sklearn.model_selection import KFold, cross_val_score
X = [[0]] * 6
y = [1, 2, 3, 4, 5, 6]
print(cross_val_score(DummyRegressor(), X, y, cv=KFold(3), scoring="neg_mean_absolute_error"))
[-3. -0.5 -3. ]
Why: Unshuffled KFold(3) validates on [1, 2], [3, 4], [5, 6]. The dummy predicts the training mean each time: 4.5, 3.5, 2.5, so the misses average 3.0, 0.5 and 3.0. Scorers are "higher is better", so the errors come back negative: put a minus sign in front to report them.
Q12
On 15 paired folds the forest beats the depth-4 tree in all 15 (CV AUC 0.867 +/- 0.018). Fitted on all training rows, it then scores 0.865 on the test set. What do you conclude?
A) The estimate held: report 0.865 and keep the forest
B) The forest got worse on the test set; switch to the tree
C) Cross-validation was optimistic; rerun it with the test rows included
D) Report 0.867, because it is based on more folds
Why: 0.865 lies well inside 0.867 +/- 0.018, and the lead over the tree was consistent fold by fold. A trustworthy estimate looks exactly like this: the single locked test number holds no surprise.
B is wrong: A 0.002 dip is far smaller than the fold-to-fold spread, and switching would be choosing with the test set.
C is wrong: Putting the test rows into cross-validation destroys the only unbiased check (Common Mistake 5).
D is wrong: The CV mean is the estimate you chose with; the test score is the one you report.

1.3 · Cross-Validation: predict, then run

P3
Predict the output, then run it.
import numpy as np
from sklearn.model_selection import StratifiedKFold
y = np.array([0] * 8 + [1] * 4)
cv = StratifiedKFold(n_splits=4, shuffle=True, random_state=42)
print([int(y[val].sum()) for _, val in cv.split(np.zeros((12, 1)), y)])
[1, 1, 1, 1]
Why: Stratified folds keep the 1-in-3 share in every fold: each validation fold of 3 rows holds one 1.
P4
Predict the output, then run it.
import numpy as np
from sklearn.model_selection import TimeSeriesSplit
for train, val in TimeSeriesSplit(n_splits=3).split(np.zeros((10, 1))):
    print(len(train), val.tolist())
4 [4, 5] 6 [6, 7] 8 [8, 9]
Why: TimeSeriesSplit(3) on 10 rows validates on the last 6 in blocks of 2 and always trains on everything before: 4, 6, 8 training rows.

The Lesson Pages' Own Quick Quizzes

Lesson 1.2 · Splits, Baselines and Leakage
  1. B 7 3: test_size=0.3 of 10 items puts 3 in the second result; the first holds the other 7.
  2. C Train on 2024, test on 2025: the model will forecast the future of products Pinecrest already sells, so the dress rehearsal is a time split.
  3. A Target leakage: a refund is recorded after the return happens, so it will not exist when the prediction is made (0.97 alone is the alarm).
  4. B 0.866, the test score: the best of 12 validation scores is optimistic; the test set was not used to choose.
  5. C When many rows share an entity and the model must work for new entities: every row of a group goes to one side.
Lesson 1.3 · Cross-Validation
  1. B Five times: one fit per fold; cross_val_score does not refit on all rows at the end.
  2. A [3, 3, 2, 2]: 10 rows in 4 folds; the first 10 mod 4 = 2 folds get one extra row.
  3. C The scaler saw the validation folds: scale inside a pipeline so it is refitted on the training folds of each round.
  4. C Time-ordered folds: train on earlier weeks, validate on the next quarter, as the forecast will be used.
  5. A The 0.004 gap is within the noise (spread about 0.015): check the paired folds and prefer the simpler model; never break a tie with the test set.

Exit Ticket

  1. Training fits every candidate; validation compares candidates and chooses; test grades the final choice, opened once at the very end (or cross-validation on the training rows replaces the fixed validation set).
  2. $854, the time split: it is how the forecast will be used (trained on the past, asked about the future). The random split is lower because almost every test day has its neighbors, the day before and the day after, in training, and sales have momentum; tomorrow's neighbors are never available.
  3. So the scaler is refitted inside every round on the training folds only. Pre-scaling lets every validation fold help compute the mean and standard deviation it is scaled with: a leak, tiny for a scaler and large for steps that learn more (selecting features, encoding categories).

Common Wrong Answers and What They Reveal

  • Q1 B (a time split for never-sold products). Knows "time split" is the honest choice and applies it everywhere. Ask: "What will be new to the model on opening night: a date, or a product?"
  • Q3 A or C (yesterday or last week as the leak). Thinks any use of past sales is cheating. Ask: "Is yesterday known the evening before?" Shifted columns that only look backward are legal; the centered window looks forward.
  • Q4 A (it fits). Has not internalized the order of the four results. Have them say "X, X, y, y" out loud and print shapes after every split.
  • Q5 C (try depth 4 on the test set too). The single most tempting move in the session. Show what the test set becomes: a second validation set with no unbiased number left.
  • Q6 written as 22.5 or NaN. Counted the first row (NaN) or divided by 4. mean skips NaN: three misses.
  • Q9 A ("the test set was not used"). Thinks leakage only means the test set. Inside cross-validation, the validation folds play the test set's role.
  • Q11 written as positive numbers. Forgot that scorers are "higher is better": error metrics come back negated.
  • Q12 B (switch to the tree). Reads a 0.002 dip as a verdict and would choose with the test set. Point at the spread, 0.018.
