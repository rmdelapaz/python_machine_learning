Session 10 12 self-check items Confidential

Warm-up

  1. You draw a bootstrap sample of 10,000 rows from 10,000. About how many distinct rows does it hold, and what are the others called? Answer: About 6,300 (63.2%); the rest are out-of-bag, and a forest's OOB score is computed from them.
  2. A forest with 300 trees has an OOB ROC AUC of 0.866. What happens if you raise n_estimators to 3,000? Answer: About the same AUC, ten times the fitting time. More trees never overfit; the score plateaus.
  3. In gradient boosting, what is each new tree trained to predict? Answer: What the current model still gets wrong: the residuals (more generally the negative gradient of the loss).
  4. You early-stop an XGBoost or HistGradientBoosting model. Which rows may decide when it stops? Answer: A validation set split off from the training rows, never the test set.
  5. HistGradientBoostingClassifier on churn needs which preparation for the five text columns? Answer: Only astype("category"): no one-hot encoding, no imputer, no scaler (missing values stay as they are).

5.4 · Voting and Stacking: self-check

Q1
Three churn models have out-of-fold probabilities that correlate 0.98 with each other, and each scores about 0.86 ROC AUC. What should you expect from a soft vote of the three?
A) A large gain, because three models always beat one
B) About 0.86: members that make the same mistakes add almost nothing
C) A score below 0.5, because correlated members cancel out
D) An error: a soft vote needs uncorrelated members
Why: A team gains only where its members disagree. Near-copies make the same mistakes on the same customers, like the panel in which everyone read the same review.
A is wrong: The lesson's simulation: with 90% copying, 25 voters score no better than one.
C is wrong: Averaging similar probabilities gives similar probabilities, not worse ones.
D is wrong: Voting runs on any members; it just does not help when they agree.
Q2
What does this print?
import numpy as np
probs = np.array([[0.30, 0.80, 0.60],
                  [0.10, 0.40, 0.45]])       # 2 customers x 3 models
print(probs.mean(axis=1).round(2), (probs > 0.5).sum(axis=1))
[0.57 0.32] [2 0]
Why: Soft vote: (0.30 + 0.80 + 0.60) / 3 = 0.57 and (0.10 + 0.40 + 0.45) / 3 = 0.32. Hard vote: the first customer gets two votes above 0.5, the second none. Note how a soft vote keeps a ranking (0.57 vs 0.32) that the hard vote throws away.
Q3
A stack's meta-model was fitted on each member's predictions for its own training rows. Its weights come out as logreg -3.25, forest 2.69, boost 12.66. What went wrong?
A) Nothing: the booster is simply the best member
B) The meta-model needs scaled inputs, so the weights are meaningless
C) The members were not tuned before stacking
D) In-sample predictions are overconfident, so the meta-model over-trusts the most flexible member
Why: On its own training rows the booster scores 0.999 ROC AUC, against 0.859 out-of-fold. A meta-model trained on those numbers learns to trust it blindly and even gives logistic regression a negative vote; on the test set this leaky stack scores 0.854, below its best member. Build meta-features with cross_val_predict, or let StackingClassifier's cv do it.
A is wrong: The out-of-fold weights for the same members are 1.03, 5.23 and 1.55: the booster is not dominant at all.
B is wrong: The members' probabilities are already on the same 0-to-1 scale.
C is wrong: Tuning helps, but it does not cause a negative weight on a useful member.
Q4
hard_vote.predict_proba(X_test) raises AttributeError. You need a ranked call list. What is the fix?
A) Build the vote with voting="soft", from members that all have predict_proba
B) Call hard_vote.predict(X_test) and sort by it
C) Add probability=True to the VotingClassifier
D) Use a StackingClassifier with a hard vote inside it
Why: A hard vote counts 0/1 labels, so it has no probability to return. A soft vote averages probabilities, keeps predict_proba, and can rank customers, draw a ROC curve and move the threshold.
B is wrong: predict gives 0 or 1 for everyone: sorting by it gives ties, not a ranking.
C is wrong: VotingClassifier has no such argument (that is an SVC setting).
D is wrong: Stacking learns from probabilities; it does not take a hard vote as a member to fix this.
Q5
What happens when this runs?
from sklearn.ensemble import VotingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
vote = VotingClassifier([LogisticRegression(), DecisionTreeClassifier()], voting="soft")
vote.fit([[0], [1], [2], [3]], [0, 0, 1, 1])
A) It fits a soft vote of the two models
B) It fits, but only the first model is used
C) ValueError: every member needs a name, as a (string, estimator) pair
D) TypeError: a VotingClassifier needs at least three members
Why: VotingClassifier and StackingClassifier need named members so that their settings can be addressed later (for example in a grid search) and found in named_estimators_. The message: ValueError: Invalid 'estimators' attribute, 'estimators' should be a non-empty...
A is wrong: It never gets as far as fitting.
B is wrong: Nothing is fitted; the list is rejected.
D is wrong: Two members are allowed; names are the problem.
Q6
A paired bootstrap of the stack minus the single booster gives a mean gain of +0.0023 ROC AUC, 95% interval -0.0070 to +0.0124. Both put 98 real churners in their top 150. What is the professional recommendation?
A) Ship the stack: its mean gain is positive
B) Ship the stack only if it is retrained every week
C) Rerun the bootstrap on the training rows until the interval excludes zero
D) Keep the single booster: the gain is within the noise and changes no call, and the stack has 19 fits and four pieces to run
Why: An interval that comfortably contains zero means this test set cannot tell the two apart, and the business number (churners in the calls) is identical. The extra training time, latency and explanation cost buy nothing measurable.
A is wrong: A positive mean inside a wide interval that includes zero is not evidence.
B is wrong: Retraining frequency does not create a gain that is not there.
C is wrong: Searching until a test passes is p-hacking; and training rows would be the wrong place to measure anyway.

5.4 · Voting and Stacking: predict, then run

P1
Predict the output, then run it.
import numpy as np
votes = np.array([[1, 0, 1],
                  [0, 0, 1],
                  [1, 1, 1]])          # three models, three customers
print((votes.sum(axis=1) >= 2).astype(int))
[1 0 1]
Why: Each row is one customer; a customer gets 1 when at least two of the three models vote 1. Hard voting is exactly this count.
P2
Predict the output, then run it.
import numpy as np
a = np.array([0.10, 0.40, 0.80, 0.30])
b = 2 * a + 0.05                      # a "second model" that only rescales the first
print(round(np.corrcoef(a, b)[0, 1], 3), np.argsort(a).tolist() == np.argsort(b).tolist())
1.0 True
Why: A rescaled copy correlates perfectly (1.0) and ranks customers identically: it is a second voter repeating the first. Correlation of out-of-fold probabilities measures exactly this.

6.1 · Model Selection and Learning Curves: self-check

Q7
Why does the lesson pass ONE splitter object, created with a fixed random_state, to every candidate's cross_validate call?
A) So the test set takes part in the comparison
B) So every candidate is scored on exactly the same folds and the scores can be compared fold by fold
C) So each model is fitted only once
D) Because cross_validate refuses an integer cv
Why: Some folds are simply harder than others. When every model meets the same folds, paired differences cancel that shared difficulty. With a different shuffle per model, the forest's edge over boosting fell from 9 wins of 10 to 6 of 10.
A is wrong: The test set never takes part in model selection.
C is wrong: Every candidate is still fitted once per fold.
D is wrong: cv=5 is accepted (and also gives identical folds, because it does not shuffle).
Q8
What does this print?
import numpy as np
a = np.array([0.84, 0.87, 0.88, 0.85, 0.86])   # model A, 5 shared folds
b = np.array([0.83, 0.85, 0.89, 0.84, 0.84])   # model B, same folds
diff = a - b
print(round(diff.mean(), 3), (diff > 0).sum())
0.01 4
Why: The per-fold differences are 0.01, 0.02, -0.01, 0.01, 0.02: mean 0.01, and A is ahead in four of the five folds. That is the paired view: fold difficulty is shared, so the difference is what tells you about the models.
Q9
A validation curve for a tree shows training AUC 0.857 and validation AUC 0.835 at depth 4, and training AUC 1.000 with validation AUC 0.673 at depth 15. What is happening at depth 15?
A) Underfitting: the tree is too simple
B) Nothing: a perfect training score means the model is right
C) Overfitting: the tree memorizes the training customers
D) The validation folds contain an error
Why: A near-perfect training score with a falling validation score is the overfitting signature: the gap between the curves is the overfitting meter. Depth 4 to 5 is the sweet spot.
A is wrong: Underfitting looks like depth 1 to 3: both scores low and close together.
B is wrong: A perfect training score is usually the warning, not the reward.
D is wrong: The same pattern appears on every fold: it is the model, not the data.
Q10
Logistic regression's learning curve flattens at about 0.83 by 1,200 rows, with training and validation scores close together. Which next step is most likely to help?
A) Better features or a more flexible model
B) Collecting twice as many rows of the same data
C) Stronger regularization
D) A larger test set
Why: Curves that meet early and flatten mean high bias: the model has learned all it can from these columns. One lapsed-customer flag added 0.005 (Exercise 3), and a feature-built logistic regression reaches 0.877 (this session's worked example).
B is wrong: More rows of the same data do not move a flat, converged curve.
C is wrong: Regularization fights variance; this model is not overfitting.
D is wrong: A test set measures; it does not improve the model.
Q11
You call validation_curve(tree_pipe, ..., param_name="max_depth", ...) where tree_pipe was built with make_pipeline. What happens?
A) It works: the pipeline passes max_depth to the tree
B) ValueError: the pipeline has no max_depth; use decisiontreeclassifier__max_depth
C) It silently varies the scaler instead
D) KeyError: max_depth
Why: A pipeline's own parameters are memory, steps, transform_input and verbose. A step's parameter is addressed as step name, two underscores, parameter; make_pipeline names steps after their class in lowercase. sorted(tree_pipe.get_params()) lists every valid name.
A is wrong: Pipelines do not guess which step you mean.
C is wrong: Nothing runs silently: the name is rejected.
D is wrong: scikit-learn raises ValueError with the list of valid parameters.
Q12
One-standard-error rule. What does this print?
import numpy as np
depths = [3, 4, 5, 6]
means = np.array([0.829, 0.835, 0.834, 0.829])
se = np.array([0.007, 0.007, 0.007, 0.008])
best = int(np.argmax(means))
print(next(d for d, m in zip(depths, means) if m >= means[best] - se[best]))
3
Why: The best depth is 4 (0.835, standard error 0.007), so the threshold is 0.828. Scanning from the simplest depth, depth 3 already reaches 0.829: the rule picks the simpler tree, trading a sliver of measured score for a model less likely to have won by luck.

6.1 · Model Selection and Learning Curves: predict, then run

P3
Predict the output, then run it.
from sklearn.model_selection import RepeatedStratifiedKFold
print(RepeatedStratifiedKFold(n_splits=3, n_repeats=4, random_state=42).get_n_splits())
12
Why: 3 folds × 4 repeats = 12 train/validation splits, so 12 fits per candidate.

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

print([name for name in pipe.get_params() if name.endswith("max_depth")])
['decisiontreeclassifier__max_depth']
Why: make_pipeline names each step after its class in lowercase; a step's parameter is step name, two underscores, parameter.

Final-Project Plans: What to Look For

  • A good plan names a decision and who makes it, the moment of prediction, the course's split (copied, not invented), one deciding metric chosen now, the do-nothing number, two candidates, one specific leak, and what would change the recommendation.
  • Churn plans that list every column as a feature: ask about cancellation_reason (filled only after a customer leaves; it lifts AUC to about 0.94). Demand plans with "units sold last week" as a feature: ask when the forecast is made (the start of 2025: last week's sales are not known for most weeks). Fraud plans with a stratified random split: ask what June is for (the model is used on the future; the fraud rate drifts from 1.00% to 0.77%).
  • Metric: accuracy as the deciding metric is a red flag for churn and fraud (doing nothing scores 0.835 and 0.991). For demand, MAE in units is the course's choice; RMSE is acceptable if argued.
  • The full rubric and instructor answer notes with reference numbers are in final-assessment.html (kit root).

Exit Ticket

  1. Out-of-fold: in-sample predictions are overconfident (booster 0.999 in-sample, 0.859 out-of-fold), so a meta-model trained on them over-trusts the most flexible member; the leaky stack scored 0.854, below its best member.
  2. 0.867 vs 0.860, +0.007, std 0.008, 9 of 10: small but consistent (the mean is about three times 0.008 / √10). Then weigh cost, speed and explainability, and confirm on the test set once.
  3. Final project: any coherent triple: churn / AP (or profit) / 0.165 and -$7,620; demand / MAE / 13.42 (per-product mean); fraud / AP then cost / $24,000 for reviewing nothing.

Common Wrong Answers and What They Reveal

  • Q1 A ("a large gain"). Believes more models always help. Show the simulation's 90%-copying line.
  • Q3 A ("the booster is simply the best"). Reads weights as accuracy. Put the out-of-fold weights (1.03 / 5.23 / 1.55) beside the leaky ones.
  • Q6 A ("ship it: the mean gain is positive"). Ignores the interval. Ask what the care team would notice (nothing: 98 vs 98).
  • Q10 B ("more data"). Reads "lower score" as "needs data". Point at the two curves touching.
  • Exit ticket 2 "forest wins" with no reasoning. The habit the lesson targets: insist on the paired numbers.
