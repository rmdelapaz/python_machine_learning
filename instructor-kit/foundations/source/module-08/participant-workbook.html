4.3

Support Vector Machines

By the end you can
  • Explain the maximum-margin idea and find the support vectors of a fitted model
  • Predict how changing C and gamma changes the margin, the number of support vectors and the risk of overfitting
  • Explain the kernel trick and use the RBF kernel to learn a curved boundary
  • Build a scaled SVC pipeline, rank with decision_function, handle imbalance with class_weight, and tune C and gamma with cross-validation
  • Decide when an SVM is a sensible choice and when its training time rules it out
Key ideas
  • The widest street. An SVM picks the boundary with the widest margin. Only the support vectors (points on or inside the street, or misclassified) shape it.
  • C prices violations. Small C: wide street, many support vectors, simpler model. Large C: narrow street that fits training points harder. C is the inverse of regularization strength.
  • The kernel trick. Data tangled in its own features can become separable after a lift into more features (the ring plus x² + y²). A kernel computes similarities as if the lift had happened, without building the features.
  • gamma (RBF kernel). How far each point's influence reaches: similarity = exp(-gamma × squared distance). Too large memorizes noise; tune C and gamma together by cross-validation (keys svc__C, svc__gamma).
  • Always scale, inside a pipeline. Kernels and margins are distances.
  • No probabilities. Rank with decision_function; calibrate with CalibratedClassifierCV(SVC(), ensemble=False) when you need probabilities.
  • Imbalance: class_weight="balanced"; without it an SVM can ignore the minority class (accuracy = baseline, nobody flagged).
  • Training time grows roughly with the square of the rows: kernel SVM up to about 10,000 rows, LinearSVC beyond.
Worked example: where do three new customers stand?

Where do three new customers stand relative to the street? An SVM on just two scaled features, recency and discount share, so the street is a line you could draw.

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC

customers = pd.read_csv("data/customers_churn.csv")
pair = ["days_since_last_order", "discount_share"]
X_train, X_test, y_train, y_test = train_test_split(
    customers[pair], customers["churned"], test_size=0.25, stratify=customers["churned"], random_state=42)
street = make_pipeline(StandardScaler(), SVC(kernel="linear", class_weight="balanced")).fit(X_train, y_train)
print("support vectors per class:", street[-1].n_support_)
print("weights (scaled features):", street[-1].coef_[0].round(2))
support vectors per class: [2287  454]
weights (scaled features): [0.87 0.7 ]

With class_weight="balanced" and heavily overlapping classes, 2,741 of 4,500 customers sit on or inside the street. Both weights are positive: more days since the last order and more discount use push toward churn.

new = pd.DataFrame({"days_since_last_order": [20, 150, 300], "discount_share": [0.05, 0.40, 0.60]})
print(street.decision_function(new).round(2))
print(street.predict(new))
[-1.59  1.09  3.37]
[0 1 1]

The scores are signed distances in street widths. The first customer (ordered 20 days ago, rarely uses discounts) is 1.59 on the "stays" side, beyond the curb. The second (150 days, 40% discounts) is inside the street on the churn side: predicted to churn, but not confidently. The third is far out on the churn side. Sort by these scores and you have a ranking; read 3.37 as a probability and you have a mistake.

5.1

Decision Trees

By the end you can
  • Explain how a classification tree chooses each split by reducing Gini impurity, and compute the impurity of a node by hand
  • Train DecisionTreeClassifier and DecisionTreeRegressor, and read their rules with export_text and plot_tree
  • Explain where a tree's probabilities come from and why trees do not need scaled features
  • Control overfitting with max_depth, min_samples_leaf, max_leaf_nodes and cost-complexity pruning, chosen by cross-validation
  • Read a tree's feature importances, including what they cannot tell you
Key ideas
  • Signposts, trails, campsites. Each node asks one yes-or-no question about one feature; a new row walks down to a leaf and gets the leaf's prediction.
  • Gini impurity = 1 - Σ p²: the chance two rows picked at random from a node disagree. 0 is pure, 0.5 is a 50/50 two-class node. Each split is the (feature, threshold) with the largest weighted decrease, tried for every midpoint.
  • Greedy. The best split now, never reconsidered; the search repeats inside each child.
  • Probabilities are leaf shares. Few leaves give coarse ties; pure leaves give 0s and 1s.
  • No scaling needed; thresholds, U-shapes and interactions come naturally; boxes, not lines.
  • Unlimited trees overfit. Control size with max_depth, min_samples_leaf, max_leaf_nodes or ccp_alpha, chosen by cross-validation.
  • Importances describe the model's splits, favor many-valued columns, and say nothing about causes. A zero means "the model did not need it".
  • Unstable: small data changes can change the whole tree (Session 9 turns this into a strength).
Worked example: a tree finds the night-time fraud

Fraud at night: does the hour matter for every payment, or only for some? A depth-2 tree on two columns answers it.

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier, export_text

tx = pd.read_csv("data/transactions.csv")
pair = ["hour", "device_new"]
X_train, X_test, y_train, y_test = train_test_split(
    tx[pair], tx["is_fraud"], test_size=0.3, stratify=tx["is_fraud"], random_state=42)
night_tree = DecisionTreeClassifier(max_depth=2, random_state=42).fit(X_train, y_train)
print(export_text(night_tree, feature_names=pair, show_weights=True))
|--- device_new <= 0.50
|   |--- hour <= 15.50
|   |   |--- weights: [16418.00, 73.00] class: 0
|   |--- hour >  15.50
|   |   |--- weights: [15174.00, 86.00] class: 0
|--- device_new >  0.50
|   |--- hour <= 5.50
|   |   |--- weights: [111.00, 82.00] class: 0
|   |--- hour >  5.50
|   |   |--- weights: [2990.00, 66.00] class: 0

Read the weights as [legitimate, fraud]. For payments from a known device the tree's second question is about the afternoon, and both leaves are about 0.5% fraud. For a NEW device it asks about the night (hour 5 or earlier): 82 frauds among 193 payments, against 66 among 3,056 during the day. The question about the hour only matters on one side of the tree: that is an interaction.

check = X_test.assign(fraud=y_test, night=X_test["hour"] <= 5)
print(check.groupby(["device_new", "night"])["fraud"].mean().round(4).to_string())
device_new  night
0           False    0.0056
            True     0.0066
1           False    0.0175
            True     0.4079

The test payments confirm it: at night from a new device, 40.8% fraud; at night from a known device, 0.66%, no different from the day. A straight-line model with one weight for hour cannot say this; a tree says it with two questions.

P3
Predict the output, then run it. (Gini = 1 - sum of squared shares.)
import numpy as np
def gini(counts):
    p = np.asarray(counts) / np.sum(counts)
    return round(float(1 - np.sum(p ** 2)), 3)
print(gini([50, 50]), gini([90, 10]), gini([100, 0]))

Glossary

TermMeaning
margin (street)The band around an SVM's boundary; the SVM makes it as wide as it can
support vectorsThe training points on or inside the margin (or misclassified); the only ones that shape the boundary
CThe price of a margin violation; small C = wide street, simpler model
kernelA similarity function that lets an SVM work as if the data were lifted into more features
RBF kernel, gammaSimilarity exp(-gamma × squared distance); gamma sets how far each point reaches
decision_functionAn SVM's signed distance from the boundary: a ranking score, not a probability
calibrationLearning a mapping from scores to probabilities (CalibratedClassifierCV)
node, root, leafA point in a tree; the first node; a node that predicts instead of asking
Gini impurity1 - Σ p²: how mixed a node is (0 pure, 0.5 a 50/50 split of two classes)
greedyChoosing the best split now and never reconsidering it
max_depth / min_samples_leaf / max_leaf_nodesLimits on questions in a row / the smallest leaf / the number of leaves
cost-complexity pruning (ccp_alpha)Grow fully, then cut branches that do not earn their keep
impurity importance (MDI)A feature's total impurity decrease in the fitted tree, normalized to sum to 1
