5.2

Bagging and Random Forests

By the end you can
  • Draw a bootstrap sample and explain why it contains about 63% of the original rows
  • Build a bagged ensemble by hand and with BaggingClassifier(estimator=...), and explain why averaging reduces variance
  • Explain how a random forest decorrelates its trees with max_features, and tune n_estimators, max_features and min_samples_leaf
  • Use out-of-bag predictions as a built-in validation estimate
  • Compare impurity-based and permutation importance, and recognize the bias of the first
Key ideas
  • A panel of new hires. Many quirky models whose quirks point different ways: average them and the quirks cancel.
  • The bootstrap draws n rows from n with replacement: about 63.2% of the distinct rows; the other 36.8% are out-of-bag.
  • Variance of an average = ρσ² + (1 − ρ)σ²/n. More models shrink one term; less alike models shrink the other.
  • Bagging helps unstable models (deep trees) and cannot fix bias. BaggingClassifier(estimator=...).
  • A random forest = bagged trees + a random subset of features at every split (max_features): weaker, less alike trees, a better average.
  • More trees never overfit; the score plateaus. Leaf size matters more; forests are forgiving to tune.
  • Out-of-bag predictions give a validation score from one fit (not after target-based preprocessing, not for time-ordered rows).
  • Importances: MDI rewards many-valued columns and chance splits; check with permutation importance on held-out data. Both describe the model.
Worked example: how sure is a churn rate?

The bootstrap is not only for forests: it tells you how sure a number is. How precise is the churn rate of Pinecrest's 475 Gold customers?

import numpy as np
import pandas as pd

customers = pd.read_csv("data/customers_churn.csv")
gold = customers.loc[customers["loyalty_tier"] == "Gold", "churned"].to_numpy()
print(len(gold), "Gold customers; churn rate", round(gold.mean(), 4))
475 Gold customers; churn rate 0.0653

Resample the 475 customers with replacement 2,000 times and recompute the rate each time:

rng = np.random.default_rng(42)
rates = [gold[rng.integers(0, len(gold), size=len(gold))].mean() for _ in range(2000)]
low, high = np.percentile(rates, [2.5, 97.5])
print(f"bootstrap: 95% of resampled rates between {low:.3f} and {high:.3f}")
bootstrap: 95% of resampled rates between 0.044 and 0.088

Each resample holds about 63% of the distinct Gold customers, some twice or more, exactly like one tree's sample in a forest. The spread of the 2,000 rates says the true Gold churn rate could plausibly be anywhere in that interval: with only 475 customers, "6.5%" deserves a plus-or-minus. Lesson 5.4 uses the same trick to ask whether one model's lead over another is real.

5.3

Gradient Boosting

By the end you can
  • Explain how boosting adds small trees one after another, each fitted to the remaining errors, and how the learning rate controls the step size
  • Train HistGradientBoostingClassifier and HistGradientBoostingRegressor on data with missing values and native categorical columns
  • Use early stopping on a validation set to choose the number of trees without touching the test set
  • Run the same model with XGBClassifier and LGBMClassifier, including their categorical and early-stopping options
  • Choose between a random forest, scikit-learn's boosting and the external libraries for a given problem
Key ideas
  • Putting on a golf green. Start from the average; each small tree aims at what is still wrong; add a fraction of it: F = F + ν · tree.
  • Gradient: for squared error the residual is the negative gradient; for churn each tree fits y − p on the log-odds scale.
  • Training error falls forever; validation error turns around. Early stopping on a validation set picks the number of trees.
  • Learning rate: smaller steps need more trees and usually generalize a little better. Recipe: small rate, high max_iter, early stopping, then tree size.
  • HistGradientBoosting: binned features, missing values handled, category columns split natively; early stopping "auto" only above 10,000 rows.
  • XGBoost and LightGBM: the same estimator API; you pass the validation set (eval_set; eval_X/eval_y), never the test set.
  • Choose the loss for the target: Poisson for counts, quantile for "enough stock".
  • Forest vs boosting: forests reduce variance and are hard to break; boosting reduces bias and usually wins once tuned.
Worked example: boosting daily store sales

Session 8's Lab B fitted one regression tree to daily store sales. A booster on the same calendar information, with the store and the event as native categories:

import pandas as pd
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error

sales = pd.read_csv("data/daily_store_sales.csv", parse_dates=["date"])
X = pd.DataFrame({"store": sales["store"].astype("category"),
                  "day_of_week": sales["date"].dt.dayofweek, "month": sales["date"].dt.month,
                  "promo": sales["promo"], "event": sales["event"].fillna("none").astype("category")})
is_train = sales["date"].dt.year < 2025
booster = HistGradientBoostingRegressor(random_state=42).fit(X[is_train], sales.loc[is_train, "sales"])
pred = booster.predict(X[~is_train])
print(f"test MAE ${mean_absolute_error(sales.loc[~is_train, 'sales'], pred):,.0f}   trees {booster.n_iter_}")
test MAE $969   trees 100
check = pd.DataFrame({"store": sales.loc[~is_train, "store"], "actual": sales.loc[~is_train, "sales"], "predicted": pred})
print(check.groupby("store")[["actual", "predicted"]].mean().round(0))
           actual  predicted
store                       
Asheville  4380.0     4625.0
Bend       5527.0     5195.0
Boise      8342.0     7332.0
Flagstaff  6561.0     5355.0

About the same as Session 8's depth-10 tree ($976): with only calendar information there is little left for more trees to find. And look at the store table: Boise and Flagstaff grew in 2025 and are under-predicted, Asheville shrank and is over-predicted. A boosted model is still a sum of trees, and every leaf value comes from 2023 and 2024: it cannot extrapolate a trend either. More trees do not fix a missing piece of information.

Glossary

TermMeaning
bootstrap samplen rows drawn with replacement from n rows; about 63.2% distinct
out-of-bag (OOB)The rows a tree never saw; their trees' average gives a free validation prediction
baggingFit one model per bootstrap sample, average the predictions
random forestBagged trees with a random subset of features tried at each split (max_features)
decorrelationMaking the models less alike (smaller ρ) so their average cancels more error
permutation importanceHow much a score drops on held-out data when one column is shuffled
boostingAdding small models one after another, each fitted to what is still wrong
learning rate (ν)The fraction of each new tree added to the model
early stoppingStopping when the validation score has not improved for a set number of rounds
residual / negative gradientWhat the current model still gets wrong; what the next tree is fitted to
log-oddslog(p / (1 − p)): the scale on which a boosted classifier adds its trees
Poisson lossA loss for counts: positive predictions, multiplicative effects
