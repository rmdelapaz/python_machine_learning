  • W1 Lesson 4.3: you raise a linear SVM's C from 0.01 to 100 on overlapping data. Street width and number of support vectors? Answer: Narrower street, fewer support vectors (the lesson: 4.06 wide with 42 support vectors, then 0.75 with 7). C is the price of a violation.
  • W2 An RBF SVM with gamma=1000 scores 1.000 on training data and 0.650 on test data. What happened, and what would have warned you without the test set? Answer: Each point's influence shrank to a tiny bubble: it memorized the training set. Cross-validation would have shown it, and so would the support-vector count (nearly every point). Today's boosting has the same trap with a new dial: the number of trees.
  • W3 A tree node holds 40 stayers and 10 churners. Gini impurity? Predict, then check. Answer: 0.32. 1 - (0.64 + 0.04) = 0.32. A customer landing there gets churn probability 0.2.
  • W4 Why does an SVM need StandardScaler while a decision tree does not? Answer: The SVM's kernel and margin are distances, so units matter. A tree only asks "above this threshold?", and rescaling moves the threshold, not the customers. Same for today's forests and boosted trees: no scaling.
  • W5 Homework check: a bootstrap sample of 4,500 rows drawn with replacement from 4,500. What share of the distinct customers does it contain? Answer: About 63%. Lesson 5.2's first block shows 62.9% (2,830 customers); theory 63.2%. Collect the written predictions: most people guess 100% or 50%. Today opens with exactly this.

Mental model to say

"Remember the new hire from Lesson 1.1 studying case files? One diligent new hire who memorizes every file makes confident, quirky judgments: that is an unlimited tree. Now hire a panel of 100. Each studies their own random stack of files from the same archive, some files twice, some missing. For a new customer, everyone gives an opinion and you average."

"Each panelist is still quirky, but the quirks point in different directions and cancel out. What they agree on is the real pattern. That is bagging. A random forest adds one rule: at every decision, a panelist may only look at a random handful of the columns, which makes them disagree more usefully."

Point at the formula: "Averaging n models: ρσ² + (1 − ρ)σ²/n. More models shrink the second term. Only less alike models shrink the first. Bagging pulls one lever; a forest pulls both."

Live demo (you type, they follow)

New notebook lesson_5_2, the 1.1 split and ten features. Step 2 runs 100 trees in a loop: a few seconds.

  1. The bootstrap (3m). "Draw 4,500 customers from 4,500, putting each one back after every draw. How many distinct customers? You wrote a guess at home." 
    import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import roc_auc_score

customers = pd.read_csv("data/customers_churn.csv")
features = ["tenure_months", "orders_12m", "spend_12m", "avg_order_value", "days_since_last_order",
            "returns_12m", "return_rate", "support_tickets_12m", "discount_share", "app_user"]
X = customers[features]
y = customers["churned"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, stratify=y, random_state=42)

rng = np.random.default_rng(42)
n = len(X_train)
rows = rng.integers(0, n, size=n)                   # n draws with replacement
times_drawn = np.bincount(rows, minlength=n)

print(f"draws: {len(rows)}, distinct customers: {np.count_nonzero(times_drawn)} ({np.count_nonzero(times_drawn) / n:.1%})")
print("how many customers were drawn 0, 1, 2, ... times:", np.bincount(times_drawn))
print(f"theory: 1 - (1 - 1/n)^n = {1 - (1 - 1 / n) ** n:.3f}")
    draws: 4500, distinct customers: 2830 (62.9%)
how many customers were drawn 0, 1, 2, ... times: [1670 1626  840  281   65   17    1]
theory: 1 - (1 - 1/n)^n = 0.632
    1,670 customers were never drawn: they are out-of-bag for this sample. Write 63.2% / 36.8% on the board; it comes back in Step 7.
  2. Bagging by hand (4m). "The worst-behaved model from Lesson 5.1, an unlimited tree, a hundred times, each on its own bootstrap sample. Average their votes." 
    single = DecisionTreeClassifier(random_state=42).fit(X_train, y_train)
print(f"one unlimited tree: test ROC AUC {roc_auc_score(y_test, single.predict_proba(X_test)[:, 1]):.3f}")

tree_probas = []
for i in range(100):
    rows = rng.integers(0, n, size=n)
    tree = DecisionTreeClassifier(random_state=42).fit(X_train.iloc[rows], y_train.iloc[rows])
    tree_probas.append(tree.predict_proba(X_test)[:, 1])
tree_probas = np.array(tree_probas)                 # 100 trees x 1,500 test customers

for k in [1, 5, 10, 25, 50, 100]:
    print(f"average of {k:3d} trees: test ROC AUC {roc_auc_score(y_test, tree_probas[:k].mean(axis=0)):.3f}")

average of   1 trees: test ROC AUC 0.668

average of 100 trees: test ROC AUC 0.848
    No single tree improved; the AUC climbs from 0.68 to 0.85 by averaging alone. The first 10 trees give most of the gain.
  3. The divided customer (2m). "Each tree is certain. The panel is honestly unsure."

divided = int(np.argmin(np.abs(panel - 0.5)))

print("first 20 trees say:", tree_probas[:20, divided])

distinct probabilities: one tree 2 | the panel 99
    And the panel gives 99 distinct probabilities where one tree gives 2: now a top 50 is possible.
  4. BaggingClassifier (2m). "scikit-learn packages the loop. The argument is estimator=." 
    from sklearn.ensemble import BaggingClassifier

bagging = BaggingClassifier(estimator=DecisionTreeClassifier(), n_estimators=100, random_state=42)
bagging.fit(X_train, y_train)
print(f"BaggingClassifier, 100 trees: test ROC AUC {roc_auc_score(y_test, bagging.predict_proba(X_test)[:, 1]):.3f}")

  5. The random forest's one twist (4m). "Bagged trees are too alike: almost all ask about recency first. A forest lets each split choose among a random handful of features." Point at the formula: this attacks ρ. 
    from sklearn.ensemble import RandomForestClassifier

forest = RandomForestClassifier(n_estimators=100, random_state=42, n_jobs=-1).fit(X_train, y_train)
print(f"random forest, 100 trees: test ROC AUC {roc_auc_score(y_test, forest.predict_proba(X_test)[:, 1]):.3f}")

def per_tree(ensemble):
    """Churn probabilities of every tree in an ensemble, one row per tree."""
    X_array = X_test.to_numpy()                       # the inner trees were fitted without column names
    return np.array([t.predict_proba(X_array)[:, 1] for t in ensemble.estimators_])

for name, ensemble in [("bagging", bagging), ("random forest", forest)]:
    probas = per_tree(ensemble)
    one_tree = np.mean([roc_auc_score(y_test, p) for p in probas])
    rho = np.corrcoef(probas)[np.triu_indices(len(probas), k=1)].mean()
    print(f"{name:14s} average single-tree AUC {one_tree:.3f}   average correlation between trees {rho:.3f}")
    random forest, 100 trees: test ROC AUC 0.855
bagging        average single-tree AUC 0.666   average correlation between trees 0.354
random forest  average single-tree AUC 0.648   average correlation between trees 0.288
    Each forest tree is WORSE (0.648 vs 0.666) and the forest is BETTER (0.855 vs 0.849): less alike trees average better. That sentence is the lesson.
  6. How many trees? (2m). "Average the first k trees of each." 
    ks = np.arange(1, 101)
for name, ensemble in [("bagging", bagging), ("random forest", forest)]:
    probas = per_tree(ensemble)
    curve = [roc_auc_score(y_test, probas[:k].mean(axis=0)) for k in ks]
    print(f"{name:14s} AUC with 1, 10, 50, 100 trees:", [round(curve[k - 1], 3) for k in [1, 10, 50, 100]])
    bagging        AUC with 1, 10, 50, 100 trees: [0.677, 0.821, 0.846, 0.849]
random forest  AUC with 1, 10, 50, 100 trees: [0.649, 0.806, 0.849, 0.855]
    Show the lesson's plateau chart. More trees never overfit; they cost time.
  7. Out-of-bag validation (4m). "Every customer was left out by about a third of the trees. Those trees' average is an honest prediction, from one fit." 
    from sklearn.model_selection import StratifiedKFold, cross_val_score

oob_forest = RandomForestClassifier(n_estimators=300, min_samples_leaf=5, oob_score=True, random_state=42, n_jobs=-1)

print(f"OOB accuracy (oob_score_)  {oob_forest.oob_score_:.3f}")
print(f"OOB ROC AUC                {roc_auc_score(y_train, oob_proba):.3f}")

print(f"test ROC AUC               {roc_auc_score(y_test, oob_forest.predict_proba(X_test)[:, 1]):.3f}")

Three mistakes to expect, and how to coach each
  • Judging the forest on its training rows (AUC 1.000 or close). Coach: "Which trees had seen this customer?" Use OOB, CV or the test set.
  • Believing more trees overfit. Learners carry the depth lesson over. Coach with the plateau chart: more trees make the average more precise; the cost is time.
  • Reading MDI as truth. The noise column and, in Lab A, the 0/1 column device_new. Coach: "Was it measured on training or unseen data, and does the column have many distinct values?"

Checks for understanding

Ask these during the demo and the labs:

  • Why did averaging 100 bad trees give a good model? Answer: their errors partly cancel; nothing about any tree improved.
  • Each forest tree is worse than a bagged tree. Why is the forest better? Answer: its trees are less correlated, so the average cancels more error.
  • Can a forest have too many trees? Answer: not in accuracy; only in time and memory.
  • When is the OOB score not enough? Answer: preprocessing that learned from the target, time- or group-structured rows; and the test set still stays locked.

Gradient Boosting

75 min

Mental model to say

"A golfer rarely sinks a long putt in one stroke. The first putt gets close; the second corrects what is left; the third tidies up. Every stroke aims at the remaining distance."

"Boosting starts from a crude guess, the average. Tree 1 aims at the gap between that guess and the truth. Tree 2 at what is left after tree 1, and so on. The learning rate is how hard you hit each putt: a gentle tap needs more strokes but rarely overshoots." Then contrast with the panel on the left of the board: "The forest's trees never talk to each other; boosting's trees each fix the one before. Forests fix variance; boosting fixes bias, and keeps going until you stop it."

  1. A wavy problem with a noise floor (2m). "200 noisy points on a wave, plus 1,000 fresh points to play new data. The noise variance is 0.25: no model can beat that on new data." 
    import numpy as np
from sklearn.tree import DecisionTreeRegressor

rng = np.random.default_rng(42)

def make_wave(n):
    x = rng.uniform(0, 10, n)
    y = 3 * np.sin(x) + 0.3 * x + rng.normal(0, 0.5, n)
    return x.reshape(-1, 1), y

X_toy, y_toy = make_wave(200)
X_new, y_new = make_wave(1000)
print(X_toy.shape, X_new.shape, f"noise variance {0.5 ** 2}")
    (200, 1) (1000, 1) noise variance 0.25
  2. Boosting by hand (5m). "Start from the average. Fit a small tree to what is still wrong. Add a fraction of it. Repeat." Read the loop line by line; it is the whole algorithm. 
    def boost(learning_rate, n_trees, report=()):
    pred = np.full(len(y_toy), y_toy.mean())       # start: the average
    pred_new = np.full(len(y_new), y_toy.mean())
    for m in range(1, n_trees + 1):
        residual = y_toy - pred                       # what is still wrong
        tree = DecisionTreeRegressor(max_depth=2, random_state=42).fit(X_toy, residual)
        pred += learning_rate * tree.predict(X_toy)   # a small step towards the truth
        pred_new += learning_rate * tree.predict(X_new)
        if m in report:
            print(f"{m:4d} trees  train MSE {np.mean((y_toy - pred) ** 2):.3f}"
                  f"  new-data MSE {np.mean((y_new - pred_new) ** 2):.3f}")
    return pred_new

curve = boost(learning_rate=0.3, n_trees=300, report=(1, 3, 10, 30, 100, 300))
       1 trees  train MSE 3.055  new-data MSE 2.964
   3 trees  train MSE 1.364  new-data MSE 1.410
  10 trees  train MSE 0.353  new-data MSE 0.476
  30 trees  train MSE 0.156  new-data MSE 0.361
 100 trees  train MSE 0.075  new-data MSE 0.393
 300 trees  train MSE 0.010  new-data MSE 0.471
    Training error falls forever, far below the 0.25 floor: memorizing. New-data error bottoms near 30 trees, then creeps up. That U-turn is why every boosting library has early stopping. Show the lesson's 1 / 10 / 300 trees pictures.

Checks for understanding

Ask these during the demo and the labs:

  • What is each new tree trained on? Answer: what the current model still gets wrong (residuals; y − p for classification).
  • Lower the learning rate from 0.1 to 0.01 with early stopping on. What happens? Answer: many more trees, similar or slightly better validation score.
  • Why does a forest not need early stopping but boosting does? Answer: averaging more trees only makes the average more precise; adding more corrections keeps fitting finer detail, including noise.
  • When would you still pick a random forest? Answer: little time to tune, a robust baseline; boosting usually wins once tuned.

Exit ticket (3 questions, no notes, 4 minutes)

Questions on the slide; answers in the workbook's Exit Ticket box or on a sticky note. Sort them: the pile for question 1 shows whether the panel and the golfer stayed apart; Session 10's Lesson 5.4 needs that distinction (diverse members).

  1. A forest and a boosted model are both made of trees. In two sentences: how are their trees different, and which kind of error does each mainly fix? Answer: A forest grows many deep, independent trees on bootstrap samples and averages them: it mainly reduces variance. Boosting grows small trees one after another, each fitted to what the model still gets wrong: it mainly reduces bias (and needs early stopping).
  2. Why is a forest's out-of-bag score free, and when should you not trust it? Answer: Each tree never saw about 37% of the training rows, so averaging only those trees gives an unseen-data prediction for every row from one fit. Do not trust it when preprocessing learned from the target, when rows are not independent (time or groups), or with too few trees.
  3. A colleague early-stops XGBoost with eval_set=[(X_test, y_test)] and reports AUC 0.867. What is wrong, and what do you tell them? Answer: The number of trees was chosen by watching the test set, so the test score is partly a training score. Early-stop on a validation set split off the training rows (or HistGradientBoosting's built-in early stopping) and touch the test set once.
