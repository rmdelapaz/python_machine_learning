Warm-up

Retrieval on Lessons 2.2 and 2.3. The note under each answer says where it comes back today.

W1
A pipeline is make_pipeline(SimpleImputer(), StandardScaler(), LogisticRegression()). What does pipe.predict(X_new) do to each of the three steps?
The imputer and the scaler only transform the new rows, with the medians, means and standard deviations they learned during fit; the model then predicts. Nothing is refitted.
Why: If someone says "it refits the scaler", ask what would happen with one new customer: a scaler fitted on one row.
W2
In Lesson 2.2 the signup-date churn rate scored CV ROC AUC 0.930 when computed with pandas, and 0.586 as a TargetEncoder inside the pipeline. Which is honest, and why was the other so high?
0.586. The pandas rates used every training row's label, including the rows that later sat in each validation fold; with one or two customers per date, "the rate on your date" was mostly your own label.
Why: This is today's selection leak in another costume: any step that looks at y belongs inside the folds.
W3
What does this print?
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
pipe = make_pipeline(StandardScaler(), LogisticRegression())
print([name for name in pipe.get_params() if name.endswith("__C")])
['logisticregression__C']
Why: make_pipeline names each step after its class in lowercase; step__parameter reaches any setting. Today you swap a whole step the same way: set_params(logisticregression=...).
W4
add_churn_features builds tickets_no_app = support_tickets_12m * (1 - app_user). What is it for an app user with 3 tickets, and why build it?
0. Tickets raise churn for customers without the app but not for app users; a linear model cannot express that from the two raw columns, so the product gives non-app tickets their own weight.
Why: Keep this pair in mind: in today's demo forward selection keeps both raw columns because they matter together.
W5
Why can FunctionTransformer(add_churn_features) be fitted outside the folds without leaking, while TargetEncoder cannot?
The feature function is stateless: its thresholds are fixed numbers and it learns nothing from the rows it sees. TargetEncoder learns rates from y, so fitting it on validation rows hands them their own answers.
Why: Feature selection and resampling, today's two subjects, are both "learn from y" steps.

2.4 · Feature Selection: self-check

Q1
Forward selection kept both support_tickets_12m and app_user; SelectKBest with the F-test or with mutual information kept neither. What explains the difference?
A) Filters cannot score 0/1 columns such as app_user
B) The F-test needs scaled data and was given raw counts
C) A filter scores each column on its own; the wrapper judges each column next to the ones already chosen, so it sees that the two matter together
D) Forward selection always keeps more columns than SelectKBest
Why: Tickets raise churn mainly for customers without the app. Alone, each column shows only a diluted average effect, so a one-column score ranks them low; a wrapper that tries tickets next to the app flag sees the pair help.
A is wrong: app_user got F rank 5 of 11: filters score 0/1 columns without trouble.
B is wrong: The F-test compares class means relative to their spread, so scaling a column does not change its score.
D is wrong: Forward selection stopped at six columns, the same number SelectKBest was asked to keep.
Q2
What does this print?
import pandas as pd
from sklearn.feature_selection import VarianceThreshold
X = pd.DataFrame({"flag": [0, 0, 0, 0, 1], "score": [1, 5, 2, 8, 4], "const": [3, 3, 3, 3, 3]})
print(VarianceThreshold(threshold=0.2).fit(X).get_feature_names_out())
['score']
Why: VarianceThreshold drops columns whose variance is not above the threshold. flag has variance 0.2 × 0.8 = 0.16, const has 0 and score has 6.0, so only score survives. It never looks at a target.
Q3
An analyst has 300 customers and 2,000 survey columns. She runs SelectKBest(f_classif, k=15) on all 300 rows, then cross-validates a logistic regression on the 15 chosen columns and gets ROC AUC 0.84. What should she do?
A) Report 0.84: five folds are enough to trust it
B) Put the selector inside a pipeline and cross-validate the whole pipeline, expecting a lower number
C) Switch to mutual information, which detects more kinds of relationship
D) Use 10 folds instead of 5 to make the estimate more stable
Why: The selector looked at every row's label, including the rows that later became validation folds, so chance alignments were baked into every fold. Inside a pipeline the choice is redone on each training part. In the lesson the same mistake turned pure noise into about 80% accuracy.
A is wrong: The number of folds does not matter when the validation rows already helped choose the columns.
C is wrong: Any score that looks at the labels leaks in the same way when it runs before the split.
D is wrong: More folds give a more stable estimate of the wrong thing.
Q4
Without a scaler, an L1 logistic regression on the churn columns keeps avg_order_value and drops discount_share, the second-best predictor. Why?
A) discount_share is redundant with spend
B) avg_order_value is the stronger predictor
C) L1 always keeps the column with more distinct values
D) discount_share runs from 0 to 1, so it needs a large weight, and the penalty charges for the size of each weight
Why: The penalty adds up the absolute weights. A column in small units needs a big weight to matter and is priced out; a column in dollars needs a tiny weight and survives. Without scaling, L1 selects by units, not by usefulness. With a scaler the choice flips.
A is wrong: It is not: the redundant ones are avg_order_value, returns_12m and return_rate.
B is wrong: It is redundant (spend divided by orders) and has the second-lowest F score.
C is wrong: L1 knows nothing about distinct values; it only sees the size of the weights.
Q5
Forward selection prints mean CV ROC AUC by number of columns: 1: 0.7215, 2: 0.8063, 3: 0.8165, 4: 0.8235, 5: 0.8289, 6: 0.8328, 7: 0.8336, 8: 0.8341, 9: 0.8358, 10: 0.8357. With a tolerance of 0.005, how many columns do you keep?
A) 6
B) 5
C) 9
D) 10
Why: The best score is 0.8358, so the line is 0.8308. The smallest set at or above it has 6 columns (0.8328). This is the lesson project's path.
B is wrong: 0.8289 is below the line of 0.8308.
C is wrong: Nine columns has the best score, but the rule asks for the smallest set within the tolerance.
D is wrong: Ten columns scores slightly lower than nine and is larger: never the choice.
Q6
L1 set the weight of avg_order_value to zero. Which sentence belongs in your report?
A) Average order value has nothing to do with churn
B) Given spend and orders, average order value adds nothing new to this model
C) Average order value should be deleted from Pinecrest's database
D) Customers with a higher average order value churn less
Why: Selection describes this model with these other columns. Average order value is spend divided by orders, so with both of them present it is redundant. Drop spend instead and it may well be kept.
A is wrong: Dropped means "adds nothing given the others", not "unrelated to the target".
C is wrong: Other models, or a model without spend, may need it. Selection is about one model.
D is wrong: A zero weight says nothing about the direction of any effect, and a model never proves a cause.

2.4 · Feature Selection: predict, then run

P1
Predict the output, then run it.
import pandas as pd
from sklearn.feature_selection import SelectKBest, f_classif
X = pd.DataFrame({"a": [1, 2, 3, 4, 5, 6], "b": [5, 1, 4, 2, 6, 3], "c": [0, 0, 1, 0, 1, 1]})
y = [0, 0, 0, 1, 1, 1]
print(SelectKBest(f_classif, k=2).fit(X, y).get_feature_names_out())
['a' 'c']
Why: a rises with the class (mean 2 against 5) and c is mostly 0 for class 0 and 1 for class 1; b is scrambled. The F-test ranks a and c highest; get_feature_names_out() keeps the original order.
P2
Predict the output, then run it.
import numpy as np
from sklearn.linear_model import Lasso
X = np.array([[1, 0], [2, 1], [3, 0], [4, 1]])
y = np.array([2, 4, 6, 8])
print(Lasso(alpha=0.1).fit(X, y).coef_.round(2))
[1.92 0. ]
Why: The first column alone explains y perfectly (y = 2 × a), so L1 sets the useless second column to exactly zero. The first weight is a little under 2 because the penalty shrinks it.

2.5 · Imbalanced Classes: self-check

Q7
What does this print?
import numpy as np
from sklearn.utils.class_weight import compute_class_weight
y = np.array([0] * 95 + [1] * 5)
print(compute_class_weight("balanced", classes=np.array([0, 1]), y=y).round(3))
[ 0.526 10. ]
Why: Each class gets n_samples / (n_classes × count): 100 / (2 × 95) = 0.526 for the common class and 100 / (2 × 5) = 10 for the rare one. Both classes then carry the same total weight (50 each).
Q8
A model's probabilities are calibrated. A manual review costs $8 and a missed fraud costs $200. Above which probability should a payment be flagged?
A) 0.5
B) 0.0088, the fraud rate
C) 0.4
D) 0.04
Why: Flag when the expected loss of letting it through, p × $200, is bigger than the $8 review: p > 8 / 200 = 0.04.
A is wrong: 0.5 is right only when both mistakes cost the same.
B is wrong: The base rate is not a cost trade-off.
C is wrong: That is 80 / 200, as if a review cost $80.
Q9
Resampling with SMOTE before cross-validation reported AP 0.912; with SMOTE inside an imblearn pipeline, 0.495. Which is honest, and why?
A) 0.495: resampling first put synthetic frauds, built from frauds in the training folds, into the validation folds, at a 50/50 balance production never has
B) 0.912: SMOTE gives the model more frauds to learn from, so it really is better
C) Neither: average precision cannot be used after resampling
D) 0.912, because the encoder was fitted on more rows
Why: Inside the pipeline each fold resamples only its own training part, so validation folds keep the real 0.9% fraud rate and contain no near-copies of training rows.
B is wrong: Both runs use SMOTE. The only difference is when it ran, so the gap is measurement, not model quality.
C is wrong: AP is fine; it must be computed on folds with the real class balance.
D is wrong: Fitting the encoder on all rows is a small extra leak, not a reason to trust the bigger number.
Q10
What does this print? (Review $10, missed fraud $375.)
from sklearn.metrics import confusion_matrix
y_true = [0, 0, 0, 0, 0, 0, 1, 1]
y_pred = [0, 1, 1, 0, 0, 0, 1, 0]
tn, fp, fn, tp = confusion_matrix(y_true, y_pred).ravel()
print(10 * (tp + fp) + 375 * fn)
405
Why: ravel() gives tn, fp, fn, tp in that order: 3, 2, 1, 1. Three payments flagged cost $30; one fraud missed costs $375: 405.
Q11
After tuned = TunedThresholdClassifierCV(...).fit(X_train, y_train), what do tuned.predict and tuned.predict_proba return?
A) Both use the new threshold: predict_proba is rescaled so that 0.5 sits at the tuned threshold
B) predict still uses 0.5; only predict_proba changes
C) predict applies the tuned threshold; predict_proba returns the underlying model's probabilities unchanged
D) predict_proba is no longer available; only predict works
Why: The wrapper only moves the cut. The probabilities stay the plain model's calibrated ones, which is why the project can sort the review queue by them. tuned.estimator_.predict gives the old 0.5 decisions for comparison.
A is wrong: Nothing is rescaled; the probabilities are still honest estimates.
B is wrong: That is the wrapped estimator's behavior, not the wrapper's.
D is wrong: Both methods work; the project uses both.
Q12
Cross-validating "all legitimate" and the plain fraud model without scoring= gives 0.9912 and 0.9941. What is wrong?
A) Nothing: the plain model is better, and the scores agree
B) The default score of a classifier is accuracy, which hides whether any fraud is found; pass scoring="average_precision" or a cost scorer
C) The folds were not stratified, so some had no fraud
D) The dummy should use strategy="prior"
Why: A model that catches 30% of fraud and one that catches none differ only in the third decimal of accuracy. Tuning or comparing on this number picks models almost at random.
A is wrong: The difference of 0.003 hides a model that finds frauds against one that finds none.
C is wrong: cross_val_score stratifies classifiers by default, and the lesson's cv is stratified.
D is wrong: A prior dummy has the same accuracy; the problem is the yardstick.

2.5 · Imbalanced Classes: predict, then run

P3
Predict the output, then run it.
import numpy as np
from sklearn.utils.class_weight import compute_class_weight
y = np.array([0] * 8 + [1] * 2)
print(compute_class_weight("balanced", classes=np.array([0, 1]), y=y))
[0.625 2.5 ]
Why: n_samples / (n_classes × count): 10 / (2 × 8) = 0.625 and 10 / (2 × 2) = 2.5. Each class then carries a total weight of 5.
P4
Predict the output, then run it.
from sklearn.metrics import confusion_matrix
y_true = [0, 0, 0, 1, 1]
y_pred = [0, 1, 0, 1, 0]
print(confusion_matrix(y_true, y_pred).ravel())
[2 1 1 1]
Why: ravel() lists tn, fp, fn, tp: two true negatives, one false positive (row 2), one false negative (row 5), one true positive. Memorize the order: every cost function today depends on it.

The Lesson Pages' Own Quick Quizzes

Lesson 2.4 · Feature Selection
  1. C ['b' 'c']: with the default threshold of 0, VarianceThreshold drops the constant column a.
  2. A The selection step used the labels of the validation rows, so chance alignments were baked into every fold.
  3. B Tenure has a U-shaped effect, which a comparison of means misses; mutual information sees it.
  4. B The 6-column set: the 0.0005 difference is far smaller than the 0.02 fold spread.
  5. A Smaller C means a heavier L1 penalty: more weights become exactly zero.
Lesson 2.5 · Imbalanced Classes
  1. B Ask for recall and average precision against the all-legitimate baseline (which already scores about 99.1%).
  2. C [ 0.505 50. ]: 1000 / (2 × 990) and 1000 / (2 × 10).
  3. A So that only the training part of each fold is resampled and validation folds stay real.
  4. B 0.05: flag when p × 400 > 20.
  5. C The ranking is about the same; the weights mainly moved where the 0.5 cut falls.

Exit Ticket

  1. Selection in the pipeline: the selector looks at y. Outside the pipeline it chooses columns with the validation rows' labels too, so cross-validation is optimistic: about 80% on pure noise, 53% when selection is a pipeline step.
  2. Weights: the ranking (AP) barely changed; the scores shifted so that far more payments cross 0.5: 1,863 flags instead of 44, precision 0.05. The probabilities are inflated (mean 0.27 against 0.009), so they no longer mean what they say.
  3. Threshold: 10 / 375 ≈ 0.027, valid only for calibrated probabilities (the plain model, no weights, no resampling). For any other model, tune the threshold with TunedThresholdClassifierCV on the training rows.

Common Wrong Answers and What They Reveal

  • Q1 B ("the F-test needs scaled data"). Mixes up filters with penalties. The F-test compares means relative to spread; only penalties and distances care about units.
  • Q3 A or D ("report 0.84", "use 10 folds"). Trusts the procedure because it has the right name. Ask: "Which rows chose the columns?"
  • Q5 C ("9"). Picks the highest score, not the smallest set within the tolerance. Draw the tolerance line on the path.
  • Q6 A ("has nothing to do with churn"). The most common reporting error in selection. Rewrite it with "given the other columns".
  • Q9 B ("0.912, SMOTE gives more frauds"). Believes the procedure improved the model; both numbers use SMOTE. Point at where it ran.
  • Q10 written as 1,140 or 30. Wrong ravel() order. Write tn, fp, fn, tp on the board and leave it there.
  • Exit ticket 2: "the weighted model is better, it catches more fraud". Has not separated RANK from DECIDE. Ask for the flags and the AP.
