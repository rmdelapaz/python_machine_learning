Key ideas
  • A workshop of your own. Python is the building, the virtual environment is your workshop, the packages are the tools, the data folder is the raw material. A model is a tool you make by showing it examples.
  • Activation is per terminal window. No (.venv) in the prompt means the computer-wide Python: ModuleNotFoundError. python -m pip installs into the Python you are running.
  • Notebook to explore, script to keep. Running notebook cells out of order is worse in machine learning: a model trained on an old split and graded on a new one gives a meaningless score. Restart and run all when in doubt.
  • The workflow: frame → prepare → train → evaluate → explain → deploy, with a loop from evaluate back to prepare. Most real improvement happens in that loop.
  • Features and a target. The target is the column you predict (churned); features are the columns the model may use. Supervised learning has a target column; unsupervised learning (finding groups) does not.
  • Classification or regression? A category target (churned, fraud) means classification; a quantity (units sold, dollars) means regression. Ask: would a value halfway between two others make sense?
  • Rare classes make accuracy easy to fake. 16.5% of customers churn and 0.88% of payments are fraud, so "nobody churns" is 83.5% accurate and "nothing is fraud" 99.12%.
  • Ask why a value is missing. A gap can be an unfilled form, a signal in itself, a normal day, or a column written after the outcome (a leak).

1.1

The scikit-learn Estimator API

By the end you can
  • Turn a table into a feature matrix X and a target y, and hold out a test set with train_test_split
  • Use the estimator methods fit, predict, predict_proba and score, and read learned attributes such as coef_
  • Use a transformer with fit and transform, fitting it on the training data only
  • Measure a DummyClassifier baseline and judge whether a real model beats it
  • Swap one model for another without changing the rest of your code
Key ideas
  • The new hire and the case files. fit = study the old files; predict = answer fresh files with the ending torn off; score = the manager's grade. Grade only with files the new hire has never seen.
  • X and y. X is a table (two dimensions, even with one feature: double brackets); y is one column. Today only numeric columns without gaps.
  • train_test_split(X, y, test_size=0.25, stratify=y, random_state=42) keeps a quarter for testing, the same churn share on both sides, and the same rows every time. Results come back as X parts, then y parts.
  • Every estimator: create with settings (get_params()), fit (returns the estimator), then predict, predict_proba or score (accuracy for classifiers, R² for regressors). Names ending in _ were learned during fit.
  • Transformers use fit and transform. Fit the scaler on the training rows only, then transform both sets. set_output(transform="pandas") keeps the column names.
  • A baseline first. DummyClassifier(strategy="most_frequent") scores 0.835 on churn while finding nobody. A model earns its place only by beating it.
  • Probabilities rank. predict_proba(X)[:, 1] is the churn probability (column order = classes_). Sorted into deciles, the riskiest tenth churned at 57%: a model barely better on accuracy can be very useful.
  • Swap models, keep the code. Because every model shares the API, one loop can compare a baseline, logistic regression, a tree and a forest.
Worked example: one feature, four new customers

A model on ONE feature, so you can see exactly what fit learned. The question: how does the time since a customer's last order change the predicted churn risk?

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
customers = pd.read_csv("data/customers_churn.csv")
X = customers[["days_since_last_order"]]          # double brackets: a one-column table
y = customers["churned"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, stratify=y, random_state=42)
tree = DecisionTreeClassifier(max_depth=2, random_state=42).fit(X_train, y_train)
print(f"test accuracy: {tree.score(X_test, y_test):.3f}")
test accuracy: 0.842

Now score four customers who are in no file: 10, 120, 200 and 330 days since their last order.

new = pd.DataFrame({"days_since_last_order": [10, 120, 200, 330]})
print(tree.predict(new))
print(tree.predict_proba(new)[:, 1].round(3))
[0 0 0 1]
[0.097 0.097 0.494 0.595]

A depth-2 tree splits the days into four bands and predicts the churn share of each band. Customers who ordered within the last four months or so are at about 10% risk; at 200 days the risk is 49%, and at 330 days 60%. Notice the third customer: a probability of 0.494 is just under 0.5, so predict says 0. That cut-off is a choice, and Lesson 1.4 is about choosing it well.

Splits, Baselines and Leakage

By the end you can
  • Measure how much a test score moves from one random split to another, and explain why stratifying helps
  • Make a train / validation / test split and use each part for its one job
  • Split by time and by group when rows are related, and show how much a careless random split flatters a model
  • Pick a baseline that fits the problem (most frequent class, mean, yesterday, same day last week)
  • Detect target leakage and train-test contamination, and remove them
Key ideas
  • The dress rehearsal rule. Evaluate the model under the same conditions it will face in real use. Every way of breaking the rule makes the score look better, which is why nobody notices.
  • One split is one sample. Over 30 seeds the same model scored 0.836 to 0.866 (standard deviation about 0.007). Differences smaller than the wobble mean nothing.
  • Stratify classification splits on the target (stratify=y), so the class share and with it the baseline stay fixed. Never stratify on a feature or a number.
  • Train fits, validation chooses, test grades once. Call train_test_split twice for 60/20/20 (test_size=0.20, then 0.25 of the rest). After the one look at the test set, no more choices.
  • Time-ordered data needs a time split (train on the past, test on the future): on daily sales a random split claimed $613 a day, the truth was $854.
  • Related rows need a group split when the model will meet new groups: GroupShuffleSplit(..., groups=...). New products: 17.84 units off instead of 10.23.
  • Beat the strongest free baseline: most frequent class, the mean, yesterday, the same day last week ($1,072 for daily sales).
  • Leakage: target leakage (recorded after the outcome), train-test contamination (a step fitted before the split), time leakage (the future helps), group leakage. Catch it with a single-feature audit and "known at prediction time?".

from sklearn.model_selection import train_test_split, GroupShuffleSplit
inter = pd.read_csv("data/interactions.csv")
print(inter.shape, inter["customer_id"].nunique(), "customers")
row_train, row_test = train_test_split(inter, test_size=0.25, random_state=42)
shared = set(row_train["customer_id"]) & set(row_test["customer_id"])
print(f"random rows: {row_test['customer_id'].nunique()} test customers, {len(shared)} also in training")

Almost every test customer (2,641 of 2,649) also has rows in training. A model graded this way is graded on customers it already knows: an easier exam than "new customers". Now split by customer instead.

gss = GroupShuffleSplit(n_splits=1, test_size=0.25, random_state=42)
train_idx, test_idx = next(gss.split(inter, groups=inter["customer_id"]))
g_train, g_test = inter.iloc[train_idx], inter.iloc[test_idx]
shared = set(g_train["customer_id"]) & set(g_test["customer_id"])
print(f"group split: {len(g_test):,} test rows, {g_test['customer_id'].nunique()} test customers, "
      f"{len(shared)} also in training")

Cross-Validation

By the end you can
  • Explain why one train/validation split gives a noisy score, and how k-fold cross-validation averages that noise away
  • Run cross_val_score and cross_validate with a stratified, shuffled splitter, and report a mean with its spread
  • Keep preprocessing inside the folds by cross-validating a make_pipeline instead of pre-scaled data
  • Compare two models fold by fold on identical folds, and get out-of-fold predictions with cross_val_predict
  • Choose TimeSeriesSplit or GroupKFold when rows are related by time or by group
Key ideas
  • One exam or five quizzes. K-fold cross-validation trains k times, validates every training row exactly once, and gives k scores: report the mean plus or minus the spread.
  • It scores a recipe, not a model. cross_val_score fits fresh copies and throws them away; afterward fit the chosen recipe once on all the training rows.
  • Build the splitter yourself: StratifiedKFold(5, shuffle=True, random_state=42) for classification, KFold(5, shuffle=True, random_state=42) for regression. cv=5 does not shuffle.
  • Preprocessing goes inside the folds: cross-validate make_pipeline(StandardScaler(), LogisticRegression()), never pre-scaled data. Selecting features outside the folds turned pure noise into 0.825 accuracy.
  • cross_validate gives several metrics and, with return_train_score=True, the training score: a big train-validation gap means overfitting.
  • Compare on identical folds and look at paired differences. A lead smaller than the fold-to-fold spread is a tie (12 of 15 folds, +0.004: a tie). Then prefer the simpler model.
  • cross_val_predict gives every training row an honest out-of-fold prediction, for charts and thresholds.
  • Match the folds to the question: what will be new to the model? New customers: shuffled stratified folds. Next period: time-ordered folds. A new product or store: GroupKFold.

Metrics for Classification and Regression

By the end you can
  • Read a confusion matrix and compute precision, recall and F1, saying what each means for Pinecrest's retention team
  • Move a classifier's decision threshold and explain the precision-recall trade-off it controls
  • Use ROC AUC and average precision to judge how well a model ranks, and know when the precision-recall view is the honest one
  • Choose a threshold from business costs with out-of-fold probabilities or TunedThresholdClassifierCV, without peeking at the test set
  • Report MAE, RMSE and R² for a regression against a baseline, and avoid the MAPE trap on zero sales
Key ideas
  • The smoke alarm. Recall: when there is a fire, does it go off? Precision: when it goes off, is there a fire? The threshold: how sensitive to set it, which depends on what each mistake costs.
  • The confusion matrix counts TN, FP, FN and TP (rows: the truth; columns: the prediction). confusion_matrix(y_test, y_pred).ravel() gives them in that order.
  • Precision = TP / (TP + FP), "of those we called, how many were leaving?"; recall = TP / (TP + FN), "of those leaving, how many did we call?"; F1 is their harmonic mean.
  • The threshold is a decision, not a property of the model. Lower it: recall up, precision down. FixedThresholdClassifier saves a threshold with the model. Never choose it on the test set.
  • ROC AUC = the chance a random churner outranks a random stayer (0.5 random, 1.0 perfect). Average precision summarizes the precision-recall curve; its random baseline is the positive rate (0.165 churn, about 0.009 fraud). For rare positives it is the more honest number.
  • Thresholds from costs. Profit = value × TP − cost × (TP + FP); break-even probability = cost / value. Choose on out-of-fold probabilities, or with TunedThresholdClassifierCV(model, scoring=make_scorer(profit), cv=cv), then test once.
  • Regression: MAE (average miss, in units), RMSE (punishes big misses, always at least the MAE), R² (against predicting the mean). Always next to a naive baseline. MAPE explodes when true values can be 0.
  • Metric functions take (y_true, y_pred), AUC needs scores not labels, and in scikit-learn 1.9 they return plain floats (round(x, 3)).

A small tree on three columns, so you can follow every number. The question: what does moving the threshold from 0.5 to 0.3 do to the retention team's calls, and to its profit at $15 per offer and $60 per churner reached?

import pandas as pd
from sklearn.metrics import confusion_matrix, precision_score, recall_score
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
customers = pd.read_csv("data/customers_churn.csv")
X = customers[["days_since_last_order", "discount_share", "tenure_months"]]
y = customers["churned"]
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, stratify=y, random_state=42)
tree = DecisionTreeClassifier(max_depth=4, random_state=42).fit(X_train, y_train)
proba = tree.predict_proba(X_test)[:, 1]
for t in [0.5, 0.3]:
    flagged = (proba >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_test, flagged).ravel()
    print(f"threshold {t}: flagged {flagged.sum()}  TP {tp}  FP {fp}  FN {fn}  "
          f"precision {precision_score(y_test, flagged):.3f}  recall {recall_score(y_test, flagged):.3f}")

threshold 0.3: flagged 274  TP 152  FP 122  FN 96  precision 0.555  recall 0.613

Read the first line as the care team would: 126 calls, 87 reach real churners, 39 are wasted, and 161 churners are missed. Lowering the threshold to 0.3 more than doubles the calls (274) and finds 152 churners: recall rises from 0.351 to 0.613 while precision falls from 0.690 to 0.555. Now put money on it.

for t in [0.5, 0.3]:
    flagged = (proba >= t).astype(int)
    tp = ((flagged == 1) & (y_test == 1)).sum()
    print(f"threshold {t}: profit {60 * tp - 15 * flagged.sum():,} dollars")
threshold 0.5: profit 3,330 dollars
threshold 0.3: profit 5,010 dollars

The lower threshold earns more, because $60 for a churner reached is worth four wasted $15 offers. One caution: this example compares thresholds on the TEST set only to show the trade-off. To CHOOSE a threshold, use out-of-fold training probabilities, as the lesson project does.

By the end you can

Key ideas
  • Mise en place. Each kind of column gets its own treatment: gaps → imputer, units → scaler, words → encoder. The recipe is learned from the training rows, then applied unchanged to the test rows and every new customer.
  • Ask what a gap means before filling it. Customers with no email count churned at 25.3% against 15.6%: the gap is a clue.
  • SimpleImputer fills with a learned value (statistics_): median for skewed numbers, most_frequent or a constant such as "unknown" for text. add_indicator=True keeps a 0/1 "was missing" column.
  • Scalers change units, not shape. StandardScaler (mean 0, sd 1), MinMaxScaler (0 to 1), RobustScaler (median 0, interquartile range 1; resists outliers). A log (np.log1p) changes the shape. Trees need neither.
  • OneHotEncoder(sparse_output=False, handle_unknown="ignore"): one 0/1 column per category; an unseen category becomes all zeros; a gap becomes its own column. Never pd.get_dummies on new data.
  • OrdinalEncoder only for ordered categories, always with the order spelled out: categories=[["Basic", "Silver", "Gold"]]. The default is alphabetical.
  • ColumnTransformer: a list of (name, transformer, columns); branches run side by side, unlisted columns are dropped. Steps that must run one after another go in a make_pipeline inside one branch.
  • fit_transform on train, transform on everything else. Check it: scaled training columns have a mean of exactly 0; test columns only close to 0.

By the end you can

  • Reach inside a fitted pipeline (named_steps, indexing, slicing) to read learned values
  • Cross-validate a whole pipeline, and show with a target-based encoding why preprocessing outside the folds leaks

  • Add a custom step with FunctionTransformer, and save and reload a fitted pipeline with joblib
Key ideas
  • The coffee machine. A pipeline is transformers in order plus one model at the end, with the same fit, predict, predict_proba and score as a single model.
  • fit vs predict. fit calls fit_transform on every step but the last, then fit; predict calls only transform, then predict. Nothing is refitted on the rows being predicted.
  • Looking inside. pipe.named_steps["prep"], pipe[-1] (the model), pipe[:-1] (everything before it). named_transformers_ holds a ColumnTransformer's fitted branches.
  • Leaks. Any step that learns from data must be fitted inside each fold. Steps that learn from y (target encoding, selection, resampling) leak the most: 0.930 leaky vs 0.586 honest for the signup-date rate.
  • Names. step__parameter, deeper step__branch__substep__parameter, for set_params and grid searches. make_pipeline names steps after their classes; Pipeline([("prep", ...), ("model", ...)]) uses yours.
  • Swap and search. clone(pipe).set_params(model=...) swaps a whole step; GridSearchCV(pipe, param_grid=..., cv=cv) cross-validates every combination without leaks.
  • Custom and saved. FunctionTransformer(func) makes a stateless step; joblib.dump/joblib.load save the whole fitted pipeline (load only files you trust).
  • What a pipeline cannot do. It separates rows, not columns: a column from the future in your feature list still leaks.

  • History. Per series and past only: groupby(...).shift(1), shift(1).rolling(k).mean(). Ask: on the day of the prediction, would this number exist?

Feature Selection

By the end you can
  • Explain what feature selection buys you (simpler, cheaper, sturdier models) and what it usually does not (big accuracy gains)
  • Find redundant features with correlations, exact relationships and cross-tabulations
  • Use filter (SelectKBest), wrapper (RFECV, SequentialFeatureSelector) and embedded (L1, SelectFromModel) methods, and say what each can miss
  • Keep selection inside a Pipeline so cross-validation stays honest, and show what happens when it is not
  • Choose the smallest feature set whose cross-validated score is within a tolerance of the best
Key ideas
  • The ultralight backpack. Redundant items (two stoves) and irrelevant ones (the unused chair) go home; the goal is the lightest pack that still finishes the trail: the smallest feature set that keeps the score.
  • Selection buys simplicity, not accuracy. Fewer inputs to collect, explain and monitor; on a good set of columns the score barely moves.
  • Ask how a column was made. Averages, ratios, tiers and lookups computed from other columns are candidates to drop. Correlation misses relationships between three columns (spend = orders × average order value).
  • Filters (SelectKBest with f_classif or mutual_info_classif) score each column alone: fast, but blind to the model and to teamwork. F sees differences in means; mutual information sees any dependence but is noisy.
  • Wrappers (RFECV, SequentialFeatureSelector) try subsets with the real model: they find columns that matter together, at the cost of many fits.
  • Embedded: an L1 penalty (l1_ratio=1, solver="liblinear") zeros weak weights; smaller C means more zeros. Always scale first.
  • Selection that sees the labels is learning. Keep it inside the pipeline, or cross-validation lies: about 80% on pure noise.
  • The tolerance rule: read the curve, not the winner; take the smallest set within a small tolerance of the best, and test once. "Dropped" means "adds nothing given the others", not "irrelevant".

Imbalanced Classes

By the end you can

Key ideas
  • The smoke detector. Never beeping is right 364 days a year and worthless; beeping at toast catches every fire and gets unplugged. Where to sit between depends on what each mistake costs.
  • The accuracy paradox. At 0.876% fraud, "all legitimate" is 99.1% accurate and catches nothing. Never compare imbalanced models by accuracy (or by cross_val_score without scoring=).
  • RANK, then DECIDE. Judge the ranking with average precision against the base rate (about 0.009 here, not 0.5) and ROC AUC; judge decisions with recall, precision and cost.
  • Class weights and samplers mostly move the cut. On fraud, class_weight="balanced", under- and oversampling and SMOTE all gave about 1,900 flags, recall near 0.7 and no better ranking, and inflated the probabilities (mean 0.27 against a real 0.009).
  • Samplers go inside an imblearn pipeline. A scikit-learn pipeline refuses them; resampling before CV faked an AP of 0.91 (honest: 0.49).
  • The threshold formula: flag when p × (loss from a miss) > (cost of a review), so p > 10 / 375 ≈ 0.027. It needs calibrated probabilities.
  • TunedThresholdClassifierCV picks a threshold for any scorer with cross-validation on the training rows; FixedThresholdClassifier applies one you choose.
  • False alarms land on real customers. Check whether one group carries more than its share.

Key ideas
  • The ruler on the scatter plot. Least squares picks the line with the smallest sum of squared residuals; for one feature, slope = covariance / variance.
  • Read coefficients in units. -0.76 snow items per °F; an intercept can be meaningless (0 °F never happens).
  • Holding the others constant. A coefficient's meaning depends on what else is in the model: the price effect went from -0.53 to -1.61.
  • Lines extrapolate without limits and give each feature one slope for everyone.
  • A fanning residual plot means percent effects: model log1p(y) with TransformedTargetRegressor; read exp(coef) − 1 as a percentage.
  • Logistic regression: z = b₀ + b·x is the log-odds; p = 1 / (1 + e^−z); exp(coef) is an odds ratio; decision_function > 0 is the same as p > 0.5.
  • Current API: multiclass uses softmax automatically (multi_class is gone); the penalty is C and l1_ratio (penalty is deprecated).
  • Coefficients describe the model, not causes; twin columns split credit arbitrarily.

Regularization and the Bias-Variance Trade-off

By the end you can

  • Add polynomial and interaction features with PolynomialFeatures and predict how many columns they create

Key ideas
  • Three students: one rule for everything (bias), every answer memorized (variance), real patterns learned (the goal).
  • The diagnostic: high training and test error = too simple; low training and much higher test error = too flexible.
  • Expected test error = bias² + variance + noise. More flexibility trades bias for variance: the U.
  • PolynomialFeatures adds powers and products; the column count explodes with the degree.
  • Ridge charges for squared weights and shrinks them all; Lasso charges for absolute weights and zeros many; ElasticNet mixes both.
  • Penalties need scaled features, inside the pipeline.
  • Choose alpha by cross-validation on the training rows (RidgeCV, LassoCV), searched on a log scale; test once.
  • More data is also a regularizer. With few rows and many columns the penalty decides everything.

Key ideas

Naive Bayes

By the end you can
  • Compute a posterior probability by hand with Bayes' rule, starting from counts in a table
  • Explain the "naive" independence assumption and show what it costs when features repeat each other
  • Turn review text into word counts with CountVectorizer and classify it with MultinomialNB inside a pipeline
  • Explain what the smoothing parameter alpha prevents, and choose between the Multinomial, Bernoulli, Complement and Gaussian variants

Key ideas
  • The store manager. A prior, clues that multiply the odds, a posterior.
  • Bayes' rule: P(class | clue) = P(clue | class) × P(class) / P(clue). Odds form: posterior odds = prior odds × likelihood ratio.
  • The naive assumption: clues are independent within a class, so their probabilities multiply. Often false; rankings still decent.
  • Bag of words: CountVectorizer makes one sparse column per word; word order is lost ("would not buy again").
  • Smoothing (alpha) adds a pretend count so no unseen word can veto the rest. Keep it above 0.
  • Variants: Multinomial or Complement for counts, Bernoulli for presence, Gaussian for measurements. Never scale count inputs.
  • Duplicated features are counted twice: removing them can help Naive Bayes.
  • Good ranking, overconfident probabilities: rank with it; recalibrate before quoting it.

Support Vector Machines

By the end you can

  • Predict how changing C and gamma changes the margin, the number of support vectors and the risk of overfitting
  • Explain the kernel trick and use the RBF kernel to learn a curved boundary
  • Build a scaled SVC pipeline, rank with decision_function, handle imbalance with class_weight, and tune C and gamma with cross-validation
  • Decide when an SVM is a sensible choice and when its training time rules it out
Key ideas
  • The widest street. An SVM picks the boundary with the widest margin. Only the support vectors (points on or inside the street, or misclassified) shape it.
  • C prices violations. Small C: wide street, many support vectors, simpler model. Large C: narrow street that fits training points harder. C is the inverse of regularization strength.
  • The kernel trick. Data tangled in its own features can become separable after a lift into more features (the ring plus x² + y²). A kernel computes similarities as if the lift had happened, without building the features.
  • gamma (RBF kernel). How far each point's influence reaches: similarity = exp(-gamma × squared distance). Too large memorizes noise; tune C and gamma together by cross-validation (keys svc__C, svc__gamma).
  • Always scale, inside a pipeline. Kernels and margins are distances.
  • No probabilities. Rank with decision_function; calibrate with CalibratedClassifierCV(SVC(), ensemble=False) when you need probabilities.
  • Imbalance: class_weight="balanced"; without it an SVM can ignore the minority class (accuracy = baseline, nobody flagged).
  • Training time grows roughly with the square of the rows: kernel SVM up to about 10,000 rows, LinearSVC beyond.

Decision Trees

  • Read a tree's feature importances, including what they cannot tell you
Key ideas
  • Signposts, trails, campsites. Each node asks one yes-or-no question about one feature; a new row walks down to a leaf and gets the leaf's prediction.
  • Gini impurity = 1 - Σ p²: the chance two rows picked at random from a node disagree. 0 is pure, 0.5 is a 50/50 two-class node. Each split is the (feature, threshold) with the largest weighted decrease, tried for every midpoint.
  • Greedy. The best split now, never reconsidered; the search repeats inside each child.
  • Probabilities are leaf shares. Few leaves give coarse ties; pure leaves give 0s and 1s.
  • No scaling needed; thresholds, U-shapes and interactions come naturally; boxes, not lines.
  • Unlimited trees overfit. Control size with max_depth, min_samples_leaf, max_leaf_nodes or ccp_alpha, chosen by cross-validation.
  • Importances describe the model's splits, favor many-valued columns, and say nothing about causes. A zero means "the model did not need it".
  • Unstable: small data changes can change the whole tree (Session 9 turns this into a strength).

Key ideas
  • A panel of new hires. Many quirky models whose quirks point different ways: average them and the quirks cancel.
  • The bootstrap draws n rows from n with replacement: about 63.2% of the distinct rows; the other 36.8% are out-of-bag.

  • A random forest = bagged trees + a random subset of features at every split (max_features): weaker, less alike trees, a better average.
  • More trees never overfit; the score plateaus. Leaf size matters more; forests are forgiving to tune.
  • Out-of-bag predictions give a validation score from one fit (not after target-based preprocessing, not for time-ordered rows).
  • Importances: MDI rewards many-valued columns and chance splits; check with permutation importance on held-out data. Both describe the model.

Gradient Boosting

By the end you can
  • Explain how boosting adds small trees one after another, each fitted to the remaining errors, and how the learning rate controls the step size
  • Train HistGradientBoostingClassifier and HistGradientBoostingRegressor on data with missing values and native categorical columns

Key ideas
  • Putting on a golf green. Start from the average; each small tree aims at what is still wrong; add a fraction of it: F = F + ν · tree.
  • Gradient: for squared error the residual is the negative gradient; for churn each tree fits y − p on the log-odds scale.
  • Training error falls forever; validation error turns around. Early stopping on a validation set picks the number of trees.
  • Learning rate: smaller steps need more trees and usually generalize a little better. Recipe: small rate, high max_iter, early stopping, then tree size.
  • HistGradientBoosting: binned features, missing values handled, category columns split natively; early stopping "auto" only above 10,000 rows.
  • XGBoost and LightGBM: the same estimator API; you pass the validation set (eval_set; eval_X/eval_y), never the test set.
  • Choose the loss for the target: Poisson for counts, quantile for "enough stock".
  • Forest vs boosting: forests reduce variance and are hard to break; boosting reduces bias and usually wins once tuned.

Voting and Stacking

By the end you can
  • Explain why a group of models beats its members only when their errors differ, and measure that diversity
  • Build hard and soft VotingClassifier ensembles from complete preprocessing pipelines
  • Build a stack by hand from out-of-fold predictions, then with StackingClassifier, and explain why in-sample predictions leak
  • Judge whether an ensemble's gain is real (bootstrap) and worth its cost in training time, latency and explainability
Key ideas
  • A crowd is wise only when its members disagree. Independent 70% voters reach 0.837 in fives; when most copy one opinion, adding voters barely helps.
  • Measure diversity on out-of-fold predictions (cross_val_predict), never on the test set. Forest and booster correlate 0.89 on churn: near-copies.
  • Soft voting averages probabilities and keeps predict_proba; hard voting counts labels and loses it. Choose weights out-of-fold.
  • Stacking fits a simple meta-model on out-of-fold member predictions; StackingClassifier(..., cv=cv) does it in one estimator. Its weights describe the combination, not the customers.
  • In-sample meta-features leak: the meta-model over-trusts the overconfident member and can score below its own best member, with no warning.
  • Blending uses one holdout instead of folds: simpler, noisier, natural for time-ordered data (blend on a later period).
  • Ship an ensemble only when the gain survives a bootstrap or CV and changes a decision, and is worth 19 fits and four pieces to run instead of one.

  • Draw a validation curve with ValidationCurveDisplay and point to where a model moves from underfitting to overfitting
  • Draw a learning curve with LearningCurveDisplay and say whether more data or a more flexible model is the better next step
  • Make a final choice you can defend, then score it once on the untouched test set
Key ideas
  • Testing tents: same campsites (folds), same nights (repeats), compare night by night. One splitter object with a fixed random_state for every candidate.
  • cross_validate returns per-fold scores and fit times, for several metrics at once. Choose the deciding metric before looking.
  • Paired differences cancel shared fold difficulty. Worth acting on: the winner wins most folds and the mean difference is clearly larger than its std / √(number of folds). Otherwise: within noise.
  • Validation curve (one knob): both scores low = underfitting; training near perfect and validation falling = overfitting. Pipeline knobs are step__param.
  • Learning curve (more data): curves that meet and flatten = high bias (better features or a more flexible model); a wide gap still closing = variance (regularize or add data).
  • Within noise? Prefer the simpler model (the one-standard-error rule).
  • Open the test set once, after the choice, and report its score as is.

Hyperparameter Tuning

By the end you can
  • Tune a whole pipeline with GridSearchCV and RandomizedSearchCV, naming its hyperparameters as step__param, and read cv_results_
  • Choose sensible search ranges (log scales, distributions from scipy.stats) and explain why random search usually beats a grid of the same size

  • Run a seeded Optuna study that learns where to search next
  • Explain why best_score_ is optimistic, estimate a tuned model honestly with nested cross-validation, and use the test set once
Key ideas
  • Parameters are learned by fit; hyperparameters are chosen by you, before fit, and found by search with cross-validation on the training rows.
  • Every search has a space (knobs and ranges), a budget (trials) and an objective (the CV metric decided first). Keys are step__param.
  • Grid search tries every combination: its cost is the product of the list lengths. Random search samples distributions (loguniform, randint) and usually beats a grid of the same size.
  • Successive halving screens many candidates on growing data; slow starters can be knocked out. Optuna (TPE) learns from past trials; seed it and run trials one at a time.
  • best_score_ is optimistic (the winner's curse). Report a nested cross-validation estimate or the test score, once. On churn: best 0.8795, nested 0.868, test 0.874.
  • Tuning moves a model toward its own ceiling; it does not change which family has the higher one. When gains flatten, look at features and framing.
Worked example: a business threshold, tuned honestly

Tuning a model is one decision; turning probabilities into actions is another, and it must be tuned honestly too. Take the tuned churn booster from Lesson 6.2's project and let TunedThresholdClassifierCV choose the offer threshold on the training customers for Lesson 1.4's economics ($15 per offer, $60 per churner reached).

import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.impute import SimpleImputer
from sklearn.metrics import make_scorer
from sklearn.model_selection import StratifiedKFold, TunedThresholdClassifierCV, train_test_split
from sklearn.pipeline import Pipeline, make_pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

customers = pd.read_csv("data/customers_churn.csv")
numeric = ["tenure_months", "orders_12m", "spend_12m", "avg_order_value", "days_since_last_order",
           "returns_12m", "return_rate", "support_tickets_12m", "discount_share", "app_user", "email_opens_90d"]
categorical = ["home_store", "region", "age_group", "loyalty_tier", "preferred_category"]
train, test = train_test_split(customers, test_size=0.25, stratify=customers["churned"], random_state=42)
X_train, y_train = train[numeric + categorical], train["churned"]
X_test, y_test = test[numeric + categorical], test["churned"]
prep = ColumnTransformer([
    ("num", make_pipeline(SimpleImputer(strategy="median"), StandardScaler()), numeric),
    ("cat", make_pipeline(SimpleImputer(strategy="most_frequent"), OneHotEncoder(handle_unknown="ignore")), categorical)])
best = {"l2_regularization": 0.0292, "learning_rate": 0.0472, "max_leaf_nodes": 50, "min_samples_leaf": 199}
tuned = Pipeline([("prep", prep), ("model", HistGradientBoostingClassifier(random_state=42, **best))])

def campaign_profit(y_true, flagged):               # Lesson 1.4: $60 per churner reached, $15 per offer
    y_true, flagged = np.asarray(y_true), np.asarray(flagged)
    return 60 * int(((flagged == 1) & (y_true == 1)).sum()) - 15 * int(flagged.sum())

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
plan = TunedThresholdClassifierCV(tuned, scoring=make_scorer(campaign_profit), cv=cv).fit(X_train, y_train)
offers = plan.predict(X_test)
print(f"threshold chosen on the training customers: {plan.best_threshold_:.3f}  (break-even 0.25)")
print(f"test: {offers.sum()} offers, {int(y_test[offers == 1].sum())} reach a churner, profit ${campaign_profit(y_test, offers):,}")
threshold chosen on the training customers: 0.240  (break-even 0.25)
test: 377 offers, 182 reach a churner, profit $5,265

Now the tempting shortcut: try thresholds on the test customers and keep the best.

p = plan.predict_proba(X_test)[:, 1]
peek = {t: campaign_profit(y_test, (p >= t).astype(int)) for t in np.round(np.arange(0.05, 0.6, 0.01), 2)}
t_peek = max(peek, key=peek.get)
print(f"threshold picked by peeking at the test set: {t_peek:.2f}, 'profit' ${peek[t_peek]:,}")
print(f"default 0.5: ${campaign_profit(y_test, (p >= 0.5).astype(int)):,}")
print(f"contact everyone: {campaign_profit(y_test, np.ones(len(p), int)):,} dollars")
threshold picked by peeking at the test set: 0.26, 'profit' $5,475
default 0.5: $3,690
contact everyone: -7,620 dollars

The chosen threshold (0.240) sits next to the break-even 0.25, a sign the probabilities are reasonably calibrated, and earns $5,265 on customers it never saw. Peeking finds $5,475, but that number was chosen by the data that grades it, so it is not a result: it is the winner's curse again. The default 0.5 earns far less, and offering to everyone loses money.

from sklearn.metrics import mean_absolute_error

demand = pd.read_csv("data/weekly_demand.csv")

            "discount_pct", "price", "promo", "holiday_week", "avg_high_temp_f"]

X = demand[features].copy()
X[cats] = X[cats].astype("category")
is_train = demand["year"] == 2024
X_train, X_test = X[is_train], X[~is_train]

         "min_samples_leaf": randint(10, 200), "l2_regularization": loguniform(1e-3, 10)}
search = RandomizedSearchCV(base, space, n_iter=8, cv=blocks, scoring="neg_mean_absolute_error",
                            random_state=42, n_jobs=-1).fit(X_train, y_train)
print(f"default CV MAE {default_cv:.2f}   best of 8 settings {-search.best_score_:.2f}")
print(f"2025 test MAE: default {mean_absolute_error(y_test, base.fit(X_train, y_train).predict(X_test)):.2f}"

2025 test MAE: default 8.05   tuned 8.20

The best of 8 settings is worse than the library default in cross-validation (8.73 against 8.49), and the test agrees (8.20 against 8.05).
