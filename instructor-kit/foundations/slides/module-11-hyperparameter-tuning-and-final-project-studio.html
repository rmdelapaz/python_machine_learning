6.2 · Mental model

Dialing in a camp stove

  • Two knobs; you cannot calculate the best setting: you try it
  • A trial = one full cross-validation run; fuel = computing time
  • Grid, random, halving, Optuna: four ways to spend the fuel
  • Space · budget · objective, written down before anything runs
WATCH The best-looking setting looks better than it is.
6.2 · Parameters vs hyperparameters

Learned by fit, or chosen by you

Learnedcoef_, the split points inside each tree: fit finds them
ChosenC, max_depth, learning_rate, max_leaf_nodes: search finds them
Namesstep name, two underscores, parameter: model__learning_rate
WHY The default to beat: 5-fold AUC 0.8615 +/- 0.0132.

6.2 · Random search

Fresh values of every knob, every trial

best CV AUC: 0.8764
{'model__l2_regularization': 0.0292,
 'model__learning_rate': 0.0472,
 'model__max_leaf_nodes': 50,

  • loguniform(0.01, 0.3) for rates; randint(4, 64) for sizes
  • Nine trials: 9 values of the important knob, not 3
WHY Usually beats a grid of the same size.

6.2 · Optuna

A search that learns where to look

{'learning_rate': 0.0609, 'max_leaf_nodes': 5,

6.2 · Honest scores

Three numbers, one to promise

# best_score_ chooses; nested CV reports
best_score_ (grid)   0.8795
best_score_ (Optuna) 0.8793
nested estimate      0.8681
default, 5-fold CV   0.8615
RULE The nested estimate (0.868) is the honest one. Then the test set, once: 0.874 vs 0.860.
6.2 · Common mistakes

Read the last line

  • {"C": [...]} on a pipeline: model__C
  • {"model__C": 1.0}: wrap it in a list
  • Two metrics: name the decider, refit="average_precision"
  • A linear grid [1, 2, 3, 4, 5] for a log-scale knob: explores nothing
  • Reporting best_score_ as the model's performance
